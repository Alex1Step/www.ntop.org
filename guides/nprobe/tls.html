Использование TLS при сборе/экспорте потока

По умолчанию nProbe использует UDP для сбора и экспорта потоков. Однако он также поддерживает

  • UDP

  • TCP

  • TLS

  • SCTP (на некоторых платформах, только для экспорта потока)

Вы можете выбрать протокол с помощью -n (экспорт потока) и -3 (сбор потока), используя формат <метод>://<адрес>. Пример:

  • udp://127.0.0.1:1234

  • tls://127.0.0.1:1234

При использовании TLS обязательно иметь действительный сертификат TLS, который подтверждается во время установления связи. В следующих разделах объясняется, как создать сертификат TLS и какие параметры командной строки доступны для TLS.

TLS Проверка сертификатов

Когда nProbe используется для сбора потоков через TLS, для nProbe требуется действительный файл сертификата. Хотя вы можете создавать сертификаты с помощью коммерческих центров сертификации (центров сертификации), иногда для тестирования необходимо использовать самозаверяющий сертификат TLS. Его можно сгенерировать следующим образом: openssl req -x509 -nodes -newkey rsa:4096 -keyout key.pem -out cert.pem -sha256 -days 365

Приведенная выше команда сгенерирует два файла: key.pem, который является личным файлом, и cert.pem, который является файлом сертификата. Такие файлы необходимо хранить в защищенном месте, и их можно передать в nProbe следующим образом:

  • --tls-priv-key <key.pem path>

  • --tls-cert <cert.pem path>

Например, следующая команда собирает потоки на локальном хосте: 2055: nprobe --tls-priv-key tls/key.pem --tls-cert tls/cert.pem -n none -i none -b 2 -3 tls://localhost:2055

nProbe может экспортировать потоки в указанную выше команду следующим образом: nprobe -i en3 -b2 -t 3 -d 3 -s 3 -n tls://localhost:2055

Если сборщик nProbe был запущен с самоподписанным или недействительным (например, с истекшим сроком действия) сертификатом, --tls-insecure Опцию можно использовать для пропуска проверки сертификата TLS. Не забудьте установить –tls-insecure перед -n.
