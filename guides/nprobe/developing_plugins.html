Разработка плагинов nProbe

Примечание

Плагин SDK доступен по запросу избранным пользователям.

Каждый плагин nProbe реализован как общая библиотека, которая загружается во время выполнения nProbe. Зонд поставляется с несколькими плагинами, которые можно использовать в качестве примера для этого действия. Ниже мы перечисляем основные понятия, которые вам необходимо знать, если вы планируете разрабатывать плагины nProbe.

Каждый плагин должен определить точку входа плагина следующим образом:

static PluginEntryPoint dbPlugin = {
  NPROBE_REVISION,
  "My Plugin Name",
  "shortName", NULL,
  "version",
  "Plugin string description",
  "author email",
  1 /* do NOT skip in collector mode */,
  0 /* always enabled */, 1, /* enabled */
  PLUGIN_PRO_VERSION,
  myPlugin_init,
  NULL, /* Term */
  myPlugin_conf,
  myPlugin_delete,
  1, /* call packetFlowFctn for each packet */
  NULL /* myPlugin_packet */,
  myPlugin_get_template,
  myPlugin_export,
  myPlugin_print,
  NULL,
  NULL,
  myPlugin_help,
  NULL, 0, 0
};

и функция следующего формата

#ifdef MAKE_STATIC_PLUGINS
PluginEntryPoint* myPluginEntryFctn(void)
#else
PluginEntryPoint* PluginEntryFctn(void)
#endif
{
  return(&myPlugin);
}

Поля функции PluginEntryPoint имеют следующее значение:

  • char *nprobe_revision; строка, которая будет определена как NPROBE_REVISION.

  • char *name; Расширенное имя плагина.

  • char *short_name; Короткое название плагина.

  • char *family; Имя семейства плагина (если есть) или NULL, чтобы использовать короткое имя плагина.

  • char *version; Версия плагина (например, 1.0).

  • char *descr; Описание плагина на простом английском языке.

  • char *author; Имя автора плагина и адрес электронной почты.

  • u_int8_t skip_in_collector_mode; Установите значение 0, чтобы пропустить плагин, когда nprobe находится в режиме коллектора, в противном случае установите значение 1.

  • u_int8_t always_enabled; Установите значение 1, чтобы включить плагин постоянно, независимо от его использования в шаблоне.

  • u_int8_t enabled; Не трогайте его и установите значение 0 (используется nProbe).

  • u_int8_t need_license; Установите значение 1, если лицензия для этого плагина необходима, или 0, если она не нужна.

  • PluginInitFctn initFctn; Функция инициализации плагина, вызываемая при загрузке плагина в память. Эта функция вызывается независимо от того, будет ли в дальнейшем использоваться плагин или нет.

  • PluginTermFctn termFctn; Функция завершения плагина вызывается, когда плагин завершается во время выключения nProbe.

  • PluginConf pluginFlowConf; Функция, возвращающая конфигурацию потока (см. ниже).

  • PluginFctn deleteFlowFctn; Обратный вызов потока, который вызывается для потоков, обрабатываемых этим плагином, при каждом экспорте потока. Эта функция используется для освобождения памяти ресурсов, связанных с потоком. Установите значение NULL, если функция не будет определена,

  • u_int8_t call_packetFlowFctn_for_each_packet; Установите значение 1, чтобы запросить nProbe вызвать обратный вызов packageFlowFctn для каждого пакета, принадлежащего этому потоку, или 0, чтобы вызвать его только для первого пакета потока.

  • PluginPacketFctn packetFlowFctn; Обратный вызов вызывается всякий раз, когда nProbe имеет пакет, принадлежащий потоку, который должен быть обработан плагином.

  • PluginGetTemplateFctn getTemplateFctn; Функция, используемая для возврата элемента шаблона для указанного информационного элемента, переданного в качестве параметра.

  • PluginExportFctn pluginExportFctn; Обратный вызов вызывается всякий раз, когда поток, обрабатываемый этим плагином, будет экспортирован.

  • PluginPrintFctn pluginPrintFctn; Функция, которая вызывается, когда используется nprobe -P, и которая должна печатать информацию о потоке в текстовые файлы.

  • PluginStatsFctn pluginStatsFctn; Функция, которая вызывается (если не установлено значение NULL) всякий раз, когда nProbe печатает периодическую информацию (-b 1 или -b 2).

  • PluginSetupFctn setupFctn; Функция, вызываемая после инициализации плагина (если не установлено значение NULL), если согласно указанному шаблону, будет использоваться этот плагин.

  • PluginHelpFctn helpFctn; Функция, которая вызывается при выполнении nprobe -h и должна печатать информацию о плагине.

  • PluginIdleTaskFctn idleFctn; Если не установлено значение NULL, эта функция будет периодически вызываться ядром nProbe для выполнения (если таковые имеются) служебных действий.

  • u_int8_t v4TemplateIdx, v6TemplateIdx; Используется nProbe. Установите их на 0.

Каждый плагин должен определить шаблон следующего формата

static V9V10TemplateElementId myPlugin_template[] = {
  { 0, BOTH_IPV4_IPV6, FLOW_TEMPLATE, LONG_SNAPLEN, NTOP_ENTERPRISE_ID, 0, STATIC_FIELD_LEN, 0, 0, 0, NULL, NULL, NULL }
};

что будет затем использоваться следующими функциями

static V9V10TemplateElementId* myPlugin_get_template(char* template_name) {
  int i;

  for(i=0; myPlugin_template[i].templateElementId != 0; i++) {
    if(!strcmp(template_name, myPlugin_template[i].netflowElementName)) {
      return(&myPlugin_template[i]);
    }
  }

  return(NULL); /* Unknown */
}

static V9V10TemplateElementId* myPlugin_conf(void) {
  return(myPlugin_template);
}

В файле template.h указаны идентификаторы потока, которые будут использоваться в V9V10TemplateElementId, который определяется следующим образом:

  • u_int8_t isInUse; Всегда устанавливайте для него значение 1 или 0, если это последний элемент шаблона, указывающий, что дальнейший элемент не будет определен.

  • u_int8_t protoMode; Установите для него значение BOTH_IPV4_IPV6 или ONLY_IPV4, ONLY_IPV6, если этот элемент предназначен как для потоков IPv4, так и для потоков IPv46, только для потоков IPv4 или только для потоков IPv6.

  • const u_int8_t isOptionTemplate; Установите для него значение 0, если это шаблон потока (по умолчанию), или 1, если он используется в качестве шаблона опции.

  • const u_int8_t useLongSnaplen; Установите значение 1, если этому плагину требуется nProbe для захвата пакетов с длинным snaplen, которые необходимы, когда плагину необходимо выполнить анализ полезной нагрузки.

  • const u_int32_t templateElementEnterpriseId; Укажите идентификатор предприятия, определенный IANA, для этого настраиваемого поля. ntop использует NTOP_ENTERPRISE_ID для проприетарных.

  • const u_int16_t templateElementId; Используется nProbe, оставьте значение 0.

  • u_int8_t variableFieldLength; Установите значение 1, чтобы указать, что если nProbe экспортирует потоки в формате IPFIX (-V 10), это поле будет иметь переменный размер.

  • u_int16_t templateElementLen; Укажите статический размер поля (-V 9) или максимальный размер поля (-V 10).

  • const ElementFormat elementFormat; Укажите формат элемента. Эта информация будет использоваться при печати данных в MySQL. Поддерживаемые типы формата: ascii_format, hex_format, numeric_format, ipv6_address_format.

  • const ElementDumpFormat fileDumpFormat; Укажите формат поля при печати информации метаданных nProbe (–метаданные). Поддерживаемые формы типов: dump_as_uint, dump_as_formatted_uint, dump_as_ip_port, dump_as_ip_proto, dump_as_ipv4_address, dump_as_ipv6_address, dump_as_mac_address, dump_as_epoch, dump_as_bool, dump_as_tcp_flags, dump_as_hex, dump_as_ascii

  • const char *netflowElementName; Строка с символическим именем сетевого элемента, используемым в NetFlow (-V 9).

  • const char *ipfixElementName; Строка с символическим именем сетевого элемента, используемым в IPFIX (-V 10).

  • const char *templateElementDescr; Строка, описывающая тип информации об элементе, используемый nProbe при выводе справки (-h).

Большинство обратных вызовов плагинов просты, и их логику можно понять, просто взглянув на примеры существующих плагинов. Единственная функция, которую стоит описать, — это та, которая обрабатывает пакеты, поскольку она самая сложная.

static void myPlugin_packet(u_char new_bucket,
                    int packet_if_idx /* -1 = unknown */,
                    void *pluginData,
                    FlowHashBucket* bkt,
                    FlowDirection flow_direction,
                    u_int16_t ip_offset, u_short proto,
                    u_char isFragment,
                    u_short numPkts, u_char tos,
                    u_short vlanId, struct eth_header *ehdr,
                    IpAddress *src, u_short sport,
                    IpAddress *dst, u_short dport,
                    u_int len, u_int8_t flags,
                    u_int32_t tcpSeqNum,  u_int8_t icmpType,
                    u_short numMplsLabels,
                    u_char mplsLabels[MAX_NUM_MPLS_LABELS [MPLS_LABEL_LEN],
                    const struct pcap_pkthdr *h, const u_char *p,
                    u_char *payload, int payloadLen) {
   ...
}

Эта функция обрабатывает пакет, принадлежащий потоку, обрабатываемому этим плагином. nProbe не имеет ни малейшего представления о том, что делают плагины, поэтому всякий раз, когда создается новый поток (new_bucket имеет значение 1 для первого пакета потока или 0 для следующих пакетов), он вызывает все активные плагины, чтобы сообщить, что новый поток активен в кеше. Затем плагин решит, может ли пакет быть обработан плагином или нет. Это делается путем просмотра полей заголовка пакета, переданных функции, или проверки полезной нагрузки пакета (точки полезной нагрузки, длина которой задается параметром payloadLen). Если плагин решает, что пакет не может быть обработан плагином (например, потому что протокол пакета не управляется плагином), никаких действий не требуется, и функция должна просто вернуться. Вместо этого, если плагин может обрабатывать пакет, в начале функции необходимо указать следующий код, чтобы добавить плагин в список плагинов (обычно он должен иметь длину 1 или 0 элементов), обрабатывающих этот поток.

if(new_bucket /* This bucket has been created recently */) {

      info->pluginPtr  = (void*)&myPlugin;
pluginData = info->pluginData = (struct my_plugin_info*)malloc(sizeof(struct my_plugin_info));

      if(info->pluginData == NULL) {
        traceEvent(TRACE_ERROR, "Not enough memory?");
        free(info);
        return; /* Not enough memory */
      } else {
        struct my_plugin_info *myinfo = (struct my_plugin_info*)pluginData;

        /* Reset fields */
        memset(myinfo, 0, sizeof(struct my_plugin_info));

        info->next = bkt->ext->plugin;
        info->plugin_used = 0;
        bkt->ext->plugin = info;
      }
    }
  }

После определения плагина его необходимо поместить в каталог nProbe/plugins, чтобы процесс сборки nProbe обнаружил и скомпилировал его.

 *
 *  This is a dummy plugin example
 *

#include "nprobe.h"

static V9V10TemplateElementId dummyPlugin_template[] = {
                                                      { 0, BOTH_IPV4_IPV6, FLOW_TEMPLATE, LONG_SNAPLEN, NTOP_ENTERPRISE_ID, 0, STATIC_FIELD_LEN, 0, 0, 0, NULL, NULL, NULL }
};

struct dummy_plugin_info {
  u_int8_t dummy_value;
};

static PluginEntryPoint dummyPlugin; /* Forward */


/* ******************************************* */

static void dummyPlugin_init() {
  traceEvent(TRACE_NORMAL, "Initialized dummy plugin");
}

/* *********************************************** */

/* Handler called whenever an incoming packet is received */

static void dummyPlugin_packet(FlowCallback callback,
                             int packet_if_idx /* -1 = unknown */,
                             void *pluginData,
                             FlowHashBucket* bkt,
                             FlowDirection flow_direction,

/* *********************************************** */

  if(pluginData)
    free(pluginData);

/* *********************************************** */

/* Handler called at startup when the template is read */

static V9V10TemplateElementId* dummyPlugin_get_template(char* template_name) {

  int len;

  traceEvent(TRACE_INFO, "%s()", __FUNCTION__);

  if(!pluginData) return(-1);

  switch(theTemplate->templateElementId) {
  default:
    return(-1); /* Not handled */
  }

  return(len);

  traceEvent(TRACE_INFO, "%s()", __FUNCTION__);

  traceEvent(TRACE_INFO, "%s()", __FUNCTION__);

                                     "Dummy Protocol",
                                     "dummy", NULL, NULL,
