Сбор собственных полей потока

nProbe умеет не только собирать стандартные поля потока, т.е. определенный в NetFlow/IPFIX RFC, он также может собирать пользовательские и собственные поля потока. Собственные поля часто используются поставщикам экспортировать данные, используя стандарт NetFlow v9 или IPFIX для транспорт. Cisco Видимость и контроль приложений (AVC), Cisco Medianet, IXIA IxFlow и SonicWall AppFlow — это лишь несколько примеров.

Собственные поля могут быть объявлены с использованием простого текстового файла, который должен быть введены в nProbe, и они будут обработаны nProbe, как если бы они были обычные, стандартные поля. Это означает, что эти поля можно экспортировать. просто указав их в шаблоне -T.

Простой текстовый файл содержит одну или несколько строк следующего формата:

Name          STANDARD_ALIAS  PEN     FieldId         Len     Format

  • Name это просто мнемоническое имя, присвоенное проприетарному поле, которое используется для идентификации поля в пределах nProbe, например при указании поля в шаблоне.

  • STANDARD_ALIAS является отображением на стандартное поле. NONE может быть указан, когда нет сопоставления со стандартным полем доступен. Обычно полезно указать это сопоставление для преобразования собственные поля в стандартные, хорошо известные.

  • PEN это номер частного предприятия собственной поле. Если в поле нет PEN, можно безопасно указать 0.

  • FieldId — целое число, которое вместе с PEN, однозначно идентифицирует собственное поле.

  • Len — длина поля, выраженная в байтах.

  • Format указывает, как интерпретировать байты поля:

    • dump_as_uint интерпретирует поле как целое число без знака

    • dump_as_ipv4_address интерпретирует поле как IPv4 адрес

    • dump_as_mac_address интерпретирует поле как Mac-адрес

    • dump_as_hex интерпретирует поле как шестнадцатеричное значение

    • dump_as_ascii в виде текстовой строки в формате ASCII.

Доступные определения пользовательских полей потока

nProbe поставляется с предварительно настроенными определениями потоков поставщиков, поэтому пользователи могут немедленно собирать популярные поля потоков без необходимости создания пользовательская конфигурация потока. Список доступных конфигураций: доступно на https://github.com/ntop/nProbe/tree/master/custom_fields

Пример

Фрагмент текстового файла с объявлением настраиваемых полей для нескольких поставщиков доступен ниже:

#
# Name                STANDARD_ALIAS  PEN     FieldId         Len     Format
#
# Notes
# - STANDARD_EQUIVALENT
#   If this field is equivalenet/alias of a standard field, put its name here
#   or put NONE if there is no standard equivalent element
#
# Notes
# - Use 0 for no PEN
#
#
# Available formats
# - dump_as_uint
# - dump_as_ipv4_address
# - dump_as_mac_address
# - dump_as_hex
# - dump_as_ascii
#

# Gigamon
HttpReqUrl                    NONE    26866   1       64      dump_as_ascii
DnsQueryName                  NONE    26866   204     64      dump_as_ascii
DnsResponseIpv4Address        NONE    26866   207     4       dump_as_ipv4_address

Предположим, частные поля HttpReqUrl и DnsQueryName придется экспортировать. можно поставить объявления в текстовом файле custom-fields.txt и начните nProbe как

./nprobe --load-custom-fields "custom-fields.txt" -T  "@NTOPNG@ %HttpReqUrl %DnsQueryName" ...

Примечание

Это только nProbe профессиональная функция.
