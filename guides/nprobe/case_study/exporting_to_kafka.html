Экспорт в Apache Kafka

nProbe, если настроен плагин экспорта, может отправлять потоки одному или нескольким брокерам Kafka в кластере. Первоначально nProbe пытается связаться с одним или несколькими указанными пользователем брокерами для получения метаданных кластера Kafka. Метаданные включают список брокеров, доступных в кластере, которые отвечают за заданную пользователем тему. Как только у nProbe появится список доступных брокеров, он начнет отправлять им потоки. Пользователь также может принять решение о сжатии данных и указать, если он/она:

  • Не хочет ждать ACK

  • Хочет получать ACK только от лидера Kafka

  • Хочет получать ACK от каждой реплики

Пример

Предполагая, что на локальном порту 2181 имеется Zookeeper, который управляет кластером Kafka, можно запросить создание новой темы Kafka. Допустим, тема называется «topicFlows», и мы хотим, чтобы она была разделена на три раздела с коэффициентом репликации два. Команда, которая должна быть выдана, следующая

./bin/kafka-topics.sh --zookeeper localhost:2181 --create --topic topicFlows --partitions 3 --replication-factor 2

Теперь, когда тема Kafka создана, можно выполнить nProbe и указать экземпляру экспортировать в тему Kafka «topicFlows». Мы также сообщаем экземпляру список из трех брокеров, работающих на локальном хосте (на портах 9092, 9093 и 9094 соответственно), которые будут запрошены вначале для получения метаданных kafka кластера/темы.

nprobe --kafka "127.0.0.1:9092,127.0.0.1:9093,127.0.0.1:9094;topicFlows"

На данный момент экземпляр nProbe активно экспортирует потоки в кластер Kafka. Чтобы убедиться, что все работает правильно, мы можем удалить сообщения из темы Kafka с помощью следующей команды

./bin/kafka-console-consumer.sh --zookeeper localhost:2181 --topic topicFlows --from-beginning

Дополнительную информацию и тонкую настройку экспорта Kafka можно найти по адресу следующие сообщения в блоге:

  • https://www.ntop.org/tutorials/stream-that-flow-how-to-inject-nprobe-cento-flows-in-a-kafka-cluster/

  • https://www.ntop.org/nprobe/improved-nprobe-kafka-export-support-theory-and-practice/

Свойства пользовательской конфигурации

nProbe позволяет устанавливать пользовательские свойства конфигурации. Будучи в состоянии установка свойств конфигурации является ключевым моментом, поскольку позволяет решить, highthroughput — это название игры, или если используется служба с низкой задержкой требуется.

Среди всех доступных свойств конфигурации для ради настройки производительности стоит упомянуть:

  • batch.num.messages: минимальное количество сообщений – потоков, на языке nProbe — ждать, пока накопится в очереди перед отправкой набора сообщений.

  • queue.buffering.max.ms: сколько ждать batch.num.messages чтобы пополнить очередь. Более низкое значение улучшает задержка за счет более низкой пропускной способности и более высокого количества сообщений накладные расходы. Более высокое значение повышает пропускную способность за счет задержки.

Свойства конфигурации задаются с помощью опции nProbe. --kafka-conf, за которым следует имя свойства и свойство значение, разделенное равным = знак. Вариант может быть повторяется несколько раз, когда необходимо установить несколько свойств.

Например, чтобы установить queue.buffering.max.ms до 1000 мс, интервал автофиксации topic.auto.commit.interval.ms до 2000 мс, и отладку сообщений можно запустить nProbe, добавив следующее:

--kafka-conf debug=msg --kafka-conf queue.buffering.max.ms=1000 --kafka-conf=topic.auto.commit.interval.ms=2000

Полный список свойств конфигурации, которые можно настроить, приведен ниже. доступно на https://github.com/edenhill/librdkafka/blob/master/CONFIGURATION.md

TLS/SSL Шифрование

Чтобы добавить шифрование TLS/SSL к Kafka, как брокеры, так и nProbe клиент должен быть соответствующим образом настроен, как описано в https://github.com/edenhill/librdkafka/wiki/Using-SSL-with-librdkafka.

В частности, свойства конфигурации, такие как ssl.ca.location и ssl.key.location можно установить с помощью опции nProbe --kafka-conf как описано в разделе выше.

Быстрый старт

Для нетерпеливых, пожалуйста, следуйте инструкциям ниже, чтобы построить базовый Kafka установку и запустите ее.

Скачать Kafka:

wget https://downloads.apache.org/kafka/2.8.0/kafka_2.13-2.8.0.tgz
tar -xzf kafka_2.13-2.8.0.tgz

Запустите Kafka Zookeeper:

cd kafka_2.13-2.8.0
bin/zookeeper-server-start.sh config/zookeeper.properties

В другом терминале запустите сервер Kafka:

cd kafka_2.13-2.8.0
bin/kafka-server-start.sh config/server.properties

Создайте тему:

cd kafka_2.13-2.8.0
bin/kafka-topics.sh --zookeeper localhost:2181 --create --topic topicFlows --partitions 3 --replication-factor 1

Запустите nProbe:

sudo nprobe -i eno1 --kafka "127.0.0.1:9092;topicFlows"
