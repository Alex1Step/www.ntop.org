Понимание того, как работает сбор потоков

nProbe поддерживает коллекцию NetFlow v5 и v9, jFlow, IPFIX и sFlow. В частности, он извлекает потоки, переносимые в NetFlow v5 и v9, jFlow и IPFIX, тогда как он создает потоки, начиная с выбранных пакетов осуществляется в пределах sFlow.

После того как потоки извлечены или созданы, их можно обработать и экспортируются, как подробно описано в настоящем руководстве, независимо от источник, из которого они исходят. Другими словами, после сбора поток для nProbe — это просто элемент с определенными полями (например, ip клиента, сервер ip, байты от клиента к серверу, байты от сервера к клиенту и т. д.), и это больше не будет иметь значения, было ли оно извлечено из NetFlow или создано из sFlow.

После сбора потоки временно помещаются на nProbe в внутренний кэш потока. Попав в кеш, потоки могут иметь свой трафик счетчики обновляются, например, когда несколько пакетов NetFlow переносят обновления для одного и того же потока или когда несколько sFlow выборочных пакетов на самом деле образцы одного и того же потока.

Потоки остаются в кеше определенное время, т.е. настраивается с помощью параметров тайм-аута -t и -d. По истечении этого времени потоки экспортируются вниз по течению. согласно указанной конфигурации (например, в текстовые файлы, Kafka, ElasticSearch и т. д.) и ограничивается полями, указанными в шаблон с опцией -T.

Размещение потоков в кеше и обновление их счетчиков трафика перед экспорт может иметь положительный эффект для сокращения объема экспортированные потоки, поскольку вместо многократного экспорта потока экспортируется один поток, несущий (всего) обновленные счетчики трафика всего один раз. Однако это происходит за счет использования дополнительной памяти. и дополнительное время на обработку кеша и поиск в нем. Следовательно, когда в этом нет необходимости или когда нежелательно собирать потоки помещаются в кеш, время и память могут быть сохранены путем полный обход внутреннего кэша потоков с помощью опции --collector-passthrough.

Вариант --collector-passthrough экспортирует потоки в настроенные ZMQ конечные точки как есть, сразу после их сбора, без размещения их в кэш. Потоки экспортируются «как есть» со всеми полями в виде находится в папке NetFlow/jFlow/IPFIX. Эта опция работает только с NetFlow/jFlow/IPFIX. (т. е. sFlow не поддерживается), приводит к тому, что шаблон -T быть игнорируется и экспортируется только в ZMQ. С использованием --collector-passthrough обеспечивает максимальную производительность сбора.

Вместо использования --collector-passthrough, можно решить просто используй --disable-cache. Просто отключить кеш, а не используя --collector-passthrough дает меньшую пропускную способность, но не имеет ограничений, описанных выше. Следовательно, -T опция шаблона будет учитываться, и потоки будут экспортированы в любое из настроенных нисходящих пунктов назначения (не только ZMQ).

Фильтрация и переформовка собранных NetFlow потоков

Иногда при сборе потоков NetFlow возникают две потребности:

  • Отменить определенные потоки, поступающие от выбранных интерфейсов/маршрутизаторов.

  • Reforge NetFlow проверяет IP-адрес, поскольку он мог быть изменен (например, через NAT)

nProbe позволяет сделать это с помощью --collector-nf-reforge <path> опция командной строки. Формат файла reforge показан в примере ниже (обратите внимание, что поля разделены табуляцией):

#
# NOTE
# - ReforgedIP set to * means no IP reforge
# - ListOfAllowedInterfaces set to * means all inIfIfx
# - valid ListOfAllowedInterfaces entries must be in the 0-63 range
#
# ExporterIP    ReforgedIP      ListOfAllowedInterfaces
127.0.0.1       10.0.24.25      12
192.168.1.1     192.168.1.1     1,2,3,4
192.168.1.21    *               1,12,43,98

Для тех роутеров, к которым вы хотите применить некоторую фильтрацию/перековку, вам необходимо указать строку в файле (на сегодняшний день поддерживается только IPv4), где вы указываете переделанный IP-адрес (или * для использования исходный IP-адрес и его не переформирование) и список разрешенных ingressInterfaceId, которые принимаются для этого экспортировал. В первой строке разрешен только интерфейс 12, то есть все остальные собранные потоки созданные другими идентификаторами интерфейса, будут отброшены и не рассмотрены nProbe. Для экспортеров, не указанных в списке в файле не производится перефорсировка IP и фильтрация по интерфейсу (т.е. все пройдет).
