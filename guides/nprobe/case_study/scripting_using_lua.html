Написание сценариев nProbe с использованием Lua

nProbe Professional позволяет пользователю создавать сценарии настраиваемых действий и поведения непосредственно перед экспортом потока. Скриптовые действия и поведение выполняются для каждого протокола и требуют соответствующего плагина. Например, для создания сценариев действий и поведения для потоков HTTP требуется установленный и доступный плагин HTTP. Аналогично, для создания сценариев действий и поведения для потоков DNS требуется, чтобы плагин DNS был включен и доступен.

Скрипты должны быть написаны на языке Lua (https://www.lua.org/about.html). Lua — это легкий язык сценариев, который динамически типизируется, запускается путем интерпретации байт-кода с помощью виртуальной машины на основе регистров и имеет автоматическое управление памятью с инкрементальной сборкой мусора, что делает его идеальным для настройки, написания сценариев и быстрого прототипирования.

Скрипты Lua указываются с помощью опции nProbe –lua. Например, чтобы указать nProbe выполнить скрипт dnsSearch.lua, расположенный в папке lua/, можно выполнить следующую команду:

./nprobe -i eth1 --lua lua/dnsSearch.lua

Но как nProbe узнает, какую функцию вызывать? Ответ довольно прост: он ищет функции Lua с определенными шаблонами имен внутри скрипта Lua, полученного в качестве входных данных.

Соглашение об именах функций Lua

nProbe ищет функции Lua, структурированные как

check<Protocol>Flow

Каждый плагин nProbe проверит входной файл Lua и попытается найти соответствующую ему функцию. Плагины должны быть правильно включены и настроены, чтобы правильно вызывать функции Lua. Плагины, поддерживающие сценарии Lua, описаны в следующей таблице.

Каждый плагин для каждого потока — перед вызовом, если таковая имеется, соответствующей функции Lua — помещает в стек Lua глобальную таблицу, которая содержит:

  • Элементы потока, общие для любого потока

  • Дополнительные элементы, характерные для потоков, захватываемых плагином.

Элементы помещаются в глобальную таблицу Lua как пары Ключ — Значение.

Примеры

В оставшейся части этого раздела показаны примеры сценариев nProbe Lua.

Перехват потоков DNS

Допустим, специальное действие должно быть выполнено непосредственно перед экспортом любого потока DNS. Давайте также предположим, в интересах педагогической ясности, что пользовательское действие состоит в печати на консоли таблицы Lua глобального потока dns, которая была вставлена ​​nProbe. Для выполнения описанного выше действия достаточно создать скрипт Lua следующего содержания:

function checkDNSFlow()
   for k, v in pairs(dns) do
      print('k: '..k..' v: '..v..'\n')
   end
end

Приведенный выше сценарий перебирает глобальную таблицу dns и выводит на консоль все пары ключ-значение, по одной в строке. Выполнение происходит один раз для каждого обнаруженного потока DNS, непосредственно перед экспортом потока. Предполагая, что сценарий сохранен в файле dnsSearch.lua в каталоге lua/, тогда nProbe можно запустить следующим образом:

./nprobe -i en4 --lua lua/dnsSearch.lua  --dns-dump-dir /tmp

Журналы консоли подтвердят, что плагин DNS включен и что интерпретатор Lua правильно проанализировал dnsSearch.lua:

[...]
[LUA] Successfully interpreted lua/dnsSearch.lua
DNS log files will be saved in /tmp
1 plugin(s) enabled
[...]

На этом этапе можно отправить запрос на сервер DNS.

$ dig google.it @8.8.8.8
