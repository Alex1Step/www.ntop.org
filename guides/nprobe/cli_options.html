Параметры командной строки

nProbe поддерживает большое количество параметров командной строки. Чтобы узнать, что это такое, просто введите команду nprobe -h и справочная информация должна быть распечатана. Самое важное параметры кратко обсуждаются здесь.

-n: collector addresses

Здесь указаны адреса сборщиков NetFlow, на которые nProbe будут отправлять потоки. Если указано более одного, их необходимо разделить запятой или флаг –n можно повторить несколько раз (например, -n 172.22.3.4:33,172.22.3.4:34 и -n 172.22.3.4:33 –n 172.22.3.4:34 эквивалентны). Если определены несколько коллекторов, вы можете контролировать способ экспорта потоков, используя опцию –a (см. ниже); если в адресе коллектора порт назначения опущен, потоки отправляются на порт 2055, а если все параметры не указаны, по умолчанию потоки отправляются на интерфейс обратной связи (127.0.0.1) на порт 2055. Если этот параметр используется, nProbe экспортирует потоки в сторону коллектора, работающего по адресу 127.0.0.1:2055. По умолчанию используется протокол UDP, а также TCP и SCTP (Linux только в том случае, если nProbe скомпилирован с поддержкой SCTP и ядро ​​поддерживает его). В этом случае вы можете указать адрес сборщика как udp://<хост>:<порт>, tcp://<хост>:<порт> и sctp://<хост>:<порт>,

-i: interface name

Он определяет интерфейс, с которого перехватываются пакеты. Если -i не используется, nProbe будет использовать интерфейс по умолчанию (если есть). Если пользователю необходимо активировать nProbe на двух разных интерфейсах, ему/ей необходимо активировать несколько экземпляров nProbe один раз для каждого интерфейса. В целях отладки можно передать nProbe файл .pcap, из которого будут считываться пакеты. Если nProbe скомпилирован и активирован с поддержкой PF_RING, вы можете указать несколько интерфейсов, с которых перехватываются пакеты. Например, «-i eth0,eth1» объединит пакеты, полученные на eth0 и eth1, в один поток трафика. Эта конфигурация особенно полезна при объединении двух направлений (TX и RX) сети TAP.

-t: maximum flow lifetime

Независимо от продолжительности потока, поток, который был активен дольше указанного максимального срока службы, считается истекшим и будет отправлен. Дальнейшие пакеты, принадлежащие тому же потоку, будут учитываться в новом потоке.

-d: maximum flow idle lifetime

Поток завершается, когда последний полученный пакет старше максимального времени ожидания потока. Это означает, что когда это применимо (например, SNMP walk) UDP потоки будут учитываться не на основе 1 пакета/1 потока, а на основе одного глобального потока, который учитывает весь трафик. Это положительно сказывается на общем количестве генерируемых потоков и общей производительности коллектора.

-l: maximum queue timeout

Он определяет максимальное время, в течение которого поток может находиться в очереди в ожидании экспорта. Используйте эту опцию, чтобы попытаться упаковать несколько потоков в меньшее количество пакетов, но при этом иметь верхнюю границу таймаута для постановки потоков в очередь в зонд.

-s:  snaplen

Этот флаг указывает часть пакета (также называемую snaplen), которая будет перехвачена nProbe. По умолчанию nprobe автоматически устанавливает snaplen в соответствии с его конфигурацией, но вы можете переопределить его значение, используя этот флаг.

-p: <VLAN Id>/<proto>/<IP>/<port>/<TOS>/<SCTP StreamId>/<exporter IP>

Потоки могут агрегироваться как на стороне коллектора, так и на стороне зонда. Однако распределение зондов гораздо более эффективно, поскольку оно значительно уменьшает количество испускаемых потоков, а значит, и работу, которую должен выполнять коллектор. nProbe поддерживает различные уровни агрегации, которые можно выбрать, указав флаг -p. Формат агрегирования: <VLAN Id>/<proto>/<IP>/<порт>/<TOS>/<SCTP StreamId>/<IP-адрес экспортера>, где для каждого параметра можно установить значение 0 (игнорировать) или 1 (будьте осторожны). Игнорируемым полям присваивается нулевое значение как при агрегировании, так и при экспорте. Например, установка для <IP-адреса экспортера> значения 0 (игнорировать) будет учитывать все входящие потоки, как если бы они исходили от того же нулевого экспортера, который будет выводиться в %EXPORTER_IPV4_ADDRESS как 0.0.0.0. По умолчанию агрегирование не выполняется. Например, значение 0/0/1/0/0/0/0 можно использовать для создания карты того, кто с кем разговаривает (матрица сетевых разговоров).

-f: packet capture filter

Этот фильтр BPF (дополнительную информацию о фильтрах BPF см. в приложении) позволяет nProbe учитывать только те пакеты, которые соответствуют фильтру (если он указан).

-a: select flow export policy

Если определены несколько коллекторов (см. параметр –n), nProbe отправляет им потоки в циклическом порядке. Однако можно отправить один и тот же поток всем сборщикам, как это делает перенаправитель потока, если используется опция –a.

-b: enable verbose logging

Используя этот флаг, nProbe генерирует подробный вывод, который можно использовать для настройки его производительности (см. главу 2.4). Zero — самый низкий уровень (выводится мало информации), 1 отображает статистику трафика, 2 действительно многословен. Пример статистики трафика:

30/Oct/2020 16:10:00 Current traffic: [1.9 pkt/sec][1 Kb/sec]
30/Oct/2020 16:10:00 Current flow export rate: [0.9 flows/sec]
30/Oct/2020 16:10:00 [Buckets: [active=13][allocated=21][free=8][toBeExported=0][frags=0]
30/Oct/2020 16:10:00 Fragment queue: [len=0]
30/Oct/2020 16:10:00 Num Packets: 111 (max bucket search: 0)
30/Oct/2020 16:10:00 115 pkts rcvd/0 pkts dropped

-G: start nprobe as a daemon.

Полезно при запуске nprobe в качестве демона.

--ndpi-protocols|-O: export only flows whose L7 protocol is in the specified list.

Эту опцию можно использовать для фильтрации экспортируемых потоков на основе протокола приложения. Пример: -O «DNS,HTTP,BitTorrent».

--ndpi-custom-protos <path|URL>

Пользовательские протоколы nDPI. Вы можете указать как путь (например, nDPI/example/protos.txt), так и URL-адрес (http://localhost/protos.txt).

-P: dump flows

Этот путь указывает каталог, в который будут сбрасываться потоки. Формат дампа — текстовый, и он зависит от шаблона nProbe, указанного с помощью -T.

-F

Он определяет частоту, с которой файлы сбрасываются на диск.

-D: dump flows format

Потоки, хранящиеся на дисках, могут храниться в нескольких форматах: текстовом (по умолчанию), двоичном (по мере экспорта), JSON или текстовых потоках, сжатых gzip. Обратите внимание, что этот флаг не имеет никакого эффекта, если не используется -P.

-u: input device index

Спецификация NetFlow содержит числовой индекс для идентификации потоков, поступающих от разных интерфейсов одного и того же зонда. Поскольку на одном хосте, но на разных устройствах может быть запущено несколько экземпляров nProbe, сборщик может использовать этот флаг для разделения потоков по номеру интерфейса. Если –u не используется, то nprobe будет использовать 0 в качестве индекса интерфейса. Альтернативно, если используется -1, то в качестве индекса используются последние два байта MAC-адреса отправителя потока.

-Q: output device index

Аналогично –u, но для выходного интерфейса.

--vlanid-as-iface-idx <mode: inner outer single double>

nProbe может использовать тег VLAN в качестве идентификатора интерфейса. Используя этот флаг, вы включаете эту функцию. Поскольку теги VLAN могут группироваться, вам необходимо указать, будет ли внутренний или внешний тег использоваться для идентификатора интерфейса.

--discard-unknown-flows <mode:0 1 2>

nProbe включает nDPI поддержку анализа содержимого пакетов с целью определения протокола приложения. Значение режима можно использовать для:

  • 0: Экспортировать все известные (т. е. те, чей протокол приложения был обнаружен) и неизвестные (т. е. протокол приложения неизвестен)

  • 1: Экспортировать только известные потоки, игнорируя неизвестные потоки.

  • 2: Экспортировать только неизвестные потоки, отбрасывая известные потоки.

-v: print version

Этот флаг используется для печати номера версии и даты nProbe.

-C: flow export lock

Это простой способ реализовать высокую доступность. Запустите два зонда, собирающих одни и те же данные. Главный зонд излучает потоки, ведомый зонд запускается с помощью –C <путь>. Пока <path> существует, ведомое устройство работает, но поток не генерируется. Если файл <path> удален (например, с помощью внешней программы для управления ведущим/ведомым устройством, например heartbeat), ведомое устройство начинает излучать потоки. Если файл восстановлен, ведомый снова молчит.

-h: print help

Печатает справку nProbe.

--dont-nest-dump-dirs

nProbe выгружает данные на диск (например, с помощью -P), используя вложенный каталог. По сути, базовый каталог будет разделен на подкаталоги со структурой <год>/<месяц>/<день>/<час>/<мин>. используйте эту опцию, если вы хотите nProbe выгрузить все данные в базовом каталоге без создания этого вложенного дерева каталогов.

-I: log to syslog <probe name>

nProbe регистрируется на стандартном выводе, если не используется флаг –g (см. выше). Если вместо файла необходимо использовать syslog, этот флаг позволяет nProbe войти в систему с использованием указанного имени (это полезно, когда на одном хосте активно несколько экземпляров nProbe). Обратите внимание, что –g игнорируется, если используется –I, и эта опция недоступна в nProbe для Win32.

-w: size of the hash that stores the flows

Размер по умолчанию — 131072, и этого должно быть достаточно для большинства сетей. В случае, если потоки создаются нечасто и при сильном трафике, необходимо увеличить хэш. Дополнительную информацию о настройке nProbe смотрите далее в этом руководстве.

-W: Discard IPv6 traffic

Используйте этот флаг, если хотите, чтобы nProbe не учитывал трафик IPv6.

-e: flow export delay

Некоторые коллекционеры не успевают за скоростью экспорта nProbe. Этот флаг позволяет замедлять потоки, добавляя небольшую задержку (указанную в мс) между двумя последовательными экспортами. Максимально допустимая задержка составляет 1000 мс.

-B: packet count delay

Он указывал, сколько пакетов потока необходимо отправить, прежде чем будет применен параметр –e.

-z: <TCP[:UDP[:O]]>

Одноранговые приложения, атаки или неправильно настроенные приложения часто генерируют множество крошечных потоков, которые могут вызвать значительную нагрузку на сторону коллектора. Поскольку большинство установок коллектора часто отбрасывают эти потоки, можно настроить nProbe с помощью флага –z, чтобы не создавать такие потоки.

-M: maximum number of active flows

Он используется для ограничения максимального количества одновременных потоков, которые может поддерживать зонд. Это полезно для предотвращения создания зондом необходимого количества потоков и, следовательно, захвата всех доступных ресурсов.

-E: netflow engine

Укажите netflow engineType:engineId в сгенерированные потоки.

-m: minimum number of flows per packet

Чтобы минимизировать количество отправляемых пакетов, содержащих потоки, можно указать минимальное количество потоков, которые обязательно должны содержаться в пакете. Это означает, что пакет не отправляется до тех пор, пока не будет достигнуто указанное количество потоков.

-q: <host>:[<port>] flow sender address and port

Эта опция используется для указания адреса и, при необходимости, порта, который будет использоваться nProbe для отправки потоков в направлении пункта назначения, указанного с помощью -n. На практике nProbe создаст сокет и привяжет его к <host>:[port], что позволяет пользователю выбирать интерфейс, используемый исходящими потоками при выходе из хоста.

-S <pkt rate>:<flow collection rate>:<flow export rate>

С помощью этой опции можно указать три различных тарифа:

  • Частота выборки захвата пакетов <pktrate>. Эта частота эффективна для интерфейсов, указанных с помощью -i, и позволяет контролировать частоту дискретизации входящих пакетов. Например, частота дискретизации 100 будет указывать nprobe фактически обрабатывать один пакет из 100, отбрасывая все остальные. Вся статистика, включая общее количество байтов и пакетов, будет автоматически увеличена на nprobe, чтобы отразить частоту дискретизации. В предыдущем примере размер выборочного пакета будет умножен на 100. К <pktrate> можно добавить символ «@», чтобы указать nprobe использовать только частоту дискретизации для масштабирования без выполнения какой-либо фактической выборки. Это особенно полезно, когда входящие пакеты уже отобраны на устройстве захвата, подключенном к nprobe, но по-прежнему имеет смысл иметь масштабированную статистику.

  • Частота выборки сбора потока <частота сбора потока>. Эта скорость работает, когда nprobe находится в режиме коллектора, то есть когда используется опция –collector-port и определяет скорость потока, при которой отбирались образцы собираемых потоков. В этом случае фактическая выборка во входящих потоках не производится. Указанная скорость используется только для выполнения масштабирования. Например, поток с 250 IN_BYTES будет масштабирован с коэффициентом, равным частоте дискретизации. Если частота дискретизации равна 100, для этого потока будет учтено в общей сложности 2500 IN_BYTES.

  • Скорость экспорта потока <скорость экспорта потока>. Эта скорость эффективна, когда nprobe экспортирует NetFlow в сторону нижестоящего коллектора, то есть когда используется опция -n. Он управляет выходной выборкой. Например, <скорость экспорта потока>, равная 100, приведет к тому, что nprobe будет экспортировать только 1 поток из 100 в сторону нижнего коллектора.

-A: AS file

Сетевые зонды обычно устанавливаются в системах, где доступна информация о маршрутизации (например, через BGP), чтобы указать идентификатор AS (автономной системы) узла потока. Поскольку nProbe не имеет доступа к информации BGP, если вы не включите плагин BGP, пользователям необходимо предоставить эту информацию посредством статического файла в формате <AS>:<сеть>. Файл можно сохранить как в текстовом формате, так и в формате gzip.

--city-list: City List

С помощью этой опции вы можете включить геолокацию IP-адресов на уровне детализации города/страны. Здесь нужно указать базу данных города GeoIP (например GeoLiteCity.dat)

-g

Он указывает путь, по которому nProbe сохранит PID процесса.

-T: flow template definition

В отличие от NetFlow v5, где формат потока фиксирован, NetFlow V9 и IPFIX потоки имеют собственный формат, который можно указать во время выполнения с помощью этой опции, как указано в приложении.

-U: flow template id

Формат потоков NetFlow v9 и IPFIX указывается в шаблоне, определение которого отправляется nProbe перед началом отправки потоков. Формат потока определяется –T, где –U используется для установки идентификатора шаблона. Эту опцию не следует использовать, если не требуется изменить значение шаблона по умолчанию (257). Поскольку на основе -T nProbe можно определить несколько шаблонов, это значение используется для первого определенного шаблона.

-V: flow export version

Он используется для указания версии потока для экспортируемых потоков. Поддерживаемые версии: 5 (v5), 9 (v9) и 10 (IPFIX).

-o: intra templates packet export.

Он определяет количество пакетов потока, которые экспортируются между двумя экспортами шаблонов.

--aggregate-gtp-tunnels

Объединяет трафик, проходящий в каждом туннеле GTP, на основе идентификатора туннеля.

-L: local networks

Используйте этот флаг, чтобы указать (в формате сеть/маска, например 192.168.0.10/24) список сетей, которые считаются локальными (см. –c).

-c: track local hosts only

Это позволяет nProbe установить значение 0.0.0.0 для всех тех хостов, которые считаются нелокальными (см. –L). Это полезно, когда необходимо ограничить анализ трафика только локальными хостами.

-r: set traffic direction

При использовании этой опции (перед –r необходимо указать -L) весь трафик, идущий в сторону локальных сетей, считается входящим, весь rest — исходящим. Это влияет на –u/-Q, которые затем принудительно активируются с помощью –r.

--if-networks

Флаги -u и -Q используются для указания идентификаторов интерфейса SNMP для излучаемых потоков. В зеркальных средах можно имитировать коммутируемую среду, играя с MAC-адресами. Эта опция позволяет пользователям привязать MAC- или IP-адрес к указанному идентификатору интерфейса. Синтаксис –if-networks: <MAC|IP/mask>@<interfaceId>, где несколько записей могут быть разделены запятой (,). Пример: –if-networks «AA:BB:CC:DD:EE:FF@3,192.168.0.0/24@2» или –if-networks @<имя файла>, где <имя файла> — это путь к файлу, содержащий сети, указанные в приведенном выше формате.

--count: debug only

Пусть зонд захватывает только указанное количество пакетов.

--collector-port: specifies the NetFlow collector port

Используйте nProbe для сбора пакетов NetFlow/jFlow/IPFIX/sFlow. Использовать опцию --collector-port указать, на каких портах должны собираться такие пакеты. nProbe способен принимать и конвертировать потоки из различных версий. Например nprobe --collector-port 2055 --i 192.168.0.1:2056 --V 10 преобразует каждый поток, полученный через порт 2055, в IPFIX и отправляет их на 192.168.0.1:2056. По умолчанию nProbe привязывает порт сбора ко всем доступным интерфейсам. При желании вы можете привязать порт только к одному интерфейсу. Это можно сделать, указав дополнительный локальный (для хоста, на котором работает nprobe) IP-адрес. Пример -3 192.168.1.23:2055.

Вариант --collector-port также может использоваться для получения пакетов NetFlow/jFlow/IPFIX/sFlow через реле ZMQ. В этом случае следует указать конечную точку ZMQ. Реализация реле ZMQ доступна в исполняемом файле. flowRelay. Бегать flowRelay -h чтобы увидеть, как его использовать.

--collector-passthrough

Экспортируйте потоки в настроенные конечные точки ZMQ как есть, игнорируя -T. С использованием --collector-passthrough обеспечивает максимальную производительность сбора. Поддерживается экспорт ZMQ/Syslog/Kafka. Видеть Понимание того, как работает сбор потоков для подробного обсуждения. Обратите внимание, что -T игнорируется при использовании сквозной передачи. Это функция nProbe только для Pro.

--collector-nf-reforge <file>

Функция только для сбора потоков. Он позволяет пользователям настраивать фильтрацию и переформирование коллекции NetFlow, указав файл конфигурации и передав его в качестве аргумента. Формат файла — тот, который показан в этом примере (столбцы разделены табуляцией). В этом примере потоки, отправленные зондом NeFflow, активным по IP-адресу 192.168.1.1, собираются с помощью nProbe и экспортируются (например, через ZMQ в ntopng или на удаленный сборщик через -n), как если бы они были отправлены хостом 192.168.1.1: только потоки с Netflow InterfaceId 1,2,3,4 являются обрабатываются, все остальные интерфейсы отбрасываются. Чтобы собрать все интерфейсы и просто изменить IP-адрес зонда, используйте * в списке интерфейсов. Зонды, не перечисленные в файле, обрабатываются как есть, без какой-либо перековки или фильтрации шаблонов.

# CollectorIP   ReforgedIP      ListOfAllowedInterfaces
# Example:
127.0.0.1       10.0.24.25      12
192.168.1.1     192.168.1.1     1,2,3,4

--tunnel

Позвольте зонду декодировать туннелированный трафик (например, трафик GTP или GRE) и, таким образом, извлекать информацию о трафике из такого трафика, а не из внешнего конверта.

--no-promisc

С этой опцией nProbe не используется неразборчивый режим для захвата пакетов.

--smart-udp-frags:

Игнорируйте UDP фрагментированные пакеты со смещением фрагмента больше zero и вычисляйте длину фрагментированного пакета по начальному заголовку фрагмента. Этот флаг может привести к неточности измерений, но он ускоряет работу с фрагментированным трафиком.

--ipsec-auth-data-len

Длина данных аутентификации IPSec в туннельном режиме. Если этот параметр не установлен, IPSec не будет декодироваться, а просто учитываться.

--dump-stats:  dump some flow statistics on file

Периодически сбрасывать статистику NetFlow в указанный файл. Обратите внимание, что при использовании nProbe вместо PF_RING, nProbe сбрасывает статистику в /proc/net/pf_ring/stats/<nprobe файл статистики>.

--black-list

С помощью этой опции вы можете указать список сетей или хостов, все входящие пакеты которых будут отбрасываться зондом. Принятым обозначением может быть формат CIDR или классический формат сети/маски сети.

--pcap-file-list <file>

Указанный путь к файлу содержит список файлов pcap, которые должны быть прочитаны последовательно с помощью nProbe. Используйте эту опцию, если вы хотите, чтобы nProbe прочитал список файлов pcap (например, если он создан с помощью tcpdump).

--biflows-export-policy <policy>

Двунаправленные потоки таковы, когда трафик существует в обоих направлениях потока (т. е. источник->назначение и место назначения->источник). Поскольку однонаправленные потоки могут указывать на подозрительные действия, этот флаг используется для определения политики экспорта:

  • 0: Экспортировать все известные данные (т. е. моно- и двунаправленные потоки).

  • 1: Экспортировать только двунаправленные потоки, исключая однонаправленные потоки.

  • 2: Экспортировать только однонаправленные потоки, отбрасывая двунаправленные потоки.

--csv-separator <separator>

Заменить разделитель «|» по умолчанию в дампах указанным.

--dont-drop-privileges

Не отказывайте root-права пользователю «никто», если указана эта опция. См. раздел –unprivileged-user далее в этом руководстве.

--account-l2

NetFlow учитывает только IP-трафик, не считая заголовков уровня 2. При использовании этой опции заголовки уровня 2 также учитываются в статистике потокового трафика.

--dump-metadata <file>

Сохраните информацию метаданных в указанный файл и выйдите. Эта опция полезна, когда пользователи хотят знать тип каждого информационного элемента, экспортируемого nProbe, чтобы (например) они могли правильно импортировать в базу данных.

--ntopng <option>

Вы можете использовать эту опцию, чтобы дать команду nProbe отправить данные в сторону ntopng, используя ZMQ (доступно на всех платформах) или Kafka (доступно на выбранных платформах). При использовании ZMQ вы можете указать --ntopng zmq://<socket>:<port> для доставки потоков в ntopng, подключенный к указанной конечной точке ZMQ (см. также старую опцию --zmq). Если определено более одной конечной точки, для равномерного балансирования потоков между ними используется хэш-функция. Пример: --ntopng zmq://*:5556 или --ntopng zmq://127.0.0.1:1234

Когда используется Kafka, синтаксис следующий: --ntopng kafka://<brokers> чтобы вы могли доставлять потоки на ntopng, подключенные к указанному брокеру Kafka, в открытом виде. Вместо этого вы можете использовать --ntopng kafka-ssl://<brokers> для доставки данных в TLS/SSL. Kafka брокеры разделяются запятой (если определено более одного). Примеры: --ntopng kafka://192.168.1.2 или --ntopng kafka-ssl://192.168.1.2,172.16.24.12.

--zmq <socket>

Укажите сокет (например, tcp://*:5556), который будет использоваться для доставки потоков подписчикам, опрашивающим сокет. Можно указать до 8 конечных точек ZMQ, повторяя –zmq. Если указано более одной конечной точки, nProbe использует хеш-функцию для равномерного балансирования потоков между всеми определенными конечными точками. Обратите внимание, что эта опция является псевдонимом для --ntopng и он может быть удален в будущих версиях. Пример:

./nprobe -i eth0 -n none --zmq tcp://\*:5556 --zmq tcp://\*:5557
./ntopng -i tcp://127.0.0.1:5556 -i tcp://127.0.0.1:5557 -i view: tcp://127.0.0.1:5556, tcp://127.0.0.1:5557

--zmq-probe-mode

По умолчанию nProbe действует как сервер ZMQ, который доставляет потоки подписчикам. При использовании этого переключателя его роль возвращается. Обычно это используется в сочетании с ntopng запуском в режиме коллектора. Подробное описание см. в разделе «Использование nProbe с ntopng».

--zmq-encryption-key <pub key>

Зашифруйте потоки, доставляемые через ZMQ, указав открытый ключ, сгенерированный ntopng. Если этот параметр не указан, трафик ZMQ по-прежнему шифруется по умолчанию с использованием общедоступного, хорошо известного встроенного ключа.: это только предотвращает случайное раскрытие открытого текста и не обеспечивает реальной конфиденциальности, поэтому всегда следует настраивать выделенную пару ключей для рабочих/недоверенных развертываний. См. Шифрование данных раздел документации ntopng и https://www.ntop.org/guides/ntopng/using_with_other_tools/nprobe.html, для получения дополнительной информации и примера конфигурации.

--zmq-encrypt-pwd <pwd>

Зашифруйте данные ZMQ, используя указанный пароль (обфускация на основе XOR). Это альтернативный устаревший механизм --zmq-encryption-key и не обеспечивает шифрование уровня CURVE.

--tcp <server:port>

Доставляет потоки в формате JSON через TCP в указанную пару сервер:порт.

--event-log <file>

Сохраните соответствующие действия (например, nProbe запуск/останов или сброс пакетов) в указанный файл.

--enable-throughput-stats

Когда используется -P, с помощью этой опции также можно генерировать информацию о пропускной способности. Файл имеет следующий формат: <эпоха> <байты> <пакеты>. Каждая строка печатается каждую секунду и содержит количество байтов и пакетов, наблюдаемых в течение минуты.

--disable-upscale

Игнорировать частоту дискретизации sFlow/NetFlow/IPFIX (используется 1:1), поэтому собранный трафик не масштабируется.

--ndpi-proto-ports <file>

Прочтите конфигурацию пользовательского протокола и портов nDPI из указанного файла. Дополнительную информацию о формате этого файла см. в руководстве nDPI.

--disable-l7-protocol-guess

Когда nDPI не может обнаружить протокол, nProbe использует информацию о порте, чтобы угадать протокол. Этот флаг запрещает nProbe делать это, поэтому протоколы обнаруживаются только nDPI без использования портов по умолчанию.

--db-engine <database engine>

В случае, если потоки сбрасываются в базу данных MySQL (см. далее в этом руководстве), ядром базы данных по умолчанию, используемым nProbe, является MyISAM. С помощью этой опции вы можете использовать другой движок (например, InnoDB).

--unprivileged-user <name>

Когда nprobe удаляет привилегии (если не используется –dont-drop-privileges), пользователь никто не используется. Используя эту опцию, можно использовать другого пользователя.

--enable-collection-cache

nProbe реализует кэш потока для объединения пакетов, принадлежащих одному потоку. В коллекции потоков кэш потока отключен. Эта опция включает кэш сбора потоков, как если бы nProbe работал в режиме захвата пакетов. Обратите внимание, что эта опция доступна только в режиме сборщика/прокси (т. е. используйте -i none).

--collector-passthrough

Если вы хотите использовать nProbe в качестве прокси/сборщика потока (например, по отношению к ntopng) и иметь сопоставление 1:1 между собранными/экспортируемыми потоками, вам следует использовать этот вариант. Это потому, что он позволяет собирать потоки на высокой скорости с ограниченным использованием CPU. Обратите внимание, что эта опция бесполезна, если используется –disable-cache.

--redis <host>[:<port>]

База данных redis (когда с ней компилируется nProbe) используется для реализации кэша данных и для агрегирования информации о потоке. Эта опция указывает хост (и, возможно, порт), который прослушивает redis. nProbe открывает несколько соединений с redis (а не только одно), чтобы максимизировать производительность.

--ucloud

Эта опция включает концепцию микрооблака. Пожалуйста, обратитесь к http://www.ntop.org/nprobe/monitoring-on-the-microcloud/ для получения дополнительной информации.

--check-license

Проверяет, действительна ли настроенная лицензия (только для двоичных nProbe).

--disable-startup-checks

Во время запуска nProbe получает как IP-адрес интерфейса управления, так и свой общедоступный IP-адрес. IP-адрес интерфейса управления — это адрес физически подключенного интерфейса, по которому передается сетевой трафик nProbe. Публичный IP-адрес — это адрес интерфейса управления, видимый из Интернета. Получение общедоступного IP-адреса запускает запрос на http://checkip.dyndns.org.

--dump-plugin-families

Дамп названий семейств установленных плагинов.

--minute-expire

Принудительно установите nProbe для экспорта активных потоков по истечении минуты. Это полезно, если вы хотите (например, используя -P), чтобы потоки обновлялись каждую минуту и ​​заканчивались через X минут 0 секунд.

Поскольку некоторые люди предпочитают иметь файл конфигурации, содержащий параметры, которые в противном случае были бы указаны в командной строке, также можно запустить nProbe следующим образом:

nprobe <configuration file path>

где файл конфигурации содержит те же параметры, которые указаны в командной строке. Единственная разница между командной строкой и файлом конфигурации заключается в том, что в разных строках необходимо указывать разные параметры. Например:

nprobe --n 127.0.0.1:2055 -i en0 -a -p

то же самое, что:

nprobe /etc/nprobe.conf

где /etc/nprobe.conf содержит следующие строки:

# cat /etc/nprobe.conf

-n=127.0.0.1:2055
-i=en0
-a=
-p=

Обратите внимание, что для флагов, не имеющих связанных параметров (например, –a), также необходимо указать знак «=». Любой стандартный коллектор NetFlow (например, ntop) можно использовать для анализа потоков, генерируемых nProbe. При использовании с ntop, nProbe может действовать как удаленный и легкий сборщик трафика, а ntop — как центральная консоль мониторинга сети. Дополнительную информацию по этой теме см. в главе 3.

Примечание об индексах интерфейсов и MAC/IP-адресах (маршрутизатора)

Флаги -u и -Q используются для указания идентификаторов интерфейса SNMP для излучаемых потоков. Однако с помощью –if-networks можно указать идентификатор интерфейса, к которому привязан MAC-адрес или IP-сеть. Синтаксис –if-networks:

<MAC|IP/mask>@<interfaceId>, где несколько записей могут быть разделены запятой (,).

Пример: –if-networks «AA:BB:CC:DD:EE:FF@3,192.168.0.0/24@2» или –if-networks @<имя файла> где <имя файла> — путь к файлу, содержащему сети указывается в указанном выше формате.
