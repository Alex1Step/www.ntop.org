5. npcapprintindex

Эта утилита считывает и отображает содержимое индексного файла npcap (.idx), созданного n2disk или npcapindex. Он может печатать информацию о пакете в удобочитаемом формате или формате JSON, проверять целостность индекса и отображать статистику об индексированном трафике.

npcapprintindex полезен для отладки индексных файлов, проверки данных захвата, анализа шаблонов трафика и извлечения метаданных без обработки всего файла pcap.

5.1. Использование

npcapprintindex -i <index file> [options]

Доступные варианты:

[-i] <index file>     | Index file to read (.idx file)
[-j]                  | JSON output format
[-c]                  | Check index integrity only (no packet printing)
[-n] <num>            | Print first num packets only
[-T]                  | Print first and last timestamps only
[-v]                  | Verbose mode (show index details)
[-h]                  | Help

5.2. Информация об индексе

npcapprintindex может читать индексные файлы в форматах V1 и V2 и поддерживает следующие типы индексов:

  • Стандартный индекс пакетов: Содержит дайджесты пакетов с информацией об IP/порте.

  • индекс GTP: включает информацию как о внешнем, так и о туннелированном (внутреннем) пакете.

Инструмент автоматически обнаруживает и отображает:

  • Индексная версия (V1 или V2)

  • Точность временной метки (микросекунда или наносекунда)

  • Необязательные поля (идентификатор устройства, идентификатор порта)

  • Растровые изображения фильтра Блума (MAC, порт, IP, протокол L7, устройство)

  • Формат сжатия, используемый для индекса

5.3. Выходные форматы

Удобочитаемый формат (по умолчанию)

Отображает каждый пакет с:

  • Номер пакета

  • Временная метка (ЧЧ:ММ:СС.микросек или ЧЧ:ММ:СС.наносек)

  • Длина пакета

  • VLAN Идентификаторы (одиночные и QinQ)

  • IP-версия (IPv4 или IPv6)

  • Номер протокола

  • IP-адреса источника и назначения

  • Порты источника и назначения

  • протокол Layer 7 (когда доступен nDPI и индекс V2)

  • GTP информация о туннелированном пакете (для индексов GTP)

JSON Формат (-j)

Выходные данные структурированы JSON с метаданными пакета для удобства анализа и интеграции с другими инструментами.

5.4. Пример использования

Отобразить все пакеты из индексного файла:

npcapprintindex -i /storage/dump.pcap.idx

Отображать пакеты в формате JSON:

npcapprintindex -i /storage/dump.pcap.idx -j

Проверьте целостность индекса без печати пакетов:

npcapprintindex -i /storage/dump.pcap.idx -c

Отображать только первые 100 пакетов:

npcapprintindex -i /storage/dump.pcap.idx -n 100

Показать временные метки первого и последнего пакета:

npcapprintindex -i /storage/dump.pcap.idx -T

Отобразить детали индекса в подробном режиме:

npcapprintindex -i /storage/dump.pcap.idx -v

5.5. Пример вывода

Удобочитаемый формат:

Found index version 2 [packet index]
Index includes timestamps
1) [14:23:45.123456] len: 74, vlan: 0, vlan_qinq: 0, ipv4, proto: 6, 192.168.1.100:49152 -> 10.0.0.1:80, l7proto: HTTP
2) [14:23:45.123789] len: 60, vlan: 0, vlan_qinq: 0, ipv4, proto: 6, 10.0.0.1:80 -> 192.168.1.100:49152, l7proto: HTTP
3) [14:23:45.124012] len: 1514, vlan: 0, vlan_qinq: 0, ipv4, proto: 6, 10.0.0.1:80 -> 192.168.1.100:49152, l7proto: HTTP

JSON Формат:

{ "epoch" : 1234567890.123456, "length" : 74, "tuple" : { "vlan" : 0, "vlan_qinq" : 0, "ip_version" : 4, "protocol" : 6, "src_ip" : "192.168.1.100", "dst_ip" : "10.0.0.1", "src_port" : 49152, "dst_port" : 80, "l7protocol" : "HTTP" } }

Вывод только меток времени (-T):

First-TS [14:23:45.123456]
Last-TS  [18:45:12.987654]

5.6. Статистика

При компиляции с поддержкой nDPI и использованием индекса V2 npcapprintindex отображает статистику протокола Layer 7 в конце:

--- Protocols stats ---
HTTP: 1523 pkts (45.32%)
TLS: 892 pkts (26.54%)
DNS: 421 pkts (12.53%)
SSH: 267 pkts (7.95%)
Unknown: 257 pkts (7.65%)

5.7. Проверка целостности индекса

Используйте -c флаг для проверки целостности индексного файла без печати пакетов. Это полезно для:

  • Проверка индексных файлов после операций копирования/перемещения

  • Проверка на коррупцию

  • Автоматические проверки работоспособности в скриптах

npcapprintindex -i /storage/dump.pcap.idx -c
echo $?  # Returns 0 if index is valid, non-zero otherwise

Проверка подтверждает:

  • Индекс магического числа и версии

  • Целостность сжатия

  • Ожидаемый и фактический размеры дайджеста

  • Структура растрового изображения (если присутствует)

5.8. IPv6 Представление

Благодаря оптимизации индекса адреса IPv6 хэшируются и отображаются в сокращенном виде, показывая только последние 4 байта:

*:a1b2:c3d4:45152 -> *:e5f6:7890:443

Этого достаточно для большинства целей отладки и позволяет компактно хранить индексы.

5.9. GTP Информация о туннеле

Для индексов GTP отображается информация как о внешних, так и о туннелированных пакетах:

vlan: 0, ipv4, proto: 17, 10.1.1.1:2152 -> 10.1.1.2:2152, tunneled ipv4, proto: 6, 192.168.1.100:49152 -> 172.16.0.1:80

5.10. Примеры

Извлечь количество пакетов:

npcapprintindex -i dump.pcap.idx | tail -1 | cut -d')' -f1

Извлечь временной диапазон:

npcapprintindex -i dump.pcap.idx -T

5.11. Поиск неисправностей

Ошибка: «Неверная версия индекса».

Индексный файл может быть поврежден или несовместим. Регенерировать с помощью:

npcapindex -i original.pcap -o new.pcap.idx

Ошибка: «Индекс слишком короткий»

Индексный файл усечен или поврежден. Проверьте место на диске и права доступа к файлам.

Ошибка: «Ошибка декомпрессии».

Сжатие индекса повреждено. Восстановите индексный файл.

Нет информации о протоколе Layer 7

Либо: - Индекс соответствует версии V1 (только версия V2 включает информацию L7) - npcapprintindex был скомпилирован без поддержки nDPI - Индекс создан без nDPI

5.12. Совместимость

npcapprintindex работает с индексными файлами, созданными: - n2disk (все версии с включенным индексированием) - утилита npcapindex
