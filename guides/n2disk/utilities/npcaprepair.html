8. npcaprepair

Эта утилита проверяет и восстанавливает поврежденные или неполные наборы дампов, созданные n2disk, включая отсутствующие индексы и неработающие ссылки на временную шкалу. Он сканирует каталог хранения, проверяет каждый файл pcap, восстанавливает отсутствующие индексные файлы и воссоздает структуру символических ссылок временной шкалы.

npcaprepair необходим для:

  • Восстановление после прерванного захвата n2disk

  • Исправление нарушенных структур временной шкалы после миграции хранилища.

  • Восстановление отсутствующих индексных файлов

  • Восстановление поврежденных наборов дампов после сбоев системы или ошибок диска.

8.1. Использование

npcaprepair <storage path> <timeline path>

Аргументы:

  • путь хранения: Каталог, содержащий файлы pcap/npcap (поиск на глубину до 2 уровней)

  • путь на временной шкале: Корневой каталог структуры временной шкалы.

8.2. Предварительные условия

npcaprepair требует установки следующих инструментов:

  • Тшарк: Для чтения временных меток пакетов из файлов pcap.

Установите tshark (инструмент командной строки Wireshark):

# Debian/Ubuntu
sudo apt-get install tshark

# Red Hat/CentOS
sudo yum install wireshark

8.3. Как это работает

Для каждого файла pcap/npcap, найденного в каталоге хранилища, npcaprepair выполняет следующие проверки и исправления:

  1. Обнаружение файлов:

    • Рекурсивно сканирует каталог хранилища (максимальная глубина: 2 уровня).

    • Определяет все .pcap и .npcap файлы

  2. Извлечение временной метки:

    • Использует tshark для чтения временной метки первого пакета.

    • Извлекает информацию о дате, времени и эпохе

    • Определяет соответствующий 10-минутный интервал временной шкалы.

  3. Проверка/создание индекса:

    • Проверяет, если .idx файл существует

    • Проверяет целостность индекса с помощью npcapprintindex -c

    • Восстанавливает индекс, если он отсутствует или поврежден, используя npcapindex

  4. Создание ссылки на временную шкалу:

    • Создает структуру каталогов временной шкалы: YYYY/MM/DD/HH/MM (10-минутные слоты)

    • Создает символическую ссылку с временной шкалы на файл pcap: timeline/YYYY/MM/DD/HH/MM/epoch.pcap

    • Создает обратную символическую ссылку от pcap на временную шкалу: storage/file.pcap.timeline

    • Повторяется для индексных файлов: timeline/YYYY/MM/DD/HH/MM/epoch.pcap.idx и storage/file.pcap.idx.timeline

  5. Тип ссылки:

    • По умолчанию использует относительные символические ссылки (переносимо и рекомендуется)

    • Возврат к абсолютным ссылкам, если расчет относительного пути не удался.

8.4. Пример использования

Восстановительный дамп с временной шкалой:

npcaprepair /storage/n2disk /storage/n2disk/timeline

Восстановление после миграции хранилища:

# After moving storage to new location
npcaprepair /new-storage /new-storage/timeline

Исправлена ​​неработающая временная шкала после ручных операций с файлами:

npcaprepair /data/pcaps /data/timeline

8.6. Структура временной шкалы

npcaprepair создает иерархическую структуру каталогов временной шкалы с 10-минутной детализацией:

timeline/
└── 2021/
    └── 09/
        └── 28/
            └── 14/
                ├── 20/
                │   ├── 1632826800.123456.pcap -> ../../../../../../storage/file.pcap
                │   └── 1632826800.123456.pcap.idx -> ../../../../../../storage/file.pcap.idx
                └── 30/
                    ├── 1632827400.654321.pcap -> ../../../../../../storage/file2.pcap
                    └── 1632827400.654321.pcap.idx -> ../../../../../../storage/file2.pcap.idx

Обратные ссылки в хранилище:

storage/
├── file.pcap
├── file.pcap.idx
├── file.pcap.timeline -> ../timeline/2021/09/28/14/20/1632826800.123456.pcap
└── file.pcap.idx.timeline -> ../timeline/2021/09/28/14/20/1632826800.123456.pcap.idx

8.7. Варианты использования

Сценарий 1: Нарушенный график после миграции

После перемещения хранилища в новое место ссылки на временную шкалу рвутся:

# Remove old broken timeline
rm -rf /old-location/timeline

# Create new timeline structure
npcaprepair /new-location/storage /new-location/timeline

Сценарий 2: Добавление файлов вручную

После копирования файлов pcap вручную в хранилище:

# Add new files to timeline
npcaprepair /storage /storage/timeline

Сценарий 3: Восстановление поврежденной файловой системы

После ремонта или восстановления файловой системы:

# Validate and repair all indexes and links
npcaprepair /recovered-storage /recovered-storage/timeline

8.8. Важные примечания

  • Именование файлов: файлы Pcap переименовываются на временной шкале с использованием временных меток эпохи, извлеченных из первого пакета.

  • 10-минутные слоты: на временной шкале используется 10-минутная детализация (00, 10, 20, 30, 40, 50 минут).

  • Относительные ссылки: для переносимости по умолчанию используются относительные символические ссылки.

  • Предел глубины: сканирует только 2 уровня каталогов в хранилище (используйте -maxdepth в скрипте подкорректировать)

  • Источник временной метки: использует временную метку первого пакета для определения размещения файла.

  • Идемпотент: Безопасно запускать несколько раз; пропускает существующие действительные индексы и ссылки

  • Неразрушающий: Не изменяет и не удаляет существующие действительные файлы.

8.9. Совместимость

npcaprepair работает с:

  • Все форматы дампов n2disk (pcap и npcap)

  • Стандартные файлы pcap, скопированные в хранилище n2disk.

  • Как сжатые, так и несжатые файлы захвата.

  • Захват с одним и несколькими интерфейсами
