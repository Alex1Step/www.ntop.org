Тюнинг

Чтобы добиться хорошей настройки n2disk, способной обеспечить максимальную производительность, важно принять во внимание следующие аспекты.

Помимо libpcap, n2disk может использовать ускорение PF_RING (стандартное или ZC) для захвата пакетов из действующего сетевого интерфейса.

Для скорости входящего трафика выше 2–3 Gbit/с рекомендуется PF_RING ZC. Если вам необходимо объединить несколько каналов со скоростью 10 Gbit/с в один дампсет, рекомендуется использовать PF_RING FPGA с использованием карты, поддерживающей аппаратную агрегацию.

В случае использования стандарта PF_RING особенно важно зарезервировать достаточно места в кольцевом буфере внутри ядра. Кроме того, чтобы уменьшить количество тактовых циклов, необходимых для захвата пакетов и прохождения сетевого стека, можно включить быстрый_режим в конфигурации модуля ядра pf_ring.

Для получения дополнительной информации о PF_RING и ZC, пожалуйста, прочитайте PF_RING документация.

Что касается параметров запуска n2disk, особенно важными являются следующие параметры:

  • Максимальный размер файла (-p) не должен быть очень маленьким. Хорошее значение должно быть больше 64 Мбайт, до 2 ГБ, если скорость трафика выше 10 Гбит/с.

  • Длина буфера (-b) должна быть достаточно большой. В большинстве случаев достаточно 2 ГБ, лучше увеличить до 8 ГБ, если скорость входящего трафика превышает 10 Гбит/с. В любом случае это значение должно быть кратно максимальному размеру файла (-p).

  • Путь хранения (-o)

  • Ограничение диска (–disk-limit) должно быть установлено на максимальное дисковое пространство, которое будет использоваться для файлов pcap. Для выделенного хранилища рекомендуется установить значение 80 % (учитывая, что для индексных файлов используется дополнительное пространство).

  • Размер блока записи (-C) должен быть больше или равен 64 Кбайт, значение по умолчанию обычно подходит.

  • Основная привязка для потоков чтения (-c) и записи (-w). Настоятельно рекомендуется привязать эти потоки к разным ядрам одного и того же физического CPU (в соответствии с топологией системы следует выбрать физический CPU, к которому ближе/напрямую подключена сетевая карта).

  • Если вы используете индексирование (-I), которое требуется для инструмента извлечения, рекомендуется включить выделенные потоки индексирования, устанавливающие привязку ядра (-z <ядра> -Z).

  • Путь временной шкалы (-A) для организации файлов pcpa и индексов и их сортировки по дате (требуется для инструментов извлечения).

  • Если у вас есть основное/быстрое хранилище (используется в качестве кэша, чтобы не отставать от часов пик) и вторичное/более медленное хранилище (используется для максимально быстрого перемещения данных), вы можете использовать опцию -O, чтобы включить архивирование на втором хранилищеi (необязательно).
