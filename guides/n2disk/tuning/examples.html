1. Примеры

1.1. Сброс 10-20 Gbps

Требование: 4-ядерная система 3 ГГц.

Командная строка:

n2disk -i zc:eth1 -o /storage/n2disk/pcap -b 8192 -p 1024 --disk-limit 80% -S 0 -c 1 -w 2

Соответствующий файл конфигурации:

--interface=zc:eth1
--dump-directory=/storage/n2disk/pcap
--disk-limit=80%
--max-file-len=1024
--buffer-len=8192
--reader-cpu-affinity=1
--writer-cpu-affinity=2
--time-pulse=0

1.2. Дамп и индекс 10-20 Gbps

Требование: 6-ядерная система 3 ГГц.

Командная строка:

n2disk -i zc:eth1 -o /storage/n2disk/pcap -I -A /storage/n2disk/timeline -b 8192 -p 1024 --disk-limit 80% -S 0 -c 1 -w 2 -k 3,4,5

Пример файла конфигурации для дампа и индексации 10-20Gbps в 6-ядерной системе:

--interface=zc:eth1
--dump-directory=/storage/n2disk/pcap
--timeline-dir=/storage/n2disk/timeline
--disk-limit=80%
--max-file-len=1024
--buffer-len=8192
--index
--reader-cpu-affinity=1
--writer-cpu-affinity=2
--indexer-cpu-affinity=3,4,5
--time-pulse=0

1.3. Дамп и индексирование на скорости 20–100 Гбит/с

Для сброса трафика на уровне 100 Gbps требуется несколько экземпляров n2disk или один экземпляр с несколькими потоками.

1.3.1. ПЛИС

На специализированных адаптерах FPGA, поддерживающих режим чанка/сегмента/блока PCAP, например Napatech или Silicom FPGA, это можно захватить до 50 Gbps на экземпляр или поток (для 100 Gbps требуется 2 потока).

Режим PCAP необходим для наилучшей производительности. В этом режиме адаптер перемещает данные PCAP порциями, оптимизируя передача данных по шине и снижение CPU нагрузки на копирование и обработку данных. Пожалуйста, проверьте разделы «Napatech Настройка» и «Silicom FPGA Настройка» для получения инструкций по настройке режима сегмента PCAP на этих адаптерах.

Для обработки 50 Gbps захват одного порта/потока обычно обеспечивает достаточную производительность.

Требования к оборудованию: 6 ядер 3 ГГц CPU.

n2disk пример конфигурации:

--interface=nt:0
--dump-directory=/storage/n2disk
--timeline-dir=/storage/n2disk/timeline
--disk-limit=80%
--max-file-len=1024
--buffer-len=4096
--index
--reader-cpu-affinity=0
--writer-cpu-affinity=1
--indexer-cpu-affinity=2,3,4,5

Чтобы обрабатывать 100 Gbps, адаптер должен быть настроен на 2 потока.

Аппаратные требования: 12 ядер 3 ГГц CPU.

Протестировано без потери пакетов до 148 Mpps 100 Gbps (средний размер пакета 60 байт).

Пример настройки потоков:

/opt/napatech3/bin/ntpl -e "Delete=All"
/opt/napatech3/bin/ntpl -e "HashMode = Hash5TupleSorted"
/opt/napatech3/bin/ntpl -e "Setup[NUMANode=0]=Streamid==(0..1)"
/opt/napatech3/bin/ntpl -e "Assign[streamid=(0..1)] = All"

Пример конфигурации n2disk (поток 0):

--interface=nt:stream0
--dump-directory=/storage1/n2disk/pcap
--dump-directory=/storage2/n2disk/pcap
--dump-directory=/storage3/n2disk/pcap
--dump-directory=/storage4/n2disk/pcap
--timeline-dir=/storage1/n2disk/timeline
--disk-limit=80%
--max-file-len=2048
--buffer-len=16384
--index
--reader-cpu-affinity=1
--indexer-cpu-affinity=2,3,4,5
--writer-cpu-affinity=0,0,0,0

Пример конфигурации n2disk (поток 1):

--interface=nt:stream1
--dump-directory=/storage5/n2disk/pcap
--dump-directory=/storage6/n2disk/pcap
--dump-directory=/storage7/n2disk/pcap
--dump-directory=/storage8/n2disk/pcap
--timeline-dir=/storage5/n2disk/timeline
--disk-limit=80%
--max-file-len=2048
--buffer-len=16384
--index
--reader-cpu-affinity=6
--indexer-cpu-affinity=7,8,9,10
--writer-cpu-affinity=0,0,0,0

1.3.2. ASIC-чипы

На адаптерах ASIC и адекватном оборудовании можно захватывать и сбрасывать до 10-20 Gbps на инстанс или поток.

Для обработки более 20 Gbps на адаптерах ASIC (NVIDIA/Mellanox или Intel), n2disk 3.7 и более поздних версиях включает встроенную поддержку RSS. RSS должен быть включен в адаптере, и n2disk можно настроить для захват из нескольких потоков RSS. Обратите внимание, что для этого требуется настройка из нескольких каталогов дампа и временных шкал (по одному на каждый RSS-поток), инструмент npcapextract можно использовать по адресу время извлечения для извлечения трафика со всех временных шкал, используя аппаратную метку времени с наносекундой разрешение (если оно поддерживается, например, на NVIDIA ConnectX и Intel E810) для объединения пакетов в правильном порядке.

Чтобы обрабатывать 100 Gbps, адаптер должен быть настроен на 8 очередей/потоков RSS.

Требования к оборудованию: 16-ядерная система 3 ГГц (например, Xeon Gold 6526Y).

Протестировано без потери пакетов до 102 Mpps 100 Gbps (средний размер пакета 100 байт).

Пример конфигурации RSS:

ethtool -L ens4f1np1 combined 8
