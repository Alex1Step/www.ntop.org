Экспорт потоков

Использование n2disk с другими инструментами, такими как ntopng, часто удобно для расширения непрерывная запись трафика с анализом/визуализацией трафика. Для этого причина n2disk была расширена для возможности экспорта статистики и потоков. метаданные в другие инструменты анализа через ZMQ.

Чтобы начать интеграцию и узнать больше о конфигурации, пожалуйста, прочтите ntopng Руководство пользователя

--zmq Эту опцию следует использовать для указания n2disk экспортировать потоки и статистика в формате TLV или JSON по ZMQ.

Пример командной строки:

n2disk -i eno1 -o /storage --zmq tcp://127.0.0.1:5556 -I -Z -z 0 --max-file-duration 10

Чтобы собрать потоки, генерируемые n2disk, с помощью ntopng, следуйте тем же инструкциям. инструкции, необходимые для через ntopng с nProbe работает ntopng в режиме коллектора (n2disk экспортирует потоки в тело зонда, соединяя до ntopng).

Пример:

ntopng -i "tcp://*:5556c"

n2disk реализует базовый шаблон (то, что вы обычно определяете в nprobe с помощью -T вариант), который содержит следующие поля:

%SRC_VLAN %IN_SRC_MAC %IN_DST_MAC %IP_PROTOCOL_VERSION %DIRECTION
%IPV4_SRC_ADDR %IPV4_DST_ADDR %IPV6_SRC_ADDR %IPV6_DST_ADDR
%INPUT_SNMP %OUTPUT_SNMP %IN_PKTS %IN_BYTES %OUT_PKTS %OUT_BYTES
%FIRST_SWITCHED %LAST_SWITCHED %L4_SRC_PORT %L4_DST_PORT
%TCP_FLAGS %PROTOCOL %SRC_TOS %L7_PROTO
%INPUT_SNMP %OUTPUT_SNMP %OBSERVATION_POINT_ID

Можно контролировать истечение потока и экспорт с помощью --lifetime-timeout и --idle-timeout параметры.

Обратите внимание, что некоторые поля заполняются в зависимости от конфигурации:

  • %INPUT_SNMP %OUTPUT_SNMP %OBSERVATION_POINT_ID доступны, когда Информация об устройстве и порте добавляется в пакет в виде метаданных внешним пакетные брокеры. Например Arista Устройства Metawatch экспортируют Metamako. трейлеры, кодирующие идентификатор устройства и идентификатор порта (добавьте –hw-timestamp метачасы в конфигурацию n2disk, чтобы включить ее).

  • %L7_PROTO доступен по умолчанию (нет необходимости использовать -E 2, как в предыдущих версиях)

Имейте в виду, что потоки вычисляются, как только файл PCAP заполнен и готов к записи на диск, это означает, что если вы имеют низкую пропускную способность трафика и файлы ошибок, потоки экспортируются с некоторыми задержка (до 10 минут, если у вас включена временная шкала и мало трафика). Чтобы уменьшить эту задержку, вы можете поиграть с --max-file-duration возможность чаще создавать файлы PCAP.

Помимо метаданных потока, также экспортируется периодическая статистика в формате JSON. Пример:

{
       "iface": {
               "name": "eth1",
               "speed": 1000,
               "ip": "10.0.0.2"
       },
       "probe": {
               "ip": "10.0.0.1"
       },
       "time" : 1568866123.456,
       "bytes": 3582434,
       "packets": 32141,
       "avg": {
               "bps": 1096415640,
               "pps": 207410
       },
         "drops" : {
               "export_queue_too_long": 0,
               "too_many_flows": 0
       },
         "timeout": {
               "lifetime": 120,
               "idle": 10
       },
         "zmq": {
               "num_flow_exports": 2431,
               "num_exporters": 1
       }
}

Где:

  • iface сообщает информацию об интерфейсе захвата

  • зонд сообщает информацию о машине (например, IP-адрес управления)

  • время это временная метка текущей эпохи

  • байты это количество захваченных байтов

  • пакеты количество перехваченных пакетов

  • среднее — средняя скорость захвата в бит/с и pps

  • капли сообщает информацию о падении потока в зависимости от причины

  • тайм-аут сообщает информацию о настройках экспорта потока

  • zmq сообщает статистику о потоках, экспортированных по каналу ZMQ
