Фильтрация пакетов

Фильтрация L2/L3/L4

Фильтры типа BPF можно указать, используя подмножество синтаксиса BPF. Поскольку сложность выражения фильтра влияет на:

  • скорость захвата пакетов при использовании для фильтрации входящего трафика

  • сложность и скорость индекса при использовании для фильтрации сбрасываемого трафика

Ниже мы определяем набор ограничений и разрешенных выражений.

Выражение состоит из одного или нескольких примитивов. Сложные выражения фильтра создаются с использованием И, ИЛИ и НЕТ операторы.

Разрешенные квалификаторы для примитивных выражений:

Протокол: эфир, ИП, IP6, tcp, udp, sctp Направление: источник, летнее время, источник или летнее время, исходный код и летнее время Тип: хозяин, сеть, порт

Другие разрешенные примитивы: vlan

Примеры примитивных фильтров:

ether host 00:11:22:33:44:55
ether src host 00:11:22:33:44:55

ip host 192.168.0.1
ip dst host 192.168.0.1

ip6 host 2001:0db8:85a3:0042:0000:8a2e:0370:7334
ip6 src host 2001:0db8:85a3:0042:0000:8a2e:0370:7334

ip net 192.168.1.0/24
ip src net 192.168.1

port 80
udp port 9000
tcp src port 80
vlan 32

Примеры сложных фильтров захвата:

ip host 192.168.1.1 and 192.168.1.2
ip src 192.168.1.1 and dst 192.168.1.2

ip host 192.168.1.1 and tcp port (80 or 443)
(ip host 192.168.1.1 or 192.168.1.2) and (port 80 or 443)

Фильтры захвата

Обратите внимание, что при использовании типа BPF существуют дополнительные ограничения. фильтры для захвата пакетов:

  • невозможно использовать НЕТ оператор.

  • можно использовать до двух уровней вложенности с круглыми скобками

  • на одном уровне вложенности и внутри одной скобки невозможно смешивать разные операторы

Экстракционные фильтры

Ниже вы найдете несколько приемов, которые помогут ускорить извлечение пакетов, когда использование фильтров типа BPF для получения трафика:

  • Используйте /32 и /24 IPv4.

  • Используйте только /128 IPv6

  • Используйте точные порты (без диапазона портов)

  • Не используйте идентификаторы протоколов

L7 Фильтрация

Также предусмотрена фильтрация трафика на основе протокола приложения. возможно как во время захвата, так и во время извлечения, используя о поддержке PF_RING FT, которая, в свою очередь, использует библиотеку nDPI.

Примечание

n2disk 10/40/100G уже включает лицензию PF_RING FT. n2disk 1/5G вместо этого для включения индексации/фильтрации Layer 7 требуется лицензия PF_RING FT.

Фильтры захвата

Чтобы включить фильтрацию L7 во время захвата, все, что вам нужно сделать: заключается в предоставлении файла конфигурации с PF_RING правилами фильтрации FT, чтобы n2disk с помощью –l7-filter-conf <файл> вариант. Этот файл содержит протоколы, которые вы хотите отбросить (действие «отбросить») или сбросить (действие «переслать»). Поскольку обнаружение протокола обеспечивается nDPI вы можете указать все имена протоколов приложений, поддерживаемые nDPI библиотека. Адаптивная (для каждого приложения) нарезка пакетов также поддерживается путем настройки протоколы, для которых пакеты должны быть нарезаны с удалением полезной нагрузки (действие «нарезка»).

Пример:

[global]
default = forward

[filter]
YouTube = discard
Netflix = discard
SSH = slice

Обратите внимание, что сброшенный PCAP может все еще содержать пакет для связь, соответствующая отброшенным протоколам. Это ожидаемо и зависит от того, как работает глубокая проверка пакетов: она должна проверять несколько пакетов в начале каждого сеанса связи, прежде чем они будут способен с разумной степенью уверенности идентифицировать протокол L7. По этой причине начальные пакеты любой связи сбрасываются. на диск, пока не будет обнаружен протокол L7. Это предназначено для использования чтобы сэкономить место на диске для нежелательного трафика, тем самым имея небольшой процент нежелательного трафика на диск обычно допустимо.

Пример с «по умолчанию = отбросить» и «MDNS = переслать»:

Пакеты в сети:

Unknown              packets: 567           bytes: 64030         flows: 4
DNS                  packets: 8             bytes: 864           flows: 2
MDNS                 packets: 6             bytes: 480           flows: 2
SSDP                 packets: 8             bytes: 1728          flows: 2
SSH                  packets: 1755          bytes: 702890        flows: 4
Dropbox              packets: 3             bytes: 639           flows: 1

Сброшенные пакеты:

Unknown              packets: 30            bytes: 4549          flows: 4
DNS                  packets: 8             bytes: 864           flows: 2
MDNS                 packets: 6             bytes: 480           flows: 2
SSH                  packets: 32            bytes: 7490          flows: 4

Пожалуйста, проверьте PF_RING футов документацию для получения дополнительной информации о PF_RING FT и расширенных конфигурациях.

Экстракционные фильтры

Синтаксис BPF для фильтров извлечения содержит дополнительные примитивы. которые могут использовать расширения индекса для сопоставления трафика на основе дополнительных атрибутов

  • Layer 7 протокол приложения: l7proto <протокол> доступен при использовании --extended-index|-E 2 вариант (пожалуйста, проверьте справку или Использование раздел с дополнительными опциями).

  • Идентификатор устройства и интерфейса: устройство <ID>, интерфейс <ID> доступны, когда информация об устройстве и порте добавляется в пакет в виде метаданных внешними брокерами пакетов. Arista Устройства Metawatch экспортируют трейлеры Metamako, кодирующие идентификатор устройства и идентификатор порта. Их можно использовать n2disk, добавив –extended-index 4 и –hw-timestamp метачасы в конфигурацию.

  • Туннелирование: внутренний, внешний доступны при включении —index-tunnel-content|-G

Пример использования индексации и извлечения Layer 7:

n2disk -i eth1 -o /storage -b 1024 -p 512 --disk-limit 50% -I -E 2 -A /storage -Z -w 0 -r 1 -z 1

На этом этапе вы можете фильтровать трафик на основе приложения. протокол с использованием фильтров типа BPF в npcapextract инструмент, как описано в Утилиты / npcapextract раздел. l7прото примитивный для этого следует использовать, как в примере фильтра ниже:

ip host 192.168.1.1 and l7proto SSH

Поскольку обнаружение протокола обеспечивается nDPI также для индекса можно указать все имена протоколов приложений поддерживается библиотекой nDPI. Ниже вы найдете полный пример использования npcapextract чтобы получить SSH трафик, генерируемый 192.168.1.1.

npcapextract -t /storage -b "2020-09-16 12:05:32" -e "2020-09-16 12:10:32" -o output.pcap -f "ip host 192.168.1.1 and l7proto SSH"
