Поддержка аппаратного обхода

При запуске программного обеспечения в режиме прозрачного моста nScrub поддерживает аппаратный обход. адаптеры, которые можно использовать для:

  • перенаправление трафика, когда система находится на обслуживании

  • реализация механизма автоматического переключения при сбое программного обеспечения

В режиме обхода все пакеты, полученные с одного порта, передаются на соседний порт. Этот режим можно включить как вручную (обычно используется, когда система находится на обслуживании), так и вручную. или используя механизм heartbeat для автоматического включения обхода, когда программное обеспечение почему-то нет в живых.

nScrub в настоящее время поддерживает обходные адаптеры Silicom. Никакой специальной настройки не требуется помимо установки драйвера Silicom, поскольку адаптер обнаруживается автоматически и heartbeat механизм включается автоматически.

Режим обхода можно включить вручную в любое время с помощью кнопки включение обхода команда в nscrub-cli. Таким же образом его можно отключить с помощью отключить обход (это автоматически включает механизм heartbeat). Фактический статус байпаса можно проверить используя статус командовать nscrub-cli.

Включение, отключение или проверка состояния обхода также возможны через REST API.

Пожалуйста, обратитесь к следующему разделу для настройки адаптера.

Silicom Адаптеры

Чтобы включить поддержку обхода на адаптерах Silicom, bp_ctl водитель (при условии по Silicom) необходимо скомпилировать и установить:

tar xvzf bp_ctl-xxx.tar.gz
cd bp_ctl-xxx
make && make install

Драйвер следует загрузить с помощью установленного инструмента (убедитесь, что это сохраняется при перезагрузке системы):

bpctl_start

Обратите внимание, что после загрузки драйвера обхода требуется перезагрузка nScrub. чтобы убедиться, что поддержка обхода обнаружена и успешно включена.
