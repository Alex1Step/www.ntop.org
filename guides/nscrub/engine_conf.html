Конфигурация двигателя

Движок можно настроить с помощью инструмента REST API или CLI nscrub-cli с поддержкой автозаполнения (обратите внимание, что в качестве бэкэнда также используется REST API). Чтобы использовать API вместо HTTPs, вам необходимо создать сертификат SSL:

openssl req -new -x509 -sha256 -extensions v3_ca -nodes -days 365 -out cert.pem
cat privkey.pem cert.pem > /usr/share/nscrub/ssl/ssl-cert.pem
rm -f privkey.pem cert.em

Чтобы запустить nScrub с помощью systemd, файл конфигурации должен быть помещен в /etc/nscrub/nscrub.conf. Пример:

touch /etc/nscrub/nscrub.start
cat /etc/nscrub/nscrub.conf
--wan-interface=zc:eth1
--lan-interface=zc:eth2
--log-path=/var/tmp/nscrub.log
--pid-path=/var/tmp/nscrub.pid
--daemon

Примечание. Если вы используете сценарий init.d в старых дистрибутивах Linux, необходимо создать /etc/nscrub/nscrub.start, чтобы включить службу.

Если ваша система использует systemd, приложение можно запустить с помощью:

systemctl start nscrub

В противном случае используйте сценарий init.d:

/etc/init.d/nscrub start

В файле конфигурации можно указать следующие параметры. Значения по умолчанию см. в справке приложения (опция –help|-h).

Основные настройки

[–wan-interface|-i] <устройство> Имя первого устройства (Интернет)

[–lan-interface|-o] <устройство> Имя второго устройства (локальная сеть)

[–асимметричный|-A] Асимметричная маршрутизация (только трафик локальной сети)

[–sw-распределение|-w] Использование SW Distribution + RSS TX Queues

[–активное-ожидание|-a] Активное ожидание пакета

Соединение с хостом/маршрутизация

[–connect-хост|-X] Пусть хост будет доступен на интерфейсах wan/lan.

[–маршрутизация|-x] Действовать как маршрутизатор (обычно используется с перенаправлением трафика BGP)

CPU Родство

[-balancer-affinity|-r] <id>:<id> Привязать потоки распределения пакетов к идентификаторам ядра (только -w)

[–thread-affinity|-g] <id>[:<id>[..]] Привязка потоков обработки к идентификатору ядра

[–time-source-affinity|-T] <id> Привязать поток источника времени к идентификатору ядра

Мониторинг трафика

[–aux-queues|-O] <число> Включить <число> наборов вспомогательных выходных очередей для выборки пакетов (анализ/сброс трафика)

[–event-script-dir|-Q] <каталог> Каталог сценариев событий

Расширенные настройки

[–cluster-id|-c] <id> Идентификатор кластера ZC

[–ht-idle-timeout|-I] <usec> Тайм-аут простоя потока

[–dyn-white-list-idle-timeout|-e] <usec> Тайм-аут простоя автоматического белого списка

[–gre-декапсуляция|-E] Декапсулировать трафик GRE

[–redis|-D] <хост[:порт][@db-id]> Redis Хост БД[:порт][@идентификатор базы данных]

REST Сервер

[–http-адрес|-G] <адрес> IP-адрес для привязки сокета сервера REST

[–http-порт|-H] <порт> HTTP порт для REST сервера

[–https-порт|-s] <порт> HTTPs порт для REST сервера

[–docs-root|-R] <каталог> Корневой каталог документов

Ведение журнала

[–log-path|-l] <путь> Путь к файлу журнала

[–stats-log-path|-y] <путь> Путь к файлу журнала статистики

[-debug-level|-t] <уровень> Уровень трассировки

Услуга

[–демон|-d] Запустить как демон

[-pid-path|-p] <путь> Путь к файлу PID

[–user] <пользователь системы> Запуск от указанного пользователя

Версия и лицензия

[–версия|-V] Версия для печати

[–идентификатор системы|-Y] Распечатать идентификатор системы

[–check-license|-C] Проверяет, действительна ли лицензия

[–проверка-обслуживание|-M] Проверяет срок действия технического обслуживания
