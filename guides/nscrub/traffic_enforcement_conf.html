Конфигурация контроля трафика

После того как приложение запущено и работает, пришло время настроить его для включения уменьшения трафика. Это означает, что нам нужно создать виртуальные скрубберы (объекты, содержащие политики защиты на основе цели), каждый виртуальный скруббер проверяет трафик, соответствующий одной или нескольким целевым подсетям. Каждый виртуальный скруббер, идентифицируемый целевым идентификатором, имеет свои собственные профили контроля трафика, которые можно настроить/изменить/проверить во время выполнения с помощью API.

В этом разделе представлены некоторые базовые знания по настройке движка с помощью REST API. Полные характеристики API см. в документации API.

Обратите внимание: хотя в этом разделе рассматривается настройка с использованием REST API, для упрощения настройки также доступно несколько инструментов командной строки (см. Приложение A), в том числе:

  • nscrub-cli, реализуя консоль с автодополнением со всеми функциями, реализованными в REST API.

  • nscrub-добавить, мастер-инструмент для создания новых жертв с базовой конфигурацией (обычно требуются дополнительные настройки с помощью nscrub-cli или API).

  • nscrub-экспорт— инструмент для сброса текущей конфигурации конкретной жертвы.

Учетных данных по умолчанию нет: пароль должен быть явно настроен для администратор пользователь до REST API/CLI примет аутентификацию. Видеть Установка пароля REST API ниже.

Управление пользователями

Установка пароля REST API

Пароли хранятся в Redis в виде соленых хешей SHA-256 под ключом. nscrub.user.<username>.password, в формате sha256:<salt>:<hash>, где <salt> представляет собой случайную 16-байтовую шестнадцатеричную строку и <hash> это дайджест SHA-256 <salt> объединено с паролем.

Чтобы установить пароль для администратор пользователь, выполните команду ниже, заменив Новый пароль с желаемый пароль (эту же команду можно использовать для любого другого имени пользователя, заменив администратор в клавиша Redis):

SALT=$(openssl rand -hex 16); redis-cli SET nscrub.user.admin.password "sha256:${SALT}:$(printf '%s%s' "$SALT" 'newpassword' | openssl dgst -sha256 -r | awk '{print $1}')"

Если Redis прослушивает хост/порт, отличный от заданного по умолчанию, укажите сведения о соединении с помощью -h хост и -p порт (или -n идентификатор базы данных для базы данных не по умолчанию).

Изменение пароля

После установки исходного пароля администратора учетными данными также можно управлять (пока работает nScrub) с помощью REST API или CLI.

используйте nscrub-cli:

nscrub-cli> usermod <username> <group> <new_password>

Пример изменения пароля администратора:

nscrub-cli> usermod admin administrator newpassword

Использование REST API напрямую:

curl -u admin:<password> "https://localhost:4443/users?action=update&username=admin&group=administrator&password=newpassword"

Добавление и удаление пользователей

используйте nscrub-cli:

nscrub-cli> useradd <username> <group> <password>    # add a new user
nscrub-cli> userdel <username>                       # remove a user
nscrub-cli> users                                    # list all users

Используя REST API:

curl -u admin:<password> "https://localhost:4443/users?action=add&username=john&group=administrator&password=secret"
curl -u admin:<password> "https://localhost:4443/users?action=del&username=john"
curl -u admin:<password> "https://localhost:4443/users?action=list"

Сброс пароля (экстренный)

Если вы потеряли пароль администратора, установите новый непосредственно в Redis, используя ту же команду, что и на рис. Установка пароля REST API выше (перезапуск не требуется). Пароли, хешированные более старыми nScrub версии (простой несоленый хэш MD5) по-прежнему принимаются для обратной совместимости и автоматически обновляется до соленого формата SHA-256 при следующем успешном входе пользователя в систему.

Логика контроля дорожного движения

Понимание того, как nScrub обрабатывает и обеспечивает соблюдение политик трафика, необходимо для правильной настройки. В этом разделе объясняется основной механизм контроля трафика и взаимодействие профилей для обеспечения Защита от DDoS при разрешении легитимного трафика.

Профильная проверка трафика

Каждый виртуальный скруббер (жертва) имеет четыре профиля, которые определяют политику контроля трафика:

  • профиль по умолчанию: Применяется к трафику с IP-адресов, которых нет ни в одном списке (неизвестные источники).

  • БЕЛЫЙ профиль: применяется к IP-адресам из белого списка (проверенные законные источники).

  • ЧЕРНЫЙ профиль: применяется к IP-адресам, занесенным в черный список (известные злоумышленники).

  • СЕРЫЙ профиль: Применяется к IP-адресам, требующим особого обращения.

Поток трафика между WAN и LAN (проверка входящего трафика)

Сначала проверяется трафик, поступающий от WAN-интерфейса и предназначенный для защищенных подсетей (целей/жертв). против глобального списка злоумышленников на основе IP-адреса источника. Если там нет конкретного совпадения (или цель игнорирует глобальный список), она проверяется по списку целевых злоумышленников, всегда на основе по исходному IP-адресу и соответствующему целевому профилю:

  1. Неизвестные источники (профиль DEFAULT):

    • Трафик от источников, которых нет ни в одном списке (БЕЛЫЙ, ЧЕРНЫЙ или СЕРЫЙ), оценивается профилем DEFAULT.

    • Обычно настраивается с политикой «отбрасывания по умолчанию», поскольку трафик должен проходить только после проверки.

    • Профиль DEFAULT содержит проверки достоверности (проверки SYN, проверки DNS, ограничения скорости и т. д.).

    • Когда пакет проходит все проверки и подтверждается как легитимный, исходный IP-адрес автоматически добавлен в БЕЛЫЙ список

    • Последующие пакеты из этого источника будут обрабатываться профилем WHITE.

  2. Источники в белом списке (профиль WHITE):

    • Трафик от источников из БЕЛОГО списка обрабатывается профилем БЕЛЫЙ.

    • Должна быть настроена политика «принимать все», чтобы разрешить свободный поток законного трафика.

    • Источники добавляются в БЕЛЫЙ список либо:

      • Автоматически после успешной проверки с помощью проверок профиля DEFAULT.

      • Вручную через API/CLI

      • Из трафика LAN в WAN (см. ниже)

  3. Источники в черном списке (черный профиль):

    • Трафик от источников в списке BLACK обрабатывается профилем BLACK.

    • Обычно настроен на отбрасывание всего трафика

    • Источники добавляются в ЧЕРНЫЙ список либо:

      • Вручную через API/CLI

      • Автоматически с помощью функций автоматического черного списка, когда источники не проходят проверку или превышают ограничения скорости.

  4. Источники в «сером» списке (профиль GAY):

    • Для трафика из источников из СЕРОГО списка требуются специальные политики.

    • Полезно для применения пользовательских правил к определенным IP-адресам или подсетям.

    • Обычно настраивается с «отбрасыванием» по умолчанию и специальными правилами разрешения для определенных типов трафика.

Поток трафика из локальной сети в глобальную (исходящий трафик)

Трафик из LAN (защищенной сети) в WAN обрабатывается по-разному:

  • Весь трафик LAN-WAN всегда передается без проверки

  • Когда пакет отправляется из локальной сети, IP-адрес назначения автоматически заносится в белый список

  • Это гарантирует обратный трафик (когда пункт назначения из белого списка становится источником в глобальной сети). принимается через БЕЛЫЙ профиль

  • Этот механизм обеспечивает легитимную двустороннюю связь, инициированную из защищенной сети.

Важный: Если обратный трафик не работает должным образом, это обычно указывает на неправильную настройку. это требует отладки (например, неправильная политика профиля WHITE, проблемы с маршрутизацией или проблемы с асимметричной маршрутизацией).

Пример проверки и продвижения трафика

Вот типичный процесс создания нового соединения TCP:

  1. Внешний клиент (1.2.3.4) отправляет SYN-пакет жертве (10.0.0.1)

  2. Источника 1.2.3.4 нет ни в одном списке → применяется профиль DEFAULT.

  3. В профиле DEFAULT включена проверка SYN (например, проверка соответствия RFC).

  4. Если пакет SYN проходит проверку:

    • Пакет пересылается жертве

    • Исходник 1.2.3.4 добавлен в БЕЛЫЙ список.

  5. Последующие пакеты из 1.2.3.4 → Применяется профиль БЕЛЫЙ.

  6. В профиле БЕЛЫЙ есть «принимать все» → пакеты передаются свободно.

  7. По истечении времени простоя (при включенной автоочистке) 1.2.3.4 может быть удален из БЕЛОГО списка.

Рекомендации по настройке

Для правильного соблюдения правил дорожного движения:

  1. БЕЛЫЙ профиль: Установить политику «принять все»

    curl -u admin:admin "https://localhost:4443/profile/all/accept?target_id=VICTIM&profile=white&action=enable"

  2. ЧЕРНЫЙ профиль: установить политику «удалить все»

    curl -u admin:admin "https://localhost:4443/profile/all/drop?target_id=VICTIM&profile=black&action=enable"

  3. профиль по умолчанию: Настройка с проверками проверки и «отбрасыванием по умолчанию».

    curl -u admin:admin "https://localhost:4443/profile/default?target_id=VICTIM&profile=default&action=update&value=drop"
curl -u admin:admin "https://localhost:4443/profile/tcp/syn/check_method?target_id=VICTIM&profile=default&action=update&value=rfc"

  4. Динамическое управление списком: Включить автоматическую очистку для автоматического удаления неактивных IP-адресов из белого списка.

    curl -u admin:admin "https://localhost:4443/attackers/dynamic/autopurging?target_id=VICTIM&action=enable"
curl -u admin:admin "https://localhost:4443/attackers/dynamic/expiration?target_id=VICTIM&action=update&value=3600"

Пожалуйста, проверьте Пошаговое руководство для примера полной (базовой) конфигурации.

Определение жертв

Жертвы можно динамически добавлять, удалять и настраивать во время выполнения. В этом разделе показаны некоторые примеры наиболее распространенных настроек времени выполнения с упором на REST API. В разделах ниже описаны все доступные вызовы API для настройки движка с использованием как CLI, так и REST API.

Читать активных жертв:

curl -u <user>:<password> "https://<host>:<port>/targets?action=list"

или сделайте то же самое с помощью инструмента командной строки:

nscrub-cli
localhost:8880> list targets

Добавьте новую жертву:

curl -u <user>:<password> "https://<host>:<port>/targets?action=add&target_id=<victim name>&subnet=<subnet (CIDR notation)>"

Каждая жертва привязана к четырем профилям: по умолчанию, черному, белому и серому. Эти профили определяют, как обрабатывается трафик на основе IP-адреса источника. Подробное объяснение того, как работают профили и логика контроля трафика, см. в разделе «Логика контроля трафика» выше.

Примечание

В этом разделе представлены лишь несколько примеров конфигурации жертвы, полные настройки см. в документации API.

Обычной практикой является установка политики «удалить все» для черного профиля:

curl -u <user>:<password> "https://<host>:<port>/profile/all/drop?target_id=<victim name>&profile=black&action=enable"

Также распространенной практикой является установка политики «принять все» для белого профиля:

curl -u <user>:<password> "https://<host>:<port>/profile/all/accept?target_id=<victim name>&profile=white&action=enable"

Серый профиль обычно используется для применения специальных политик к «специальным» IP-адресам. Например, общепринятой практикой является установка политики «по умолчанию» на «отбрасывание», а затем указание более конкретных политик, позволяющих пропускать определенные типы трафика.

curl -u <user>:<password> "https://<host>:<port>/profile/default?target_id=<victim name>&profile=gray&action=update&value=drop"

В профиле по умолчанию используются политики контроля реального трафика для проверки неизвестного трафика. Например, также распространенной практикой является установка политики по умолчанию на удаление:

curl -u <user>:<password> "https://<host>:<port>/profile/default?target_id=<victim name>&profile=default&action=update&value=drop"

Примите ICMP:

curl -u <user>:<password> "https://<host>:<port>/profile/icmp/accept?target_id=<victim name>&profile=default&action=enable"

Падение UDP:

curl -u <user>:<password> "https://<host>:<port>/profile/udp/drop?target_id=<victim name>&profile=default&action=enable"

Примите UDP порт 53 (DNS):

curl -u <user>:<password> "https://<host>:<port>/profile/udp/src/53/accept?target_id=<victim name>&profile=default&action=enable"

Проверьте трафик TCP:

curl -u <user>:<password> "https://<host>:<port>/profile/tcp/syn/check_method?target_id=<victim name>&profile=default&action=update&value=rfc"

Также можно установить ограничитель скорости (в этом примере для каждого источника), чтобы установить порог скорости трафика.

curl -u <user>:<password> "https://<host>:<port>/profile/rate?target_id=<victim name>&profile={black, white, gray, default}[&action=update&value=<pkts/s>]"

Доступно гораздо больше политик, пожалуйста, обратитесь к полной документации API.

Обратите внимание, что все настройки также можно прочитать, опуская параметр действия (и значения).

Чтобы временно отключить проверку трафика, можно перевести систему в состояние обхода, как глобально:

curl -u <user>:<password> "https://<host>:<port>/bypass?[action={enable, disable}]"

или на одну жертву:

curl -u <user>:<password> "https://<host>:<port>/profile/bypass?target_id=<victim name>&profile=default[&action={enable, disable}]"

Глобальные списки злоумышленников

В дополнение к спискам БЕЛЫЙ/ЧЕРНЫЙ/СЕРЫЙ для каждой цели, nScrub поддерживает глобальные списки злоумышленников, общий для всех целей, поэтому черный список (или белый список) не нужно загружать один раз для каждой цели.

  • Глобальный список проверен до поиск профиля для каждой цели, описанный ниже: если соответствующий IP-адрес (источник трафика из глобальной сети в локальную сеть) имеет запись в глобальном списке, этот профиль используется немедленно, а список целей не рассматривается.

  • Если глобального соответствия нет, трафик попадает в обычный поиск по целевому профилю. описано в пункте rest этого раздела.

  • Любая цель может отказаться и использовать только свои собственные списки, полностью игнорируя глобальный список, см. «Игнорировать глобальный список злоумышленников для цели» в разделе «Глобальное управление злоумышленниками».

  • Глобальный список поддерживает только статически управляемые записи (добавленные/загруженные через CLI/REST). Нет глобальный эквивалент автоматически заполняемого динамического списка для каждой цели, поскольку динамическое обнаружение основан на одном целевом трафике.

См. раздел «Глобальное управление злоумышленниками», чтобы узнать, как управлять глобальным списком с помощью CLI/REST.

Настроить метод проверки SYN

Выберите метод, используемый для проверки соединений TCP из источников, не внесенных в белый список:

  • rfc: первый SYN источника отбрасывается, законный клиент повторно передает его в соответствии со спецификацией TCP и попадает в белый список. Это задерживает первое подключение каждого источника на время ожидания повторной передачи SYN клиента (обычно 1 секунда).

  • прокси: nScrub отвечает на SYN с помощью SYN-ACK, содержащего файл cookie SYN, и открывает соединение с сервером только после того, как клиент завершил трехстороннее рукопожатие; трафик соединения затем преобразуется на nScrub. Никаких задержек не добавляется. В асимметричном режиме (только трафик локальной сети) это работает как проверка файлов cookie SYN.

  • отключить: нет проверки SYN (по умолчанию).

Трафик SSL (порт 443 TCP) проверяется с помощью метода RFC, если в качестве метода проверки SYN выбран RFC или прокси, если только другой метод не настроен с помощью настройки метода проверки SYN SSL ниже.

CLI

> target ID profile white|gray|black|default tcp syn check_method [rfc|proxy|disable]

REST

curl -u <user>:<password> https://<host>:<port>/profile/tcp/syn/check_method?target_id=<target id>\&profile={black, white, gray, default}[\&action=update\&value={rfc, proxy, disable}]

Пример:

curl -u admin:admin https://localhost:4443/profile/tcp/syn/check_method?target_id=SCRBR1\&profile=default

Настройте метод проверки SSL SYN.

По умолчанию трафик SSL (порт TCP 443) проверяется методом rfc, когда используется метод проверки SYN. либо RFC, либо прокси-сервер, поскольку методы, основанные на сбросе соединения, могут быть проблемой для некоторых клиентов SSL. Этот параметр переопределяет метод, используемый для порта 443:
