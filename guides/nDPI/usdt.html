USDT-зонды

nDPI поддерживает USDT (Статически определяемая трассировка на уровне пользователя) зонды для динамической трассировки zero-заголовков в производственных средах. Каждый зонд компилируется в одной инструкции NOP и не требует затрат во время выполнения, если не отслеживается активно. Внешние инструменты, такие как bpftrace, perf, и SystemTap может подключаться к этим зондам во время выполнения без перезапуска или перекомпилировать приложение.

Сборка с поддержкой USDT

Установите необходимые заголовки разработки (Linux):

# Debian/Ubuntu
sudo apt-get install systemtap-sdt-dev dwarves

# RHEL/CentOS/Fedora
sudo dnf install systemtap-sdt-devel dwarves

Затем настройте и соберите nDPI с включенной поддержкой USDT:

./autogen.sh
./configure --enable-usdt-probes --enable-debug-build
make

Примечание

На macOS, sys/sdt.h обеспечивается системой. На платформах, где это есть недоступны, зонды компилируются и не оказывают никакого влияния.

Примечание

Чтобы разрешить bpftrace struct ndpi_flow_struct поля по имени без любой --include флаги, встраивайте BTF в двоичные файлы после сборки с помощью pahole -J (из dwarves упаковка). Видеть Доступ к полю структуры ниже. Без BTF скалярные аргументы остаются полностью пригодными для использования.

Доступные зонды

Имя зонда

Аргументы

Описание

flow_classified
arg0: идентификатор главного протокола (u16)
arg1: идентификатор протокола приложения (u16)
arg2: уровень уверенности (enum)
arg3: категория (enum)
arg4: указатель потока (struct ndpi_flow_struct *)

Срабатывает ровно один раз за поток, когда классификация завершена. Охватывает все пути выхода: успешное обнаружение, отказ, максимальное количество пакетов. достигнуто, совпадение nBPF и завершение внедиссектора. Скалярные аргументы (arg0–arg3) поддерживают эффективную фильтрацию внутри предикатов bpftrace; arg4 обеспечивает доступ ко всем оставшимся поля потока, когда требуется более глубокий осмотр.

hostname_set
arg0: строка имени хоста (char *)
arg1: указатель потока (struct ndpi_flow_struct *)

Срабатывает всякий раз, когда имя хоста или SNI извлекается из потока. Охватывает все протоколы, содержащие имя хоста: TLS (SNI), DNS, HTTP (заголовок хоста), QUIC, NetBIOS, DHCP, STUN и другие. Для удобства имя хоста передается непосредственно в виде строки; указатель потока обеспечивает доступ ко всем остальным полям потока.

fragment_ipv4
arg0: указатель на заголовок IPv4 (struct ndpi_iphdr *)

Срабатывает, когда пакет IPv4, обработанный библиотекой, фрагментирован. на уровне IP.

fragment_ipv6
arg0: указатель на заголовок IPv6 (struct ndpi_ipv6hdr *)

Срабатывает, когда пакет IPv6, обработанный библиотекой, фрагментирован. на уровне IP.

Примечания к bpftrace

Доступ к полю структуры

Чтобы разыменовать указатели пользовательского пространства (например, struct ndpi_flow_struct прошло как arg1 в hostname_set зонд) необходимо встроить информацию BTF в общую библиотеку или исполняемый файл. Рекомендуемый подход — запустить pahole -J (из dwarves package) в качестве шага после сборки: он считывает Информация об отладке DWARF уже присутствует в двоичном файле и вставляет .BTF раздел с полной информацией о типе.

# Debian/Ubuntu
sudo apt-get install dwarves

# RHEL/CentOS/Fedora
sudo dnf install dwarves

./configure --enable-usdt-probes --enable-debug-build
make
pahole -J src/lib/libndpi.so
pahole -J example/ndpiReader

Как только .BTF раздел присутствует, bpftrace может разрешить struct ndpi_flow_struct поля по имени — без каких-либо --include флаги — при условии, что в спецификации зонда используется полный двоичный путь. Обратите внимание, что :: сокращение не запускает поиск BTF:

bpftrace -e 'usdt:/path/to/ndpiReader:ndpi:flow_classified {
  $flow = (struct ndpi_flow_struct *)arg4;
  if ($flow->risk != 0) { @risky[arg0] = count(); }
}'

Убедитесь, что раздел присутствует с:

readelf -S example/ndpiReader | grep '\.BTF'

Генерация BTF — известные проблемы и обходные пути

Типы C11 ``_Atomic`` нарушают кодировку Pahole BTF

Входящая в комплект nDPI библиотека CRoaring использует _Atomic квалификаторы, которые компилятор выдает как DW_TAG_atomic_type записи в DWARF. Все выпущено версии pahole (включая 1.31) прерывать кодирование BTF при обнаружении этот тег, даже если --btf_encode_force передается:

Unsupported DW_TAG_atomic_type(0x47): type: 0x153c6
Encountered error while encoding BTF.

Обходной путь, используемый в конвейере CI nDPI, заключается в перестроении с помощью CROARING_ATOMIC_IMPL=1, который выбирает путь неатомарного кода и удаляет оскорбительные записи DWARF:

CFLAGS="-DCROARING_ATOMIC_IMPL=1" ./configure \
    --enable-usdt-probes --enable-debug-build
make

Резервный вариант: сгенерируйте заголовок C с помощью bpftool

Даже при правильном внедрении информации BTF разыменование указателя все равно может потерпеть неудачу с:

stdin:1:65-93: ERROR: Cannot resolve unknown type "struct ndpi_flow_struct"

В этом случае сгенерируйте заголовок C из информации BTF и передайте его в bpftrace с --include:

# Generate a C header containing the full layout of the userspace structures
bpftool btf dump file /path/to/ndpiReader format c > ndpi_types.h

# Pass the header to bpftrace
sudo bpftrace --include ndpi_types.h \
  -e 'usdt:/path/to/ndpiReader:ndpi:flow_classified {
    $flow = (struct ndpi_flow_struct *)arg4;
    if ($flow->risk != 0) { @risky[arg0] = count(); }
  }'

Ограничения размера карты bpftrace

При трассировке длительных или высокопроизводительных захватов карты bpftrace могут заполняться. и выдать команду уровня ядра E2BIG предупреждение:

WARNING: Map full; can't update element.
Additional Info - helper: map_update_elem, retcode: -7

Увеличьте лимит ключей карты с помощью переменной среды (поддерживается всеми последние версии bpftrace):

sudo BPFTRACE_MAX_MAP_KEYS=100000 bpftrace --include ndpi_types.h \
  -e 'usdt:/path/to/ndpiReader:ndpi:hostname_set {
    @top[str(arg0)] = count();
  }'

Более новые сборки bpftrace также принимают config блок в верхней части сценарий:

sudo bpftrace --include ndpi_types.h \
  -e 'config = { max_map_keys = 100000 }
usdt:/path/to/ndpiReader:ndpi:hostname_set {
  @top[str(arg0)] = count();
}'

Предикаты против блоков действий

предикаты bpftrace (/condition/) хорошо подходят для фильтрации скалярных аргументов (arg0–arg3 в flow_classified):

bpftrace -e 'usdt::ndpi:flow_classified /arg0 == 91/ { ... }'

Фильтрация полей структуры с помощью указателя (например, arg4 в flow_classified или arg1 в hostname_set) является не поддерживается в предикатах.

Используйте if вместо этого оператор внутри блока действий:

bpftrace -e 'usdt:/path/to/ndpiReader:ndpi:hostname_set {
  $flow = (struct ndpi_flow_struct *)arg1;
  if ($flow->detected_protocol_stack[0] == 5) {
    @dns[str(arg0)] = count();
  }
}'

Примеры bpftrace

Примечание

Примеры разыменования указателя пользовательского пространства (arg4 в flow_classified, arg1 в hostname_set) требуют либо .BTF раздел, встроенный в двоичный файл через pahole -J или явный --include ndpi_types.h заголовок (сгенерированный через bpftool btf dump ... format c). Видеть Генерация BTF — известные проблемы и обходные пути выше.

Скалярные примеры (использующие только arg0–arg3 в flow_classified или arg0 в hostname_set, без разыменования структуры) работают без BTF или заголовки и можете использовать :: стенография.

Список всех доступных зондов:

bpftrace -l "usdt:./src/lib/.libs/libndpi.so:ndpi:*"

flow_classified Примеры

Журнал классификации протоколов в реальном времени:

bpftrace -e 'usdt::ndpi:flow_classified {
  printf("master=%d app=%d confidence=%d category=%d\n",
         arg0, arg1, arg2, arg3);
}'

Гистограмма распределения протоколов:

bpftrace -e 'usdt::ndpi:flow_classified {
  @proto_master[arg0] = count();
}'

Разбивка по уровням уверенности:

bpftrace -e 'usdt::ndpi:flow_classified {
  @confidence[arg2] = count();
}'

Распространение по категориям:

bpftrace -e 'usdt::ndpi:flow_classified {
  @category[arg3] = count();
}'

Подсчет неклассифицированных потоков (главный протокол == 0):

bpftrace -e 'usdt::ndpi:flow_classified /arg0 == 0/ {
  @unknown = count();
}'

Скорость классификации потока (потоков/сек):

bpftrace -e 'usdt::ndpi:flow_classified {
  @ = count();
} interval:s:1 { print(@); clear(@); }'

Фильтровать по определенному протоколу (например, TLS = 91):

bpftrace -e 'usdt::ndpi:flow_classified /arg0 == 91/ {
  @tls[arg1] = count();
}'

Потоки, классифицированные в SocialNetwork (категория 6):

bpftrace -e 'usdt::ndpi:flow_classified /arg3 == 6/ {
  @social[arg0, arg1] = count();
}'

Потоки с битовым изображением риска, отличным от zero (требуется BTF или --include):

bpftrace -e 'usdt:/path/to/ndpiReader:ndpi:flow_classified {
  $flow = (struct ndpi_flow_struct *)arg4;
  if ($flow->risk != 0) {
    @risky[arg0] = count();
  }
}'

имя_хоста_set Примеры

Журнал имен хостов в реальном времени:

bpftrace -e 'usdt:/path/to/ndpiReader:ndpi:hostname_set {
  $flow = (struct ndpi_flow_struct *)arg1;
  printf("%s (master=%d app=%d)\n",
         str(arg0),
         $flow->detected_protocol_stack[0],
         $flow->detected_protocol_stack[1]);
}'

Самые популярные имена хостов по количеству потоков:

bpftrace -e 'usdt::ndpi:hostname_set {
  @top[str(arg0)] = count();
}'

Мониторинг определенного домена (например, всех *.google.com трафик):

bpftrace -e 'usdt::ndpi:hostname_set /strcontains(str(arg0), "google.com")/ {
  @google[str(arg0)] = count();
}'

Имена хостов разрешаются только через DNS (DNS = 5):

bpftrace -e 'usdt:/path/to/ndpiReader:ndpi:hostname_set {
  $flow = (struct ndpi_flow_struct *)arg1;
  if ($flow->detected_protocol_stack[0] == 5) {
    @dns[str(arg0)] = count();
  }
}'

TLS Извлечение SNI в реальном времени (TLS = 91):

bpftrace -e 'usdt:/path/to/ndpiReader:ndpi:hostname_set {
  $flow = (struct ndpi_flow_struct *)arg1;
  if ($flow->detected_protocol_stack[0] == 91) {
    printf("TLS SNI: %s\n", str(arg0));
  }
}'

Разбивка протокола имени хоста к приложению:

bpftrace -e 'usdt:/path/to/ndpiReader:ndpi:hostname_set {
  $flow = (struct ndpi_flow_struct *)arg1;
  @host_app[str(arg0), $flow->detected_protocol_stack[1]] = count();
}'

Скорость разрешения имени хоста (имена хостов/сек):

bpftrace -e 'usdt::ndpi:hostname_set {
  @ = count();
} interval:s:1 { print(@); clear(@); }'

Обнаружение потенциальной активности DGA (подсчет уникальных имен хостов DNS с течением времени):

bpftrace -e 'usdt:/path/to/ndpiReader:ndpi:hostname_set {
  $flow = (struct ndpi_flow_struct *)arg1;
  if ($flow->detected_protocol_stack[0] == 5) {
    @unique_dns = count();
  }
} interval:s:10 {
  printf("Unique DNS hostnames in last 10s: %d\n", @unique_dns);
  clear(@unique_dns);
}'

пример производительности

Запись попаданий зонда с perf:

perf probe -x ./src/lib/.libs/libndpi.so sdt_ndpi:flow_classified
perf record -e sdt_ndpi:flow_classified -p $(pidof ndpiReader) -- sleep 10
perf report

Накладные расходы

  • Когда не отслеживается: zero накладные расходы. Каждый зонд компилируется в одну инструкцию NOP.

  • При активном отслеживании: примерно 2–5 микросекунд на одно попадание зонда, в зависимости от инструмент трассировки и сложность прилагаемого сценария.

  • flow_classified и hostname_set срабатывать не более одного раза за поток (не за пакет), поэтому их накладные расходы остаются незначительными даже при активной трассировке при больших объемах трафика. fragment_ipv4 и fragment_ipv6 срабатывать один раз за фрагментированный пакет.
