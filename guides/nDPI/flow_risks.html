nDPI Риски потоков

nDPI предназначен не только для обнаружения протоколов приложений в потоках трафика, но и для оценки потенциальных рисков безопасности, связанных с трафиком. На языке nDPI это называется «риск потока». Потоки могут иметь несколько обнаруженных рисков, поэтому nDPI сообщает о них в виде растрового изображения. Каждый обнаруженный риск соответствует биту в битовой карте риска потока. You can read more about ndpi_risk_enum для списка всех числовых рисков, поддерживаемых в настоящее время.

Ниже вы можете найти описание каждого риска потока, чтобы вы могли легко понять, когда риск срабатывает и его значение. Риски потока перечислены в числовом порядке, как они определены в ndpi_risk_enum.

NDPI_URL_POSSIBLE_XSS

Только HTTP: этот риск указывает на возможную XSS (перекрестный скриптинг) атака.

NDPI_URL_POSSIBLE_SQL_INJECTION

Только HTTP: этот риск указывает на возможную .

NDPI_URL_POSSIBLE_RCE_INJECTION

.

NDPI_BINARY_APPLICATION_TRANSFER

Только HTTP: этот риск указывает на то, что загружается/выгружается двоичное приложение. Обнаруженные приложения включают двоичные файлы Windows, исполняемые файлы Linux, сценарии Unix и приложения Android.

NDPI_KNOWN_PROTOCOL_ON_NON_STANDARD_PORT

Этот риск указывает на известный протокол, используемый на нестандартном порту. В примере HTTP предполагается использовать TCP/80, и в случае его обнаружения на TCP/1234 этот риск обнаруживается.

NDPI_TLS_САМОподписанный_сертификат

Только TLS/QUIC: этот риск срабатывает, когда используется.

NDPI_TLS_OBSOLETE_VERSION

Риск возникает, когда версия TLS старше 1.1.

NDPI_TLS_WEAK_CIPHER

Риск возникает при использовании небезопасного шифра TLS. Видеть эта страница для списка небезопасных шифров.

NDPI_TLS_CERTIFICATE_EXPIRED

Риск возникает, когда срок действия сертификата TLS истек, т. е. текущая дата выходит за рамки сроков действия сертификата.

NDPI_TLS_CERTIFICATE_MISMATCH

Риск возникает, когда сертификат TLS не соответствует имени хоста, к которому мы обращаемся. Пример, который вы делаете http://www.aaa.com и возвращенный сертификат TLS предназначен для www.bbb.com.

NDPI_HTTP_SUSPICIOUS_USER_AGENT

Только HTTP: этот риск срабатывает всякий раз, когда пользовательский агент содержит подозрительные символы или его формат подозрительный. Пример: <?php что-то ?> — типичный подозрительный пользовательский агент.

NDPI_NUMERIC_IP_HOST

Этот риск возникает всякий раз, когда соединение HTTP/TLS/QUIC использует буквальный адрес IPv4 или IPv6 в качестве имени сервера (TLS/QUIC; пример: SNI=1.2.3.4) или в качестве имени хоста (HTTP; пример: http://1.2.3.4.).

NDPI_HTTP_SUSPICIOUS_URL

Только HTTP: этот риск срабатывает всякий раз, когда URL-адрес, к которому осуществляется доступ, является подозрительным. Пример: http://127.0.0.1/msadc/..%255c../..%255c../..%255c../winnt/system32/cmd.exe.

NDPI_HTTP_SUSPICIOUS_HEADER

Только HTTP: этот риск возникает всякий раз, когда заголовок HTTP содержит подозрительные записи, такие как Uuid, TLS_version, Osname, которые неожиданны в заголовке HTTP.

NDPI_TLS_NOT_CARRYING_HTTPS

Только TLS: этот риск указывает на то, что этот поток TLS не будет использоваться для транспортировки контента HTTP. Примеры VPN используют TLS для шифрования данных, а не для передачи HTTP. Это полезно для выявления подобных случаев.

NDPI_SUSPICIOUS_DGA_DOMAIN

А ДГА используется для создания доменных имен, часто используемых вредоносными программами. Этот риск указывает на то, что это доменное имя может (но не на 100 %) быть DGA, поскольку его имя является подозрительным.

NDPI_MALFORMED_PACKET

Этот риск возникает, когда пакет (например, пакет DNS) имеет неожиданный формат. Это может указывать на ошибку протокола или, что чаще всего, на попытку поставить под угрозу действительный протокол для передачи данных другого типа.

NDPI_SSH_OBSOLETE_CLIENT_VERSION_OR_CIPHER

Этот риск возникает всякий раз, когда клиент SSH использует устаревшую версию протокола SSH или небезопасные шифры.

NDPI_SSH_OBSOLETE_SERVER_VERSION_OR_CIPHER

Этот риск возникает всякий раз, когда сервер SSH использует устаревшую версию протокола SSH или небезопасные шифры.

NDPI_SMB_INSECURE_VERSION

Этот риск указывает на то, что СМБ используемая версия небезопасна (т. е. v1).

NDPI_MISMATCHING_PROTOCOL_WITH_IP

Этот риск указывает на то, что протокол nDPI, обнаруженный для этого потока (например, Facebook), не преобразуется в IP-адрес сервера числового потока, который соответствует известным IP-адресам для такого протокола (в приведенном выше примере IP-адрес не принадлежит Facebook/Meta).

NDPI_UNSAFE_PROTOCOL

Этот риск указывает на то, что используемый протокол небезопасен и что следует использовать безопасный протокол (например, Telnet или SSH).

NDPI_DNS_SUSPICIOUS_TRAFFIC

Этот риск возвращается, когда трафик DNS возвращает неожиданный/устаревший тип записи или когда обнаружен подозрительный запрос с очень длинным именем хоста.

NDPI_TLS_MISSING_SNI

TLS необходимо нести СНИ удаленного сервера, к которому мы обращаемся. К сожалению, SNI не является обязательным в TLS, поэтому его можно опустить. В данном случае этот риск срабатывает, поскольку это нестандартная ситуация, указывающая на потенциальную проблему безопасности или использование протокола TLS для других целей (или ошибку протокола).

NDPI_HTTP_SUSPICIOUS_CONTENT

Только HTTP: о риске сообщается, когда HTTP передает контент в ожидаемом формате. Пример: заголовок HTTP указывает, что контекст — text/html, но реальный контент не читается (т. е. он может передавать двоичные данные). В общем, это попытка использовать действительный тип MIME для переноса данных, не соответствующих этому типу.

NDPI_RISKY_ASN

Это заполнитель для трафика, которым обмениваются АСН которые считаются рискованными. nDPI не заполняет этот риск, который вместо этого должен быть заполнен приложениями, расположенными поверх nDPI (например, ntopng).

NDPI_RISKY_DOMAIN

Это заполнитель для трафика, которым обмениваются доменные имена, которые считаются рискованными. nDPI не заполняет этот риск, который вместо этого должен быть заполнен приложениями, расположенными поверх nDPI (например, ntopng).

NDPI_MALICIOUS_FINGERPRINT

Этот риск указывает на то, что отпечаток соединения TLS считается подозрительным. nDPI не заполняет этот риск, который вместо этого должен быть заполнен приложениями, расположенными поверх nDPI (например, ntopng).

NDPI_MALICIOUS_SHA1_CERTIFICATE

TLS сертификаты однозначно идентифицируются с помощью SHA1 хеш-значение. Если такой хеш обнаружен в черном списке, можно использовать этот риск. Что касается других рисков, это заполнитель, поскольку nDPI не заполняет этот риск, который вместо этого должен быть заполнен приложениями, расположенными поверх nDPI (например, ntopng).

NDPI_DESKTOP_OR_FILE_SHARING_SESSION

Этот риск устанавливается, когда поток содержит сеансы рабочего стола или обмена файлами (например, TeamViewer или AnyDesk, и это только два).

NDPI_TLS_UNCOMMON_ALPN

Этот риск возникает, когда АЛПН (это указывает на протокол, передаваемый в этот поток TLS, например HTTP/1.1) является необычным по отношению к списку ожидаемых значений.

NDPI_TLS_CERT_VALIDITY_TOO_LONG

С 09.01.2020 срок действия сертификатов TLS ограничен 13 месяцев. Этот риск возникает для сертификатов, не соответствующих этой директиве.

NDPI_TLS_SUSPICIOUS_EXTENSION

Этот риск возникает, когда доменное имя (расширение SNI) невозможно распечатать, и, следовательно, это проблема. В TLS расширения могут динамически указываться клиентом в пакете приветствия.

NDPI_TLS_FATAL_ALERT

Этот риск срабатывает, когда в потоке TLS обнаруживается фатальное предупреждение TLS. Видеть эта страница для получения подробной информации.

NDPI_SUSPICIOUS_ЭНТРОПИЯ

Этот риск используется для обнаружения подозрительных данных, передаваемых в пакетах ICMP, чья энтропия (используемая для измерения распределения данных и, следовательно, для косвенного определения типа передаваемых данных) является подозрительной и, таким образом, может указывать на утечку данных. Подозрительные значения указывают на случайную энтропию или энтропию, аналогичную зашифрованному трафику. В последнем случае это может быть признаком подозрительной кражи данных.

NDPI_CLEAR_TEXT_CREDENTIALS

Протоколы открытого текста не являются плохими по своей сути, но их следует избегать, если они содержат учетные данные, поскольку они могут быть перехвачены злонамеренными пользователями. Этот риск возникает всякий раз, когда протоколы открытого текста (например, FTP, HTTP, IMAP…) содержат учетные данные в открытом виде (читай, что nDPI не вызывает этот риск для соединений HTTP, которые не несут учетные данные).

NDPI_DNS_LARGE_PACKET

DNS пакеты старше UDP должны быть ограничены 512 байтами. Пакеты DNS, превышающие этот порог, указывают на потенциальную угрозу безопасности (например, использование DNS для передачи данных) или неправильную конфигурацию.

NDPI_DNS_ФРАГМЕНТИРОВАННЫЙ

UDP DNS пакеты не могут быть фрагментированы. Если это так, это указывает на потенциальную угрозу безопасности (например, использование DNS для переноса данных) или неверную конфигурацию.

NDPI_INVALID_CHARACTERS

Риск устанавливается всякий раз, когда разделенный протокол содержит символы, недопустимые в этом поле протокола. Например, имя хоста DNS должно содержать только подмножество всех печатных символов, иначе будет установлен этот риск. Кроме того, некоторые поля протокола TLS также проверяются на наличие печатных символов.

NDPI_POSSIBLE_EXPLOIT

Риск устанавливается всякий раз, когда возможна попытка использования эксплойта (например. Log4J/Log4Shell) обнаружен.

NDPI_TLS_CERTIFICATE_ABOUT_TO_EXPIRE

Риск устанавливается всякий раз, когда срок действия сертификата TLS приближается к дате истечения срока действия.

NDPI_PUNYCODE_IDN

Риск возникает всякий раз, когда доменное имя указывается в формате IDN, поскольку они иногда используются в Атаки на омографы IDN.

NDPI_ERROR_CODE_DETECTED

Риск устанавливается всякий раз, когда в базовом протоколе обнаруживается код ошибки (например, HTTP и DNS).

NDPI_HTTP_CRAWLER_BOT

Риск устанавливается всякий раз, когда обнаруживается сканер/бот/robot.

NDPI_ANONYMOUS_SUBSCRIBER

Риск возникает всякий раз, когда (исходный) IP-адрес анонимизирован и его нельзя использовать для идентификации подписчика. Пример: поток генерируется выходным узлом iCloud-private-relay.

NDPI_UNIDIRECTIONAL_TRAFFIC

Риск устанавливается всякий раз, когда поток имеет однонаправленный трафик (обычно нет трафика от сервера к клиенту). ЭТО риск не срабатывает для направлений многоадресной/широковещательной рассылки.

NDPI_HTTP_OBSOLETE_SERVER

Этот риск возникает всякий раз, когда сервер HTTP использует устаревшую версию сервера HTTP.

NDPI_PERIODIC_FLOW

Этот риск возникает всякий раз, когда поток наблюдается с определенной периодической скоростью (например, каждые 10 секунд).

NDPI_MINOR_ISSUES

Обнаружены незначительные проблемы с пакетами/потоками (например, трафик DNS с TTL zero).

NDPI_TCP_ISSUES

Соответствующие проблемы с подключением TCP, такие как отказ в соединении, сканирование или попытка проверки.

NDPI_UNRESOLVED_HOSTNAME

Риск устанавливается при разговоре (TLS, QUIC, HTTP) с символическим именем хоста, ранее не наблюдавшимся при разрешении DNS. Если разрешение не было соблюдено так, как оно было выполнено до запуска nDPI, это может указывать на то, что было установлено соединение с фальшивыми хостами.

NDPI_TLS_ALPN_SNI_MISMATCH

Недопустимое несоответствие TLS ALPN/SNI. Например, ALPN объявляет поток как h2 (HTTP/2.0), но SNI не сообщается.

NDPI_MALWARE_CONTACTED

Клиент связался с хостом сервера, помеченным как вредоносное ПО.

NDPI_BINARY_DATA_TRANSFER

Только HTTP: этот риск указывает на то, что приложение передает двоичный файл/данные (попытка).

NDPI_PROBING_ATTEMPT

Соединение без обмена данными, похожее на попытку зондирования.

NDPI_OBFUSCATED_TRAFFIC

Этот риск возникает, когда соединение, вероятно, использует какой-либо метод запутывания, чтобы попытаться «выглядеть» как что-то другое, скрывая свою истинную природу.

NDPI_SLOW_DOS

Этот риск возникает, когда соединение TCP может быть подвержено медленным DoS-атакам.

NDPI_NON_PQC

Этот риск возникает, когда зашифрованный поток (например, TLS, QUIC, SSH, IPSEC) не использует алгоритмы постквантовой криптографии.

NDPI_AI_INFERENCE_TRAFFIC

Этот риск возникает, когда трафик TLS/HTTP может использоваться для доступа к локальному серверу LLM на основе приложений с ac vLLM или llama.cpp.

NDPI_NON_PQC_FLOW

Для TLS этот риск срабатывает только тогда, когда за наблюдаемым ClientHello следует TLS 1.3 ServerHello, который явно согласовывает группу непост-квантового обмена ключами. Он не устанавливается из объявления ClientHello, трассировки только для сервера или только из HelloRetryRequest. Стандартизированные гибридные группы ML-КЕМ из RFC 10024 рассматриваются как постквантовые. Потоки, в которых рукопожатие является неполным, возобновляется только с помощью PSK или иным образом не раскрывает согласованный общий доступ к ключу, остаются неклассифицированными.
