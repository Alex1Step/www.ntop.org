Поиск неисправностей

В этом разделе представлены решения распространенных проблем, возникающих при развертывании и эксплуатации nEdge Lite.

Проблемы при запуске

Проверка лицензии не удалась

Проблема: Invalid license или License file not found

Решение:

# Check license file location
ls -la nedgelite.license /etc/nedgelite.license

# Verify license validity
nedgelite --check-license

# Display system ID for license generation
nedgelite --show-system-id

# Contact ntop.org for valid license

Невозможно привязаться к NFQUEUE

Проблема: Unable to open queue 0 или Unable to bind to queue

Причины и решения:

  1. Очередь уже занята:

    # Check for other nedgelite instances
ps aux | grep nedgelite
sudo killall nedgelite

# Check for other applications using the queue
cat /proc/net/netfilter/nfnetlink_queue

  2. Модуль ядра не загружен:

    sudo modprobe nfnetlink_queue
sudo modprobe nf_conntrack

  3. Недостаточно разрешений:

    # Must run as root
sudo nedgelite -q 0 -z tcp://127.0.0.1:1234

Ошибки отказа в разрешении

Проблема: Permission denied при доступе к сетевому фильтру

Решение:

# Run as root or with sudo
sudo nedgelite -q 0 -z tcp://127.0.0.1:1234

# Check capabilities (if using capabilities instead of root)
sudo setcap cap_net_admin=eip /usr/local/bin/nedgelite

Проблемы с обработкой пакетов

Никакие пакеты не достигают nEdge Lite

Проблема: nEdge Lite запускается, но не проявляет активности.

Диагностика:

# Check iptables rules
sudo iptables -t mangle -L -n -v

# Verify packets are being queued
# Look for non-zero packet counts on NFQUEUE rules

# Check queue statistics
cat /proc/net/netfilter/nfnetlink_queue

Решения:

  1. правила iptables не настроены:

    # Run setup script
sudo /usr/share/nedgelite/scripts/default_setup.sh eth0

  2. Неверный номер очереди:

    # Ensure iptables queue-num matches nedgelite -q option
sudo iptables -t mangle -L -n -v | grep NFQUEUE
# Should show: --queue-num 0
# Must match: nedgelite -q 0

  3. Пакеты уже отмечены:

    # Flush conntrack table to reset marks
sudo conntrack -F

  4. Трафик не соответствует правилам:

    # Add catch-all rule for testing
sudo iptables -t mangle -A PREROUTING -j NFQUEUE --queue-num 0 --queue-bypass

Пакеты неожиданно отбрасываются

Проблема: Легитимный трафик блокируется.

Диагностика:

# Run with verbose logging
sudo nedgelite -q 0 -r /etc/nedgelite/policy.json -v

# Check conntrack marks
sudo conntrack -L | grep mark=2

# View blocked flows in ntopng

Решения:

  1. Слишком широкие правила политики:

    Просмотрите файл политики и настройте фильтры категорий/протоколов:

    {
  "policy": {
    "markers": {
      "categories": {
        "SocialNetwork": "drop"  # May block too much
      }
    },
    "default_marker": "pass"  # Change from "drop"
  }
}

  2. Неверное определение протокола:

    Проверьте журналы nEdge Lite, чтобы узнать, какой протокол был обнаружен. nDPI иногда может неправильно идентифицировать протоколы.

  3. Маркер по умолчанию — «дроп».:

    "default_marker": "pass"  # More permissive

  4. Политики тестирования:

    # Temporarily use pass-all policy
sudo nedgelite -q 0 -v  # No -r option

Высокая потеря пакетов

Проблема: Пакеты отбрасываются из-за переполнения очереди.

Диагностика:

# Check queue statistics
cat /proc/net/netfilter/nfnetlink_queue
# Look for queue_dropped counter

# Check system logs
dmesg | grep nf_queue

Решения:

  1. Увеличить размер очереди:

    sudo iptables -t mangle -A PREROUTING -m mark --mark 0 \
  -j NFQUEUE --queue-num 0 --queue-size 4096

  2. Используйте несколько очередей:

    sudo iptables -t mangle -A PREROUTING -m mark --mark 0 \
  -j NFQUEUE --queue-balance 0:3 --queue-cpu-fanout

sudo nedgelite -q 0:4 -z tcp://127.0.0.1:1234

  3. Добавить обход очереди:

    sudo iptables -t mangle -A PREROUTING -m mark --mark 0 \
  -j NFQUEUE --queue-num 0 --queue-bypass

    Это позволяет пакетам проходить, если nEdge Lite перегружен или выходит из строя.

  4. Оптимизация производительности nEdge Lite:

    • Уменьшите интервал обновления потока: -u 60

    • Увеличить размер таблицы conntrack

    • Прикрепите nEdge Lite к выделенным ядрам CPU

Проблемы обнаружения протокола

Протоколы не обнаруживаются

Проблема: nDPI отмечает потоки как «Неизвестные».

Причины:

  • Зашифрованный трафик (HTTPS, VPN)

  • Недостаточное количество проверенных пакетов

  • Новый/неподдерживаемый протокол

  • Фрагментированные пакеты

Решения:

  1. Обновить библиотеку nDPI:

    cd ~/nDPI
git pull
make
sudo make install

  2. Проверьте список протоколов nDPI:

    nedgelite -H | grep -i <protocol>

  3. Разрешить больше пакетов для обнаружения:

    nDPI для некоторых протоколов может потребоваться 10–20 пакетов. Убедитесь, что начальные пакеты не отбрасываются.

  4. Пользовательская конфигурация протокола:

    См. документацию nDPI для определения пользовательских протоколов.

Зашифрованный трафик

Проблема: трафик HTTPS/TLS классифицирован неправильно

Объяснение: nDPI может обнаружить множество протоколов выше HTTPS, используя:

  • TLS SNI (указание имени сервера)

  • Анализ сертификатов

  • Поведенческие модели

Ограничения: Некоторые зашифрованные протоколы невозможно идентифицировать без перехвата TLS (MITM).

Обнаружен неправильный протокол

Проблема: nDPI неправильно идентифицирует протокол

Решения:

  1. Обновление nDPI: новые версии имеют улучшенную точность.

  2. Сообщите проекту nDPI: Отправьте PCAP файлов на анализ.

  3. Используйте политики на основе категорий: Категории более надежны, чем отдельные протоколы.

  4. Ручное переопределение: использовать правила на основе IP для определенных служб.

Вопросы политики

Политика не применяется

Проблема: Правила политики не соблюдаются.

Диагностика:

# Check if policy file is being loaded
sudo nedgelite -q 0 -r /etc/nedgelite/policy.json -v
# Look for "Loading policy" messages

# Verify JSON syntax
cat /etc/nedgelite/policy.json | jq .

Решения:

  1. JSON синтаксическая ошибка:

    # Validate JSON
cat /etc/nedgelite/policy.json | jq .
# Fix any syntax errors

  2. Пул не соответствует трафику:

    Проверьте диапазоны IP-адресов в определении пула:

    {
  "pool": {
    "ip": ["192.168.1.0/24"],  # Must match actual traffic
    ...
  }
}

  3. Политика перезагрузки:

    sudo kill -HUP $(pidof nedgelite)

Изменения политики не вступают в силу

Проблема: Изменения в файле политики не имеют эффекта.

Решения:

  1. Политика перезагрузки:

    sudo kill -HUP $(pidof nedgelite)

  2. Перезапустите nEdge Lite.:

    sudo killall nedgelite
sudo nedgelite -q 0 -r /etc/nedgelite/policy.json -z tcp://127.0.0.1:1234

  3. Очистить соединение:

    Существующие соединения сохраняют старые отметки:

    sudo conntrack -F

ntopng Проблемы интеграции

В ntopng никаких потоков не появляется

Проблема: nEdge Lite работает, но ntopng не отображает потоки.

Диагностика:

# Check ZMQ connection
sudo netstat -tn | grep 1234

# Verify ntopng endpoint
ps aux | grep ntopng | grep tcp://

Решения:

  1. Несоответствие конечной точки:

    # ntopng must have trailing 'c'
sudo ntopng -i tcp://127.0.0.1:1234c

# nEdge Lite must NOT have trailing 'c'
sudo nedgelite -q 0 -z tcp://127.0.0.1:1234

  2. Блокировка брандмауэра ZMQ:

    # Allow TCP port 1234
sudo iptables -A INPUT -p tcp --dport 1234 -j ACCEPT

  3. ntopng не работает:

    ps aux | grep ntopng
# Start ntopng if not running

ZMQ Отказ в соединении

Проблема: Connection refused когда nEdge Lite пытается подключиться к ntopng

Решения:

  1. Сначала начните ntopng:

    sudo ntopng -i tcp://0.0.0.0:1234c

  2. Проверьте, что ntopng слушает:

    sudo netstat -tnlp | grep 1234

  3. Проверьте адрес конечной точки:

    • Использовать 0.0.0.0 на ntopng для прослушивания на всех интерфейсах

    • Используйте правильный IP-адрес в nEdge Lite -z вариант

Обновления политики от ntopng не работают

Проблема: Изменения в ntopng GUI не влияют на nEdge Lite.

Решения:

  1. Проверка конечной точки политики:

    # ntopng must publish events
sudo ntopng -i tcp://0.0.0.0:5556c --zmq-publish-events tcp://0.0.0.0:5557

# nEdge Lite must subscribe
sudo nedgelite -q 0 -z tcp://ntopng:5556 -p tcp://ntopng:5557

  2. Проверьте подключение политики ZMQ:

    sudo netstat -tn | grep 5557

  3. Перезапустите обе службы:

    sudo killall ntopng nedgelite
# Start ntopng first, then nEdge Lite

Проблемы с производительностью

Высокое использование CPU

Проблема: nEdge Lite потребляет слишком много CPU

Причины:

  • Высокая скорость передачи пакетов

  • Комплексная политика

  • Слишком частые обновления потока

Решения:

  1. Используйте несколько очередей:

    sudo nedgelite -q 0:$(nproc) -z tcp://127.0.0.1:1234

  2. Уменьшите частоту обновления потока:

    sudo nedgelite -q 0 -z tcp://127.0.0.1:1234 -u 60

  3. Оптимизация политик:

    • Используйте фильтры категорий вместо множества фильтров протоколов.

    • Упростите логику политики

  4. Настройка системы:

    # Increase conntrack table
sudo sysctl -w net.netfilter.nf_conntrack_max=1048576

Высокое использование памяти

Проблема: Использование памяти nEdge Lite со временем растет.

Диагностика:

# Monitor memory
ps aux | grep nedgelite
pmap $(pidof nedgelite)

Причины:

  • Большое количество одновременных потоков

  • Утечки потока (не очищаются)

Решения:

  1. Нормальное поведение: ожидается ~2–3 КБ на активный поток.

  2. Настройка тайм-аута простоя: Если потоки не очищаются, проверьте таймауты conntrack:

    sudo sysctl -w net.netfilter.nf_conntrack_tcp_timeout_established=3600

  3. Мониторинг количества потоков:

    sudo conntrack -C  # Show connection count

Задержка сети

Проблема: увеличена задержка при работе nEdge Lite.

Решения:

  1. Оптимизация обработки очереди:

    • Использовать --queue-cpu-fanout в iptables

    • Прикрепите nEdge Lite к выделенным ядрам

  2. Отключить пакетирование потока:

    sudo nedgelite -q 0 -z tcp://127.0.0.1:1234 -f

  3. Проверить глубину очереди:

    cat /proc/net/netfilter/nfnetlink_queue

Системные проблемы

Модуль ядра не загружается

Проблема: modprobe: FATAL: Module nfnetlink_queue not found

Решения:

# Install kernel modules
# Ubuntu/Debian
sudo apt-get install linux-headers-$(uname -r)

# CentOS/Rocky
sudo yum install kernel-devel-$(uname -r)

# Rebuild modules
sudo depmod -a
sudo modprobe nfnetlink_queue

Таблица Conntrack заполнена

Проблема: nf_conntrack: table full, dropping packet

Решения:

# Increase conntrack table size
sudo sysctl -w net.netfilter.nf_conntrack_max=1048576

# Make persistent
echo "net.netfilter.nf_conntrack_max=1048576" | \
  sudo tee -a /etc/sysctl.conf

# Verify
sudo sysctl -p

Недостаточно памяти

Проблема: Убийца Kernel OOM прекращает работу nEdge Lite

Решения:

  1. Добавьте еще RAM

  2. Уменьшите количество потоков: Реализация агрессивной политики тайм-аута.

  3. Ограничить память nEdge Lite:

    # Use systemd to limit memory
sudo systemctl set-property nedgelite.service MemoryMax=1G

Методы отладки

Подробное ведение журнала

sudo nedgelite -q 0 -r /etc/nedgelite/policy.json -z tcp://127.0.0.1:1234 -v

Захват пакетов

# Capture packets going to NFQUEUE
sudo tcpdump -i any -w /tmp/capture.pcap

# Analyze with Wireshark
wireshark /tmp/capture.pcap

Мониторинг Conntrack

# Watch connections in real-time
watch -n 1 'sudo conntrack -L | head -20'

# Show statistics
sudo conntrack -S

# Show connections with marks
sudo conntrack -L -m

Проверка правил iptables

# List mangle table with counters
sudo iptables -t mangle -L -n -v

# Trace packet path (requires iptables-extensions)
sudo iptables -t raw -A PREROUTING -p tcp --dport 80 -j TRACE
sudo xtables-monitor -t

Системные журналы

# Check kernel messages
sudo dmesg | grep -i "nf_queue\|conntrack\|nedgelite"

# Check system logs
sudo journalctl -u nedgelite -f  # If running as systemd service
