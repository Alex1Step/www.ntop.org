Конфигурация

В этом разделе описаны все параметры конфигурации, доступные в nEdge Lite, включая аргументы командной строки, переменные среды и поведение во время выполнения.

Параметры командной строки

Основные параметры

-q, –queue-id <id>[:<num>]

Указывает идентификаторы NFQUEUE для прослушивания.

  • Единая очередь: -q 0

  • Несколько очередей: -q 0:4 (использует очереди 0, 1, 2, 3)

Количество очередей определяет количество потоков. Каждая очередь обрабатывается отдельным потоком.

Примеры:

# Single queue
sudo nedgelite -q 0

# Four queues (0-3) for load balancing
sudo nedgelite -q 0:4

# Eight queues starting at queue 10
sudo nedgelite -q 10:8

-v, – многословный

Включите подробный вывод журнала. Показывает подробную информацию об обработке пакетов, обнаружении протоколов и управлении потоками.

sudo nedgelite -q 0 -v

-х, –помогите

Отображение справочного сообщения со всеми доступными опциями.

nedgelite --help

-V, –версия

Отображение информации о версии.

nedgelite --version

-ЧАС

Отображение подробной справки, за которой следуют списки поддерживаемых протоколов nDPI и категорий. и риски потоков (с их идентификаторами, кодами и короткими именами), принятые в карте меток. (см. Этикетки подключения).

nedgelite -H

Варианты политики

-r, –rules <путь>

Загрузить правила политики из файла JSON. Файл содержит определения пулов и правила политики.

sudo nedgelite -q 0 -r /etc/nedgelite/policy.json

При использовании этой опции вы можете перезагрузить политики, отправив SIGHUP процессу nEdge Lite:

sudo kill -HUP $(pidof nedgelite)

-p, –zmq-policy-endpoint <url>

Подпишитесь на обновления политики с ntopng по ZeroMQ. Это обеспечивает динамическое управление политиками через веб-интерфейс ntopng.

sudo nedgelite -q 0 -p tcp://127.0.0.1:5557

Для резервирования поддерживается несколько конечных точек:

sudo nedgelite -q 0 -p tcp://127.0.0.1:5557 -p tcp://10.0.0.1:5557

Параметры экспорта потока

-z, –zmq-flow-endpoint <url>

Отправьте данные о потоке на ntopng через ZeroMQ. Обычно это требуется для мониторинга и визуализации.

sudo nedgelite -q 0 -z tcp://127.0.0.1:1234

Поддерживается несколько конечных точек для отправки потоков в несколько экземпляров ntopng:

sudo nedgelite -q 0 -z tcp://192.168.1.10:1234 -z tcp://192.168.1.20:1234

-j, –json

Экспортируйте потоки в формате JSON вместо формата TLV по умолчанию (Тип-Длина-Значение).

sudo nedgelite -q 0 -z tcp://127.0.0.1:1234 -j

Примечание: Формат TLV более компактен и эффективен. Используйте JSON только в том случае, если это необходимо для отладки или пользовательской интеграции.

-f, –флеш

Промывка течет сразу выше ZMQ без дозирования. Это уменьшает задержку, но может увеличить накладные расходы.

sudo nedgelite -q 0 -z tcp://127.0.0.1:1234 -f

-u, –flow-update <секунды>

Установите интервал (в секундах) для периодических обновлений потока. По умолчанию — 30 секунд.

# Update flows every 10 seconds
sudo nedgelite -q 0 -z tcp://127.0.0.1:1234 -u 10

Диапазон: 3–120 секунд

-y, –zmq-ключ-шифрования <ключ>

Включите шифрование ZeroMQ CURVE для безопасного экспорта потока. Предоставьте открытый ключ сервера.

sudo nedgelite -q 0 -z tcp://127.0.0.1:1234 -y "server-public-key"

Параметры отслеживания соединений

-s, –skip-ct-reset

Пропустить инициализацию conntrack при запуске. По умолчанию nEdge Lite:

  • Включает учет conntrack

  • Включает временные метки conntrack

  • Сбрасывает счетчики nfacct

Используйте эту опцию, если эти параметры уже настроены или управляются извне.

sudo nedgelite -q 0 -s

Опции метки подключения

nEdge Lite может помечать соединения метками conntrack (connlabels), описывающими, что nDPI обнаружены, поэтому правила iptables могут соответствовать им. Видеть Этикетки подключения для Подробности и примеры.

-L, –labels <путь>

Включите метки соединений, используя указанный файл карты меток. Карта выбирает, какой nDPI протоколы, категории и риски потока определяют, какой из 128 доступных битов меток.

sudo nedgelite -q 0 -L /etc/nedgelite/labels.conf

-o, –connlabel <каталог>

Генерировать <dir>/connlabel.conf из карты меток, затем выйдите. Файлу присваивается имя каждому биту метки, используемому картой, и должен быть установлен как /etc/xtables/connlabel.conf чтобы iptables и conntrack могли ссылаться на метки по имени. Требует -L. Названия ярлыков содержать только буквы, цифры и -.

nedgelite -L /etc/nedgelite/labels.conf -o /tmp
sudo mkdir -p /etc/xtables
sudo cp /tmp/connlabel.conf /etc/xtables/connlabel.conf

Варианты лицензии

--show-system-id

Отображение идентификатора системы, используемого для создания лицензии.

nedgelite --show-system-id

–check-лицензия

Проверьте действительность установленной лицензии.

nedgelite --check-license

–проверка-обслуживание

Проверьте дату истечения срока технического обслуживания.

nedgelite --check-maintenance

Файлы конфигурации

Файл лицензии

Локации (проверено по порядку):

  1. nedgelite.license (текущий каталог)

  2. /etc/nedgelite.license

Формат: Файл двоичной лицензии, предоставленный ntop.org.

Файл политики

Расположение: Указывается с -r вариант

Формат: JSON (объекты JSON, разделенные новой строкой)

Пример: /etc/nedgelite/policy.json

Видеть Правила политики для подробного формата файла политики.

Файл карты меток

Расположение: Указывается с -L вариант

Формат: Текст, один <bit> <type> <name> [<label>] отображение на строку

Пример: /etc/nedgelite/labels.conf

Видеть Этикетки подключения для формата файла.

Конфигурация времени выполнения

Сигналы

nEdge Lite реагирует на сигналы POSIX:

СИГИНТ / СИГТЕРМ

Грамотное завершение работы nEdge Lite:

sudo kill -TERM $(pidof nedgelite)
# or press Ctrl+C

ПОДПИСАТЬСЯ

Перезагрузить правила политики из файла (только если -r был использован вариант):

sudo kill -HUP $(pidof nedgelite)

Системные настройки

nEdge Lite требует определенных настроек ядра для оптимальной работы:

Контрэк Бухгалтерия:

echo 1 | sudo tee /proc/sys/net/netfilter/nf_conntrack_acct

Временные метки Conntrack:

echo 1 | sudo tee /proc/sys/net/netfilter/nf_conntrack_timestamp

Размер таблицы Conntrack (для большого количества подключений):

# Increase conntrack table size
echo 262144 | sudo tee /proc/sys/net/netfilter/nf_conntrack_max

Тайм-ауты Conntrack (отрегулируйте по мере необходимости):

# TCP established timeout (default: 5 days)
echo 3600 | sudo tee /proc/sys/net/netfilter/nf_conntrack_tcp_timeout_established

Сделайте эти настройки постоянными, добавив их в /etc/sysctl.conf:

net.netfilter.nf_conntrack_acct=1
net.netfilter.nf_conntrack_timestamp=1
net.netfilter.nf_conntrack_max=262144
net.netfilter.nf_conntrack_tcp_timeout_established=3600

Общие примеры конфигурации

Автономный со статической политикой

sudo nedgelite -q 0 -r /etc/nedgelite/policy.json -v

Интегрировано с ntopng

# On ntopng host
sudo ntopng -i tcp://0.0.0.0:5556c --zmq-publish-events tcp://0.0.0.0:5557

# On nEdge Lite host
sudo nedgelite -q 0 -z tcp://ntopng-server:5556 -p tcp://ntopng-server:5557

Мультиочередь для повышения производительности

# Configure 8 queues
sudo nedgelite -q 0:8 -z tcp://127.0.0.1:1234 -u 15

Режим моста с файлом политики

# Set up bridge
sudo /usr/share/nedgelite/scripts/bridge_setup.sh eth0 eth1

# Start nEdge Lite
sudo nedgelite -q 0 -r /etc/nedgelite/policy.json -z tcp://127.0.0.1:1234

Этикетки подключения

# Generate and install connlabel.conf (once, and after changing the map)
nedgelite -L /etc/nedgelite/labels.conf -o /tmp
sudo cp /tmp/connlabel.conf /etc/xtables/connlabel.conf

# Start nEdge Lite with labels enabled
sudo nedgelite -q 0 -r /etc/nedgelite/policy.json -L /etc/nedgelite/labels.conf

Несколько коллекторов ntopng

sudo nedgelite -q 0 \
  -z tcp://ntopng1.local:5556 \
  -z tcp://ntopng2.local:5556 \
  -p tcp://ntopng1.local:5557

Экспорт зашифрованного потока

sudo nedgelite -q 0 \
  -z tcp://remote-ntopng:5556 \
  -y "Yne@$w-vo<fVvi]a<NY6T1ed:M$fCG*[IaLV{hID" \
  -p tcp://remote-ntopng:5557

Настройка производительности

Для сред с высоким трафиком:

Настройка нескольких очередей:

# Use one queue per CPU core
sudo nedgelite -q 0:$(nproc) -z tcp://127.0.0.1:1234 -u 10

Оптимизация обновлений потока:

# Reduce update interval for real-time monitoring
sudo nedgelite -q 0 -z tcp://127.0.0.1:1234 -u 5

# Increase update interval for high-volume environments
sudo nedgelite -q 0 -z tcp://127.0.0.1:1234 -u 60

CPU Родство:

# Pin to specific CPU cores
sudo taskset -c 0-3 nedgelite -q 0:4 -z tcp://127.0.0.1:1234
