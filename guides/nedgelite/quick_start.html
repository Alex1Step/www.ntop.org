Краткое руководство

Это руководство поможет вам быстро запустить nEdge Lite. Мы рассмотрим базовый сценарий развертывания с интеграцией ntopng.

Предварительные условия

Прежде чем начать, убедитесь, что у вас есть:

  1. Установлен nEdge Lite.: Следуйте Установка руководство, если вы еще этого не сделали

  2. Действующая лицензия: Поместите файл лицензии по адресу /etc/nedgelite.license

  3. Корневой доступ: Все команды должны выполняться от имени пользователя root или с помощью sudo.

  4. Сетевые интерфейсы: минимум один сетевой интерфейс для проверки трафика.

Быстрая настройка (единый интерфейс)

Это простейшее развертывание для тестирования или защиты трафика на одном интерфейсе.

Шаг 1. Настройте правила Netfilter

Запустите сценарий настройки для режима одного интерфейса:

sudo /usr/share/nedgelite/scripts/default_setup.sh eth0

Заменять eth0 с вашим фактическим именем интерфейса. Этот скрипт настраивает iptables для маршрутизации пакетов в NFQUEUE.

Что это делает:

  • Настраивает таблицу mangle iptables для сохранения/восстановления CONNMARK.

  • Направляет немаркированные пакеты (mark=0) в NFQUEUE 0.

  • Отбрасывает пакеты, отмеченные меткой = 2.

  • Разрешает пакеты, отмеченные меткой = 1.

Шаг 2: Начните ntopng

На том же хосте (или другом) начните ntopng с коллектора ZMQ:

sudo ntopng -i tcp://127.0.0.1:1234c

Важный: Обратите внимание на конечный c в URL-адресе конечной точки. Это указывает ntopng действовать как коллектор ZMQ.

ntopng будет прослушивать порт 1234 для передачи данных от nEdge Lite.

Шаг 3. Запустите nEdge Lite.

Запустите nEdge Lite и подключите его к ntopng:

sudo nedgelite -q 0 -z tcp://127.0.0.1:1234 -v

Разбивка команд:

  • -q 0: использовать идентификатор NFQUEUE 0.

  • -z tcp://127.0.0.1:1234: отправить потоки в ntopng в этой конечной точке ZMQ.

  • -v: Подробное журналирование

Шаг 4. Проверьте работу

  1. Проверьте, работает ли nEdge Lite:

    Вы должны увидеть выходные данные, указывающие, что nEdge Lite запущен и обрабатывает пакеты.

  2. Создайте немного трафика:

    ping 8.8.8.8
curl http://www.example.com

  3. Просмотр потоков в ntopng:

    Откройте браузер и перейдите к http://локальный хост:3000 (веб-интерфейс по умолчанию ntopng). Вы должны увидеть потоки, появляющиеся в режиме реального времени.

  4. Проверьте отслеживание соединения:

    sudo conntrack -L | head -20

    Вы должны увидеть нанесенные метки соединения.

Быстрая настройка (режим моста)

Режим моста позволяет nEdge Lite прозрачно проверять трафик между двумя сегментами сети.

Шаг 1: Настройка моста

Запустите скрипт настройки моста:

sudo /usr/share/nedgelite/scripts/bridge_setup.sh eth0 eth1

Заменять eth0 (локальная сеть) и eth1 (WAN) с реальными именами интерфейсов.

Что это делает:

  • Создает мостовой интерфейс br0

  • Добавляет оба интерфейса в мост

  • Настраивает iptables для фильтрации пакетов моста.

  • Направляет пакеты в NFQUEUE для проверки.

Шаг 2. Запустите ntopng и nEdge Lite.

# Terminal 1: Start ntopng
sudo ntopng -i tcp://127.0.0.1:1234c

# Terminal 2: Start nEdge Lite
sudo nedgelite -q 0 -z tcp://127.0.0.1:1234 -v

Шаг 3. Проверка подключения

С устройства на стороне локальной сети проверьте подключение к Интернету:

ping 8.8.8.8
curl http://www.google.com

Трафик должен проходить через мост и проверяться nEdge Lite.

Использование файлов политики

Вместо использования политики ntopng вы можете использовать статический файл политики JSON.

Шаг 1. Создайте файл политики

Создавать /etc/nedgelite/policy.json:

{
  "pool": {
    "id": 1,
    "name": "Default Pool",
    "ip": ["192.168.1.0/24"],
    "mac": []
  },
  "policy": {
    "id": 1
  }
}
{
  "policy": {
    "id": 1,
    "root": 0,
    "name": "Default Policy",
    "markers": {
      "protocols": {
        "Facebook": "drop",
        "YouTube": "drop",
        "BitTorrent": "drop"
      },
      "categories": {
        "SocialNetwork": "drop",
        "Streaming": "drop"
      },
      "countries": {},
      "continents": {},
      "asn": {}
    },
    "default_marker": "pass"
  }
}

Эта политика блокирует Facebook, YouTube, BitTorrent и целые категории, такие как социальные сети и потоковое вещание.

Шаг 2. Запустите nEdge Lite с файлом политики.

sudo nedgelite -q 0 -r /etc/nedgelite/policy.json -z tcp://127.0.0.1:1234 -v

Разбивка команд:

  • -r /etc/nedgelite/policy.json: загрузить правила политики из этого файла.

  • Остальные параметры остаются прежними

Шаг 3. Проверка соблюдения политики

  1. Попробуйте получить доступ к Facebook:

    curl https://www.facebook.com

    Соединение должно быть заблокировано (или зависло).

  2. Попробуйте получить доступ к разрешенным сайтам:

    curl https://www.wikipedia.org

    Это должно работать нормально.

  3. Просмотр заблокированных потоков в ntopng:

    Откройте ntopng и проверьте наличие пропущенных потоков.

Динамические обновления политики

Для динамического управления политиками используйте ntopng для отправки обновлений политики в nEdge Lite.

Шаг 1. Начните ntopng с ZMQ Издатель.

sudo ntopng -i tcp://127.0.0.1:5556c --zmq-publish-events tcp://127.0.0.1:5557

Параметры:

  • -i tcp://127.0.0.1:5556c: ZMQ коллектор потоков (обратите внимание на c)

  • --zmq-publish-events tcp://127.0.0.1:5557: Публикация событий политики

Шаг 2. Запустите nEdge Lite с помощью сборщика политик.

sudo nedgelite -q 0 -z tcp://127.0.0.1:5556 -p tcp://127.0.0.1:5557 -v

Параметры:

  • -z tcp://127.0.0.1:5556: отправить потоки на ntopng

  • -p tcp://127.0.0.1:5557: Подпишитесь на обновления политики с ntopng.

Шаг 3. Настройте политики в ntopng

  1. Откройте веб-интерфейс ntopng: http://локальный хост:3000

  2. Перейдите в раздел «Политики».

  3. Создание или изменение политик

  4. nEdge Lite автоматически получит и применит обновления.

Перезагрузка политик

Если вы используете статический файл политики (-r вариант), вы можете перезагрузить политику без перезапуска:

# Find the PID
ps aux | grep nedgelite

# Send SIGHUP
sudo kill -HUP <PID>

nEdge Lite перезагрузит файл политики и применит новые правила.

Если вместо этого вы настраиваете политики через ntopng, они автоматически перезагружаются при изменении политики в ntopng.
