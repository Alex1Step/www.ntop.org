ntopng Интеграция

nEdge Lite предназначен для бесперебойной работы с ntopng, обеспечивая централизованный мониторинг, визуализацию и управление политиками. В этом разделе объясняется, как настроить и оптимизировать интеграцию.

Обзор

Интеграция nEdge Lite-ntopng обеспечивает:

  • Мониторинг потока в реальном времени: просмотр всех потоков, проверенных nEdge Lite, в веб-интерфейсе ntopng.

  • Аналитика протоколов: просмотр подробной статистики по обнаруженным протоколам и приложениям.

  • Динамическое управление политиками: Настройте и обновите политики с помощью ntopng и GUI.

  • Исторические данные: Храните и запрашивайте данные о потоке с течением времени.

  • Оповещение: Настройка оповещений о нарушениях политики или подозрительном трафике.

  • Поддержка нескольких экземпляров: несколько экземпляров nEdge Lite могут передавать данные одному ntopng

Интеграционная архитектура

Каналы связи

nEdge Lite и ntopng обмениваются данными по двум каналам ZeroMQ:

  1. Канал экспорта потока: nEdge Lite отправляет данные о потоке на ntopng (ZMQ PUB/SUB)

  2. Канал обновления политики: ntopng отправляет обновления политики в nEdge Lite (ZMQ PUB/SUB)

┌─────────┐                    ┌─────────┐
│   nEdge Lite   │──── Flows ────────>│  ntopng │
│         │<─── Policies ──────│         │
└─────────┘                    └─────────┘

ZeroMQ Конечные точки

  • ntopng как Коллекционер: URL-адрес конечной точки должен заканчиваться c (например., tcp://127.0.0.1:1234c)

  • nEdge Lite как издатель: URL-адрес конечной точки без c (например., tcp://127.0.0.1:1234)

Базовая настройка

Развертывание на одном хосте

Когда nEdge Lite и ntopng работают на одном компьютере:

Начало ntopng:

sudo ntopng -i tcp://127.0.0.1:1234c

Запустите nEdge Lite:

sudo nedgelite -q 0 -z tcp://127.0.0.1:1234

Доступ к веб-интерфейсу ntopng:

Открыть http://локальный хост:3000 в вашем браузере. Вы должны увидеть потоки от nEdge Lite, появляющиеся в режиме реального времени.

Удаленное развертывание

Когда nEdge Lite и ntopng работают на разных машинах:

На хосте ntopng (192.168.1.10):

sudo ntopng -i tcp://0.0.0.0:1234c

На хосте nEdge Lite:

sudo nedgelite -q 0 -z tcp://192.168.1.10:1234

Конфигурация брандмауэра:

Убедитесь, что порт TCP 1234 доступен с хоста nEdge Lite на хост ntopng.

Динамическое управление политиками

Чтобы включить двунаправленную связь (экспорт потока + обновления политики):

Настройка с обновлениями политики

На хосте ntopng:

sudo ntopng -i tcp://0.0.0.0:5556c --zmq-publish-events tcp://0.0.0.0:5557

На хосте nEdge Lite:

sudo nedgelite -q 0 -z tcp://ntopng-host:5556 -p tcp://ntopng-host:5557

Настройте политики в ntopng:

  1. Открыть веб-интерфейс ntopng

  2. Перейдите к Настройки → Политика

  3. Создание или изменение политик

  4. Изменения автоматически передаются в nEdge Lite.

Управление политиками через ntopng

Создание пула:

  1. Перейти к Бассейны → Хост-пулы

  2. Нажмите Добавить пул

  3. Определите диапазоны IP и/или MAC-адреса

  4. Назначить политику пулу

Создание политики:

  1. Перейти к Политика → Политика дорожного движения

  2. Нажмите Добавить политику

  3. Настройка фильтров протокола/категории

  4. Установить действие по умолчанию (Пропустить/Отбросить)

  5. Нажмите Сохранять

Просмотр примененных политик:

  1. Перейти к Потоки → Все потоки

  2. Ищите Политика столбец

  3. Потоки показывают, какая политика была применена.

Несколько экземпляров nEdge Lite

Одно ntopng, несколько развертываний nEdge Lite

Разверните nEdge Lite на нескольких хостах, сообщая все данные одному ntopng:

На хосте ntopng:

sudo ntopng -i tcp://0.0.0.0:5556c --zmq-publish-events tcp://0.0.0.0:5557

На хосте nEdge Lite 1:

sudo nedgelite -q 0 -z tcp://ntopng-host:5556 -p tcp://ntopng-host:5557

На хосте nEdge Lite 2:

sudo nedgelite -q 0 -z tcp://ntopng-host:5556 -p tcp://ntopng-host:5557

На хосте nEdge Lite 3:

sudo nedgelite -q 0 -z tcp://ntopng-host:5556 -p tcp://ntopng-host:5557

Все экземпляры nEdge Lite будут:

  • Отправьте потоки в тот же ntopng

  • Получайте обновления политики от того же ntopng

  • Появляются как отдельные интерфейсы/коллекторы в ntopng

Высокая доступность

Для обеспечения избыточности отправьте потоки в несколько экземпляров ntopng:

sudo nedgelite -q 0 \
  -z tcp://ntopng1:5556 \
  -z tcp://ntopng2:5556 \
  -p tcp://ntopng1:5557

Зашифрованное общение

Безопасный экспорт потоков с помощью шифрования ZeroMQ CURVE.

Генерация ключей CURVE

На хосте ntopng сгенерируйте пару ключей:

# Generate keys using zmq tools
curve_keygen

Это выводит:

public-key: Yne@$w-vo<fVvi]a<NY6T1ed:M$fCG*[IaLV{hID
secret-key: D:)Q[IlAW!ahhC2ac:9*A}h:p?([4%wOTJ%JR%cs

Настройте ntopng с шифрованием

sudo ntopng -i tcp://0.0.0.0:5556c \
  --zmq-encryption-key "Yne@$w-vo<fVvi]a<NY6T1ed:M$fCG*[IaLV{hID:D:)Q[IlAW!ahhC2ac:9*A}h:p?([4%wOTJ%JR%cs"

Настройка nEdge Lite с шифрованием

sudo nedgelite -q 0 \
  -z tcp://ntopng-host:5556 \
  -y "Yne@$w-vo<fVvi]a<NY6T1ed:M$fCG*[IaLV{hID"

Примечание: nEdge Lite нужен только открытый ключ, ntopng — оба.

Форматы экспорта потоков

Формат TLV (по умолчанию)

Формат Тип-Длина-Значение компактен и эффективен:

sudo nedgelite -q 0 -z tcp://127.0.0.1:1234

Преимущества:

  • Компактный двоичный формат

  • Меньшее использование полосы пропускания

  • Более быстрая сериализация

JSON Формат

Удобочитаемый формат JSON для отладки:

sudo nedgelite -q 0 -z tcp://127.0.0.1:1234 -j

Преимущества:

  • Человекочитаемый

  • Легко отлаживать

  • Совместимость с пользовательскими интеграциями

Недостатки:

  • Более высокое использование полосы пропускания

  • Медленная сериализация

Оптимизация экспорта потоков

Интервал обновления потока

Настройте частоту обновления потоков:

# Update every 10 seconds (more real-time)
sudo nedgelite -q 0 -z tcp://127.0.0.1:1234 -u 10

# Update every 60 seconds (less overhead)
sudo nedgelite -q 0 -z tcp://127.0.0.1:1234 -u 60

Рекомендации:

  • Мониторинг в реальном времени: 5–15 секунд

  • Исторический анализ: 30-60 секунд

  • Высокообъемные среды: 60–120 секунд

Немедленная промывка

Отключите пакетную обработку для минимальной задержки:

sudo nedgelite -q 0 -z tcp://127.0.0.1:1234 -f

Варианты использования:

  • Отладка и устранение неполадок

  • Среды с низким трафиком

  • Когда задержка имеет решающее значение

Компромиссы:

  • Более высокое использование CPU

  • Больше ZMQ сообщений

  • Увеличенная пропускная способность

Мониторинг интеграции

Проверка экспорта потока

В ntopng:

  1. Перейти к Интерфейсы

  2. Найдите интерфейс коллектора ZMQ.

  3. Проверьте счетчики пакетов/байтов

Проверьте соединение ZMQ:

# On ntopng host
sudo netstat -tnlp | grep 1234

# On nEdge Lite host
sudo netstat -tn | grep 1234

Просмотр потоков в ntopng

  1. Все потоки: Перейти к Потоки → Все потоки

  2. Лучшие протоколы: Перейти к Панель управления → Лучшие протоколы

  3. Топ приложений: Перейти к Панель управления → Топ приложений

  4. Оповещения: Перейти к Оповещения → Обнаруженные оповещения

Устранение неполадок интеграции

В ntopng никаких потоков не появляется

  1. Убедитесь, что ntopng слушает:

    sudo netstat -tnlp | grep ntopng

  2. Проверьте, работает ли nEdge Lite:

    ps aux | grep nedgelite

  3. Проверьте конфигурацию конечной точки ZMQ:

    • ntopng конечная точка должна заканчиваться на c

    • Конечная точка nEdge Lite не должна иметь c

  4. Проверьте правила брандмауэра:

    sudo iptables -L -n -v | grep 1234

  5. Включите подробное ведение журнала:

    sudo nedgelite -q 0 -z tcp://127.0.0.1:1234 -v

Обновления политики не работают

  1. Проверьте конечную точку политики:

    sudo nedgelite -q 0 -z tcp://127.0.0.1:5556 -p tcp://127.0.0.1:5557 -v

  2. Проверка ntopng публикует:

    sudo netstat -tnlp | grep 5557

  3. Перезапустите nEdge Lite после изменения политики:

    Если вы используете статические файлы, отправьте SIGHUP:

    sudo kill -HUP $(pidof nedgelite)

Высокая задержка или потеря пакетов

  1. Уменьшите интервал обновления потока:

    sudo nedgelite -q 0 -z tcp://127.0.0.1:1234 -u 60

  2. Используйте несколько очередей:

    sudo nedgelite -q 0:4 -z tcp://127.0.0.1:1234

  3. Проверьте пропускную способность сети:

    iftop -i eth0

Лучшие практики интеграции

  1. Совместное размещение, когда это возможно: Запустите nEdge Lite и ntopng на одном хосте для минимальной задержки.

  2. Использовать формат TLV: Более эффективен, чем JSON для производства.

  3. Интервал обновления настройки: Балансируйте видимость в реальном времени и производительность.

  4. Включить шифрование: для удаленных развертываний или чувствительных сред.

  5. Мониторинг очереди ZMQ: следите за отставанием, указывающим на проблемы с производительностью.

  6. Используйте несколько коллекторов: Для развертываний с высокой доступностью.

  7. Регулярное резервное копирование: Экспортировать конфигурацию ntopng и исторические данные.
