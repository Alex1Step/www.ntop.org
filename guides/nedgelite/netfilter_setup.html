Настройка сетевого фильтра

nEdge Lite использует сетевой фильтр Linux (iptables) для перехвата пакетов для проверки. В этом разделе объясняется, как настроить netfilter для различных сценариев развертывания. однако чтение этого раздела обычно не требуется при использовании предоставленных сценариев, как описано в разделе «Краткое руководство».

Понимание NFQUEUE

NFQUEUE — это целевой сетевой фильтр, который ставит пакеты в очередь в приложения пользовательского пространства для обработки. nEdge Lite использует NFQUEUE для:

  1. Получать пакеты от ядра

  2. Выполните глубокую проверку пакетов

  3. Применять политические решения

  4. Возвращать вердикты (принять/отбросить) ядру

Ключевые понятия

Идентификатор очереди: каждая NFQUEUE имеет числовой идентификатор (0–65535). nEdge Lite прослушивает определенные идентификаторы очередей, указанные в -q вариант.

Маркировка соединений (CONNMARK): вместо маркировки отдельных пакетов nEdge Lite маркирует целые соединения с помощью conntrack. Это гарантирует, что все пакеты в соединении следуют одной и той же политике.

Отметить значения:

  • 0: Без маркировки (требуется проверка)

  • 1: Пропустить (разрешить)

  • 2: Отбросить (блокировать)

Пакетный поток:

PREROUTING → Restore CONNMARK → [mark=2? DROP] → [mark=0? NFQUEUE] → POSTROUTING → Save CONNMARK

Сценарии настройки

nEdge Lite включает сценарии установки для распространенных сценариев развертывания.

Режим единого интерфейса

Используйте этот режим при защите трафика на одном сетевом интерфейсе (например, защита локальных служб или трафика шлюза).

Скрипт: /usr/share/nedgelite/scripts/default_setup.sh

Использование:

sudo /usr/share/nedgelite/scripts/default_setup.sh <interface>

Пример:

sudo /usr/share/nedgelite/scripts/default_setup.sh eth0

Что он делает:

# Enable conntrack accounting and timestamps
echo 1 > /proc/sys/net/netfilter/nf_conntrack_acct
echo 1 > /proc/sys/net/netfilter/nf_conntrack_timestamp

# INPUT chain: local incoming traffic
iptables -t mangle -A INPUT -j CONNMARK --restore-mark
iptables -t mangle -A INPUT -m mark --mark 2 -j DROP
iptables -t mangle -A INPUT -m mark --mark 0 -j NFQUEUE --queue-num 0

# OUTPUT chain: local outgoing traffic
iptables -t mangle -A OUTPUT -j CONNMARK --restore-mark
iptables -t mangle -A OUTPUT -m mark --mark 2 -j DROP
iptables -t mangle -A OUTPUT -m mark --mark 0 -j NFQUEUE --queue-num 0

# Save marks to conntrack
iptables -t mangle -A POSTROUTING -j CONNMARK --save-mark

Режим моста

Используйте этот режим для прозрачной проверки между двумя сегментами сети (например, LAN и WAN).

Скрипт: /usr/share/nedgelite/scripts/bridge_setup.sh

Использование:

sudo /usr/share/nedgelite/scripts/bridge_setup.sh <lan_interface> <wan_interface>

Пример:

sudo /usr/share/nedgelite/scripts/bridge_setup.sh eth0 eth1

Что он делает:

# Create bridge
ip link add name br0 type bridge
ip link set dev $LAN_IF master br0
ip link set dev $WAN_IF master br0
ip link set dev br0 up
ip link set dev $LAN_IF up
ip link set dev $WAN_IF up

# Enable bridge netfilter
modprobe br_netfilter
echo 1 > /proc/sys/net/bridge/bridge-nf-call-iptables

# Configure iptables for bridge
iptables -t mangle -A PREROUTING -j CONNMARK --restore-mark
iptables -t mangle -A PREROUTING -m mark --mark 2 -j DROP
iptables -t mangle -A PREROUTING -m mark --mark 0 -j NFQUEUE --queue-num 0
iptables -t mangle -A POSTROUTING -j CONNMARK --save-mark

Мост с VLAN:

При использовании транкинга VLAN на мосту можно создать субинтерфейсы VLAN:

# Add VLAN 10
ip link add link br0 name br0.10 type vlan id 10
ip link set dev br0.10 up
ip addr add 192.168.10.1/24 dev br0.10

Ручная настройка

Для пользовательских развертываний вы можете вручную настроить iptables.

Базовая ручная настройка

# Enable conntrack features
sudo sysctl -w net.netfilter.nf_conntrack_acct=1
sudo sysctl -w net.netfilter.nf_conntrack_timestamp=1

# Configure iptables (example for FORWARD chain)
sudo iptables -t mangle -A PREROUTING -j CONNMARK --restore-mark
sudo iptables -t mangle -A PREROUTING -m mark --mark 2 -j DROP
sudo iptables -t mangle -A PREROUTING -m mark --mark 0 -j NFQUEUE --queue-num 0 --queue-bypass
sudo iptables -t mangle -A POSTROUTING -j CONNMARK --save-mark

Важные параметры:

  • --restore-mark: копирует метку conntrack на метку пакета.

  • --save-mark: копирует метку пакета обратно в conntrack.

  • --queue-num 0: указывает идентификатор NFQUEUE (должен совпадать с идентификатором nEdge Lite). -q вариант)

  • --queue-bypass: Если nEdge Lite не запущен, пакеты проходят (необязательно, но рекомендуется для тестирования).

Конфигурация с несколькими очередями

Для балансировки нагрузки по ядрам CPU используйте несколько очередей:

# Configure 4 queues (0-3)
sudo iptables -t mangle -A PREROUTING -j CONNMARK --restore-mark
sudo iptables -t mangle -A PREROUTING -m mark --mark 2 -j DROP
sudo iptables -t mangle -A PREROUTING -m mark --mark 0 -j NFQUEUE --queue-balance 0:3 --queue-cpu-fanout
sudo iptables -t mangle -A POSTROUTING -j CONNMARK --save-mark

Затем запустите nEdge Lite с помощью:

sudo nedgelite -q 0:4 -z tcp://127.0.0.1:1234

Объяснение опций:

  • --queue-balance 0:3: Распределить пакеты по очередям 0–3.

  • --queue-cpu-fanout: закрепите очереди на ядрах CPU для повышения производительности.

IPv6 Поддержка

Чтобы фильтровать трафик IPv6, добавьте соответствующие правила ip6tables:

# Enable IPv6 conntrack
sudo modprobe nf_conntrack_ipv6

# Configure ip6tables
sudo ip6tables -t mangle -A PREROUTING -j CONNMARK --restore-mark
sudo ip6tables -t mangle -A PREROUTING -m mark --mark 2 -j DROP
sudo ip6tables -t mangle -A PREROUTING -m mark --mark 0 -j NFQUEUE --queue-num 0
sudo ip6tables -t mangle -A POSTROUTING -j CONNMARK --save-mark

Расширенные сценарии

Режим маршрутизатора

Когда nEdge Lite работает на маршрутизаторе/шлюзе:

# Enable IP forwarding
sudo sysctl -w net.ipv4.ip_forward=1

# Configure NAT (if needed)
sudo iptables -t nat -A POSTROUTING -o wan0 -j MASQUERADE

# Configure packet filtering
sudo iptables -t mangle -A PREROUTING -j CONNMARK --restore-mark
sudo iptables -t mangle -A PREROUTING -m mark --mark 2 -j DROP
sudo iptables -t mangle -A PREROUTING -m mark --mark 0 -j NFQUEUE --queue-num 0
sudo iptables -t mangle -A POSTROUTING -j CONNMARK --save-mark

Фильтрация, специфичная для интерфейса

Фильтровать только определенные интерфейсы:

# Only inspect traffic on eth0
sudo iptables -t mangle -A PREROUTING -i eth0 -j CONNMARK --restore-mark
sudo iptables -t mangle -A PREROUTING -i eth0 -m mark --mark 2 -j DROP
sudo iptables -t mangle -A PREROUTING -i eth0 -m mark --mark 0 -j NFQUEUE --queue-num 0
sudo iptables -t mangle -A POSTROUTING -o eth0 -j CONNMARK --save-mark

Фильтрация по определенному направлению

Проверяйте только входящий или исходящий трафик:

# Only inspect incoming traffic (from WAN)
sudo iptables -t mangle -A PREROUTING -i wan0 -j CONNMARK --restore-mark
sudo iptables -t mangle -A PREROUTING -i wan0 -m mark --mark 2 -j DROP
sudo iptables -t mangle -A PREROUTING -i wan0 -m mark --mark 0 -j NFQUEUE --queue-num 0
sudo iptables -t mangle -A POSTROUTING -j CONNMARK --save-mark

Фильтрация по подсети

Применяйте фильтрацию только к определенным диапазонам IP-адресов:

# Only inspect traffic from 192.168.1.0/24
sudo iptables -t mangle -A PREROUTING -s 192.168.1.0/24 -j CONNMARK --restore-mark
sudo iptables -t mangle -A PREROUTING -s 192.168.1.0/24 -m mark --mark 2 -j DROP
sudo iptables -t mangle -A PREROUTING -s 192.168.1.0/24 -m mark --mark 0 -j NFQUEUE --queue-num 0
sudo iptables -t mangle -A POSTROUTING -j CONNMARK --save-mark

Просмотр и отладка

Посмотреть текущие правила

# View mangle table
sudo iptables -t mangle -L -n -v

# View specific chain
sudo iptables -t mangle -L PREROUTING -n -v

Просмотр статистики NFQUEUE

# Check queue statistics (requires nfqueue-utils)
cat /proc/net/netfilter/nfnetlink_queue

Просмотр отслеживания соединений

# View all connections
sudo conntrack -L

# View connections with marks
sudo conntrack -L -m

# View connections with labels (when -L is used)
sudo conntrack -L -o labels

# View statistics
sudo conntrack -S

Правила клиринга

Чтобы удалить все правила iptables:

# Flush all chains
sudo iptables -t mangle -F

# Delete custom chains
sudo iptables -t mangle -X

# Reset policies to ACCEPT
sudo iptables -t mangle -P PREROUTING ACCEPT
sudo iptables -t mangle -P POSTROUTING ACCEPT

Поиск неисправностей

Пакеты не доходят до nEdge Lite

  1. Проверьте правила iptables:

    sudo iptables -t mangle -L -n -v

    Найдите правила NFQUEUE и убедитесь, что счетчики пакетов увеличиваются.

  2. Проверьте идентификатор очереди:

    Убедитесь, что iptables --queue-num соответствует nEdge Lite -q вариант.

  3. Проверить контрек:

    sudo conntrack -L | grep MARK

nEdge Lite не запускается

  1. Проверьте, не используется ли уже очередь:

    cat /proc/net/netfilter/nfnetlink_queue

  2. Использовать обход очереди:

    Добавлять --queue-bypass к правилам iptables для тестирования.

Проблемы с производительностью

  1. Используйте несколько очередей:

    Распределите нагрузку между ядрами CPU (см. Конфигурацию нескольких очередей выше).

  2. Проверьте близость CPU:

    Прикрепите потоки nEdge Lite к определенным ядрам CPU.

  3. Мониторинг глубины очереди:

    watch -n 1 'cat /proc/net/netfilter/nfnetlink_queue'
