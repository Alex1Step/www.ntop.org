5. NVIDIA/Mellanox Поддержка

PF_RING (8.1 или новее) включает встроенную поддержку адаптеров NVIDIA/Mellanox ConnectX-4, ConnectX-5 и ConnectX-6. Поддерживаются как захват пакетов (включая RSS, хэш пакетов, поддержка аппаратных временных меток), так и их передача.

5.1. Предварительное условие

1. Установите пфринг пакет, настроив один из наших репозиториев по адресу http://packages.ntop.org. PF_RING также можно скачать в исходном формате из GIT по адресу https://github.com/ntop/PF_RING/

2. Установите Mellanox OFED/EN из https://www.mellanox.com/products/infiniband-drivers/linux/mlnx_ofed Этот пакет также устанавливает libibглаголы библиотека, необходимая для использования адаптеров Mellanox с PF_RING, а также другими зависимостями. Обратите внимание, что для OFED SDK для использования в системах захвата ( –dpdk для этого доступна опция), как показано в примере ниже.

cd MLNX_OFED_LINUX-*
./mlnxofedinstall

Примечание: --upstream-libs –dpdk требовались в версиях SDK <5.x:

./mlnxofedinstall --upstream-libs --dpdk

5.2. Совместимость

Проверьте прошивку адаптера:

ibv_devinfo

Рекомендуемые версии прошивки:

  • ConnectX-4: >= 28.12.2006

  • ConnectX-5: >= 16.21.1000

  • ConnectX-6: >= 20.27.0090

  • ConnectX-6 Dx: >= 22.27.0090

Также поддерживаются адаптеры Bluefield. Обратите внимание, что этот модуль обнаруживает только устройства с поддержкой RDMA. Если некоторые устройства не поддерживают RDMA они могут не отображаться в списке распознаваемых интерфейсов при запуске pfcount -L -v 1 на Блуфилде.

5.3. Конфигурация

Загрузите необходимые модули (не требуется при использовании сервиса pf_ring, который позаботится об этом):

modprobe -a ib_uverbs mlx5_core mlx5_ib

Убедитесь, что адаптер распознан и указан как PF_RING:

pfcount -L -v 1
Name       SystemName Module  MAC               BusID         NumaNode  Status  License Expiration
enp1s0f0       enp1s0f0       pf_ring B8:CE:F6:8E:DD:5A      0000:01:00.0  -1              Up             Valid       1662797500
enp1s0f1       enp1s0f1       pf_ring B8:CE:F6:8E:DD:5B      0000:01:00.1  -1              Up             Valid       1662797500
mlx:mlx5_0 enp1s0f0   mlx     B8:CE:F6:8E:DD:5A 0000:00:00.0  -1        Down    Valid   1662797500
mlx:mlx5_1 enp1s0f1   mlx     B8:CE:F6:8E:DD:5B 0000:00:00.0  -1        Down    Valid   1662797500

Обратите внимание, что одни и те же интерфейсы появляются дважды, поскольку их можно использовать оба с помощью драйвера ядра. (создание сокета на enp1s0f0 например) или млкс модуль в режиме zero-копирования (создание разъем на соответствующем млкс:mlx5_0 интерфейс).

5.4. Захват трафика

Чтобы перехватить трафик с адаптера Mellanox с помощью нативного млкс модуль mlx:<device> должен быть указано как имя интерфейса, как сообщает пфкаунт -L. Пример:

pfcount -i mlx:mlx5_0

Размер кольца RX по умолчанию (максимальное количество пакетов, которые адаптер может хранить в буфер FIFO) составляет 32 КБ. Это можно настроить с помощью переменной среды PF_RING_RX_QUEUE_SIZE. Пример:

PF_RING_RX_QUEUE_SIZE=4096 pfcount -i mlx:mlx5_0

5.4.1. RSS/многоочередь

Поддержка нескольких очередей (RSS) доступна на Mellanox с тем ограничением, что все очереди следует использовать в одном процессе (поддерживая несколько потоков захвата). Количество очередей RSS можно установить с помощью стандартной команды ethtool в ядре. интерфейс. Пример для 4 очередей:

ethtool -L enp1s0f0 combined 4

В качестве альтернативы количество очередей можно настроить в самом приложении через переменная среды (PF_RING_RSS).

PF_RING_RSS=4 pfcount_multichannel -i mlx:mlx5_0

Чтобы перехватить трафик из очереди, в качестве интерфейса следует использовать mlx:<device>@<queue>. имя. Пример с очередью 0:

pfcount -i mlx:mlx5_0@0

Или открыть все очереди:

pfcount_multichannel -i mlx:mlx5_0

5.5. Передача трафика

Передача пакетов также поддерживается на Mellanox (включая многоочередную/многопоточную передачу). передача при включенном RSS). Тот же синтаксис, который используется для захвата трафика, может быть используется для выбора интерфейса TX. Пример:

pfsend -i mlx:mlx5_0

Или отправлять из всех очередей и масштабировать производительность передачи:

pfsend_multichannel -i mlx:mlx5_0

5.6. Часы

Адаптеры ConnectX обеспечивают аппаратную метку времени пакета с помощью внутренних часов. Убедитесь, что внутренние аппаратные часы (PHC) синхронизированы с системными часами. чтобы приложения не жаловались на сдвиги во времени.

Установите инструмент linuxptp:

apt install linuxptp

Прочтите идентификатор устройства PTP для интерфейса ConnectX для синхронизации:

ethtool -T ens4f0np0 | grep 'PTP Hardware Clock'
PTP Hardware Clock: 2

Считайте текущие часы с устройства ptp (/dev/ptp<id>):

phc_ctl /dev/ptp2 get
phc_ctl[1782789.530]: clock time is 1749026103.583312192 or Wed Jun  4 10:35:03 2025

Синхронизируйте аппаратные часы с системным временем (или используйте предпочитаемый вами метод синхронизации):

phc2sys -s CLOCK_REALTIME -c ens4f0np0 -O 0 -m

(запустите эту команду на несколько секунд, чтобы она отрегулировала время)

5.7. Аппаратная фильтрация

Адаптеры Mellanox поддерживают фильтрацию пакетов в hw. Поддерживается до 64 тыс. правил. Чтобы установить аппаратный фильтр, pfring_add_hw_rule следует использовать API.

Пример кода для фильтрации трафика с помощью Mellanox (как и с другими адаптерами) доступен в pfcount.c образец заявления (ищите sample_filtering_rules).

Правила фильтрации можно определить как уронить или проходить. Поведение по умолчанию может быть установлено с pfring_set_default_hw_action API. Если значение по умолчанию не установлено явно, это зависит от неразборчивого режима: при установленном неразборчивом режиме весь трафик принимается по умолчанию (пропустить), в противном случае трафика нет (отбросить). Промиск устанавливается с помощью pfring_open флаг PF_RING_ПРОМИСК.

Чтобы задать правило фильтрации, правилу должен быть присвоен идентификатор (0..65534). Это уникальный идентификатор, который можно использовать для последующего удаления правила. Идентификатор может автоматически назначаться библиотекой с помощью FILTERING_RULE_AUTO_RULE_ID в качестве идентификатора правила.

Правилу также может быть присвоен приоритет в диапазоне 0..2. Захват двух приложений трафик с того же интерфейса и установка правила пропуска, соответствующего тому же трафику и с одинаковым приоритетом оба будут получать один и тот же трафик. Вместо этого только приложение который устанавливает более высокий приоритет для правила, в противном случае получил бы трафик.

Пример настройки правила фильтрации для удаления трафика UDP, соответствующего IP-адресу источника и порту назначения:

pfring_set_default_hw_action(socket, default_pass);

hw_filtering_rule r = { 0 };

r.rule_id = FILTERING_RULE_AUTO_RULE_ID;
r.priority = 0;
r.rule_family_type = generic_flow_tuple_rule;

r.rule_family.flow_tuple_rule.action = flow_drop_rule;

r.rule_family.flow_tuple_rule.vlan_id = 10;
r.rule_family.flow_tuple_rule.ip_version = 4;
r.rule_family.flow_tuple_rule.src_ip.v4 = src_ip_rule;
r.rule_family.flow_tuple_rule.protocol = IPPROTO_UDP;
r.rule_family.flow_tuple_rule.dst_port = 3000;

pfring_add_hw_rule(socket, &r);

Обратите внимание:

  • все поля расположены в порядке байтов хоста.

  • когда FILTERING_RULE_AUTO_RULE_ID используется идентификатор правила, назначенный pfring_add_hw_rule возвращается в r.rule_id.

Полный список поддерживаемых полей см. generic_flow_tuple_hw_rule структура.

Пример удаления правила фильтрации по идентификатору:

pfring_remove_hw_rule(socket, RULE_ID);

Фильтры BPF также выгружаются в адаптер, если они могут быть автоматически преобразованы механизмом nBPF в аппаратные правила. Пример:

pfcount -i mlx:mlx5_0 -f "vlan 10 and host 192.168.1.1"

5.8. Захват RoCEv2/RDMA

Адаптеры Mellanox изначально поддерживают трафик RoCEv2/RDMA. Этот трафик не захватывается в стандартном режиме, как это обрабатывает адаптер, даже если это выглядит стандартно UDP трафик. Чтобы включить захват трафика RoCEv2/RDMA, необходимо включить специальный режим прослушивания. включено через переменную среды PF_RING_MLX_SNIFFER_MODE, как показано ниже:

PF_RING_MLX_SNIFFER_MODE=1 ./pfcount -i mlx:mlx5_0 -v 1

Обратите внимание, что аппаратная фильтрация (включая разгрузку BPF) не работает в этом режиме. включен.
