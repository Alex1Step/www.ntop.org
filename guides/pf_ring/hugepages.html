Поддержка огромных страниц

Огромные страницы используются ZC для распределения буферов. В этом документе описывается как включить их в вашу систему.

Для нетерпеливых

# 1024 * 2048kB = 2 GB
echo 1024 > /sys/kernel/mm/hugepages/hugepages-2048kB/nr_hugepages
mount -t hugetlbfs nodev /dev/hugepages

_Внимание: если вы случайно превысите количество доступных RAM, ядро ​​округлит до максимально возможного количества огромных страниц и остановит вашу систему._

Как настроить Hugepages навсегда

Как поясняется в установка раздел, вам необходимо отредактировать /etc/pf_ring/hugepages.conf файл и укажите там настройки Hugepages.

Вся история

Linux обычно использует страницы памяти размером 4 КБ, но обеспечивает явное интерфейс для выделения страниц большего размера, называемых огромными страницами. Это вверх разработчикам/администраторам решать, когда их следует использовать.

Преимущества Hugepages:

  • большие объемы физической памяти могут быть зарезервированы для распределения памяти, в противном случае это потерпит неудачу, особенно когда физически непрерывная память требуется.

  • уменьшены накладные расходы: поскольку TLB (буфер поиска трансляции) содержит сопоставление виртуальных и физических адресов на каждой странице с использованием большого количества памяти с размером страницы по умолчанию приводит к накладным расходам на обработку управление записями TLB.

Размер огромной страницы по умолчанию обычно составляет 2 МБ. Огромный размер страницы можно найти в /proc/meminfo:

cat /proc/meminfo | grep Hugepagesize
Hugepagesize: 2048 kB

Огромные страницы могут быть динамически зарезервированы с помощью:

echo 1024 > /sys/kernel/mm/hugepages/hugepages-2048kB/nr_hugepages

Вышеупомянутые страницы выделяются системой без привязки узлов. Если вы хотите принудительно выделить определенный узел NUMA, который вам нужно сделать:

echo 1024 > /sys/devices/system/node/node0/hugepages/hugepages-2048kB/nr_hugepages
echo 1024 > /sys/devices/system/node/node1/hugepages/hugepages-2048kB/nr_hugepages

Можно изменить размер огромных страниц по умолчанию и зарезервировать большие. объемы памяти во время загрузки, используя следующие параметры ядра:

default_hugepagesz=2M hugepagesz=2M hugepages=1024

Если эта команда возвращает непустую строку, поддерживаются страницы размером 2 МБ:

cat /proc/cpuinfo | grep pse

Чтобы сделать огромные страницы доступными для использования, Linux предоставляет Файловая система на основе RAM, называемая «hugetlbfs», которую необходимо смонтировать с помощью:

mount -t hugetlbfs none /dev/hugepages

Чтобы контролировать максимальный объем памяти, привязанный к точке монтирования можно указать опцию «size=» (размер округляется до ближайший огромный размер страницы). Пример:

mount -t hugetlbfs -o pagesize=2M,size=2G none /dev/hugepages

Посмотреть, какие страницы в данный момент используются, можно с помощью следующая команда:

cat /sys/devices/system/node/node*/meminfo | grep Huge
Node 0 HugePages_Total:  1024
Node 0 HugePages_Free:   1024
Node 0 HugePages_Surp:      0

Возможные ошибки

  1. Количество страниц, о которых сообщает HugePages_Total, меньше настроенного количества страниц.

Причины:

Диспетчер памяти не может зарезервировать достаточно физической памяти для выделения запрошенного числа. страниц. Попробуйте выполнить новую загрузку или даже просто очистите кэш буферов:

echo 3 > /proc/sys/vm/drop_caches

  1. Приложение печатает «ошибка mmap’ing Hugepage xxx: ресурс временно недоступен».

Причины:

  • Возможно, у вас нет разрешений на отображение огромных страниц.

  • Увеличьте ulimit «максимальной заблокированной памяти» (см. ulimit -l), чтобы приспособить память, необходимая для буферов и метаданных. Вы можете вручную увеличить значение ulimit:

ulimit -l 4194304

  • Увеличьте значение в /proc/sys/kernel/shmmax. Обратите внимание, что на В 32-битных системах он будет занимать около 4 ГБ.

echo 2147483648 > /proc/sys/kernel/shmmax
