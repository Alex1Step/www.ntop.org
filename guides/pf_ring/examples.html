Примеры приложений

Если вы новичок в PF_RING, вы можете начать с нескольких примеров. PF_RING/пользовательское пространство папка богата готовыми к использованию приложениями PF_RING. Это небольшие автономные приложения. которые демонстрируют различные особенности PF_RING. Пользователи, желающие начать работу с PF_RING могут тестировать приложения и расширять их в соответствии со своими потребностями.

  • PF_RING/пользовательская среда/примеры содержит пример приложения с использованием PF_RING API

  • PF_RING/userland/examples_zc содержит пример приложения с использованием PF_RING ZC API

  • PF_RING/userland/examples_ft содержит пример приложения с использованием PF_RING FT API

Обратите внимание, что приложения имеют множество опций, позволяющих охватить все варианты использования. пожалуйста, проверьте справку (-h) для получения полного списка опций.

Компиляция приложений

Чтобы скомпилировать пример приложения, см. Установка из GIT раздел. Обратите внимание: если вы устанавливаете PF_RING из пакетов, некоторые из примеры приложений, описанные здесь, также распространяются в двоичном формате с расширением пфринг упаковка.

Базовый захват пакетов

pfcount (в PF_RING/пользовательская среда/примеры) — это пример приложения, которое позволяет вам для захвата необработанных пакетов и вывода некоторой статистики. Пример:

sudo ./pfcount -i zc:eth1
=========================
Absolute Stats: [64415543 pkts rcvd][0 pkts dropped]
Total Pkts=64415543/Dropped=0.0 %
64'415'543 pkts - 5'410'905'612 bytes [4'293'748.94 pkt/sec - 2'885.39 Mbit/sec]
=========================
Actual Stats: 14214472 pkts [1'000.03 ms][14'214'017.15 pps/9.55 Gbps]
=========================

Это же приложение также можно использовать для анализа пакетов и извлечения метаданных из L2/L3/L4. заголовки, добавив опцию -v. Пример:

sudo ./pfcount -i eth1 -v 1

zcount (в PF_RING/userland/examples_zc) похоже на pfcount, однако он основан на PF_RING ZC API. Пример:

sudo ./zcount -i zc:eth1 -c 10
=========================
Absolute Stats: 89415341 pkts (0 drops) - 7510888644 bytes
Actual Stats: 14'218'113.27 pps (0.00 drops) - 9.55 Gbps
=========================

Где:

  • Интерфейс, указанный с помощью -i, может быть любым интерфейсом (в приведенном выше примере мы используем драйвер ZC).

  • Число, указанное с помощью -c, является идентификатором кластера (для ZC API требуется уникальный идентификатор для идентификации экземпляра кластера).

Базовая передача пакетов

пфсенд (в PF_RING/пользовательская среда/примеры) позволяет генерировать трафик, подделывая синтетические пакеты или воспроизведение pcap файл. По умолчанию пакеты передаются с максимальной скоростью, поддерживаемой драйвером. можно использовать -p <pps> или -r <Gbps> для управления скоростью перемещения. Также возможно укажите количество пакетов для отправки с помощью -n <num>.

Пример с синтетическим трафиком на стандартном интерфейсе:

sudo ./pfsend -i eth1
TX rate: [current 1'275'650.89 pps/0.86 Gbps][average 1'275'650.89 pps/0.86 Gbps][total 1'275'656.00 pkts]

Полезные опции:

  • -l <длина>, чтобы указать длину пакетов

  • -n <количество>, чтобы остановить передачу после <количества> пакетов

  • -r <gbps>, чтобы указать скорость передачи (Gbit/с)

  • -p <pps скорость>, чтобы указать скорость передачи (пакетов/с)

  • -M <mac> для указания MAC-адреса источника

  • -m <mac>, чтобы указать MAC-адрес назначения

  • -b <номер> указывает количество различных исходных IP-адресов, которые необходимо сгенерировать.

  • -S <ip> для указания IP-адреса источника

  • -D <ip> для указания IP-адреса назначения

  • -V <версия> для указания версии IP (по умолчанию: 4)

  • -L <num>, чтобы добавить заголовок VLAN (сгенерировать <num> разных идентификаторов VLAN)

Пример воспроизведения файла pcap на интерфейсе ZC, управления скоростью (5 Gbps), отправки в цикле (-n 0):

sudo ./pfsend -i zc:eth1 -f 64byte_packets.pcap -n 0 -r 5
TX rate: [current 7'508'239.00 pps/5.05 Gbps][average 7'508'239.00 pps/5.05 Gbps][total 7'508'239.00 pkts]

zsend (в PF_RING/userland/examples_zc) похоже на пфсенд, однако он основан на PF_RING ZC API. Пример:

sudo ./zsend -i eth1 -c 10
=========================
Absolute Stats: 2'604'538 pkts - 218'781'192 bytes
Actual Stats: 1'305'510.19 pps - 0.88 Gbps [109672836 bytes / 1.0 sec]
=========================

Где:

  • Интерфейс, указанный с помощью -i, может быть любым интерфейсом (в приведенном выше примере мы используем стандартный драйвер ядра).

  • Число, указанное с помощью -c, является идентификатором кластера (для ZC API требуется уникальный идентификатор для идентификации экземпляра кластера).

Базовая пересылка пакетов

подпрыгивать (в PF_RING/userland/examples_zc) соединяет трафик между парой интерфейсов как наткнуться на провод.

Пример:

sudo ./zbounce -i zc:eth1 -o zc:eth2 -c 10 -b -g 1:2
=========================
Absolute Stats: 360 pkts (0 drops) - 57'340 bytes
Actual Stats: 57.00 pps (0.00 drops) - 0.00 Gbps
=========================

Где:

  • Число, указанное с помощью -c, является идентификатором кластера (для ZC API требуется уникальный идентификатор для идентификации экземпляра кластера).

  • -b указывает, что мы хотим пересылать трафик в обоих направлениях (в противном случае будет пересылаться только -i на -o)

  • В этом примере приложения используется по одному потоку на каждое направление, поэтому -g требует 2 ядра, чтобы установить сходство CPU для обоих потоков.

Балансировка нагрузки

Многопоточный

zбаланс (в PF_RING/userland/examples_zc) — пример приложения, способного захватывать трафик от одного или нескольких интерфейсов и пакеты балансировки нагрузки к нескольким потребительским потокам.

sudo ./zbalance -i eno1 -c 10 -m 1 -r 0 -g 1:2
Starting balancer with 2 consumer threads..
=========================
Thread #0: 17 pkts - 2'723 bytes
Thread #1: 19 pkts - 3'011 bytes
=========================
Absolute Stats: 36 pkts - 5'734 bytes
Actual Stats: 15.00 pps - 0.00 Gbps
=========================

Где:

  • Интерфейс, указанный с помощью -i, может представлять собой список интерфейсов, разделенных запятыми.

  • Число, указанное с помощью -c, является идентификатором кластера (для ZC API требуется уникальный идентификатор для идентификации экземпляра кластера).

  • С помощью -m можно выбрать хеш-функцию для распределения трафика по потокам (см. список в справке по -h). Существует несколько встроенных опций, но также можно определить собственные функции распределения (см. zbalance_ipc дополнительные примеры функций распределения)

  • Опция -r выбирает ядро ​​CPU, где будет работать поток балансировщика нагрузки.

  • Опция -g выбирает ядра CPU, на которых будут выполняться потребительские потоки (столько потоков, сколько ядер).

Многопроцессный

zbalance_ipc (в PF_RING/userland/examples_zc) — это пример приложения, которое можно использовать для захвата трафика от одного или нескольких интерфейсов и распределения пакетов нагрузки нескольким потребителям процессы. Пожалуйста, прочтите Балансировка нагрузки ZC раздел, чтобы узнать больше о многопроцессной балансировке нагрузки и этом приложении.

Простой пример агрегации трафика от двух интерфейсов и балансировки нагрузки на два процесса с использованием хэша на основе IP:

zbalance_ipc -i zc:eth1,zc:eth2 -n 2 -m 1 -c 10

Где:

  • -n указывает количество исходящих очередей

  • -m выбирает хеш-функцию

  • -c указывает идентификатор кластера ZC

Этот простой пример создает 2 потока. Чтобы перехватить трафик из этих потоков, можно использовать как стандарт PF_RING API, так и ZC API. Потребительское приложение, использующее стандарт PF_RING API, может открывать каждый поток как стандартный интерфейс, передавая имя zc:<cluster ID>@<queue ID> (например, zc:10@0 и zc:10@1) в pfring_open API. Пример с pfcount:

pfcount -i zc:10@0
pfcount -i zc:10@1

Потребительское приложение, использующее ZC API, чтобы в полной мере воспользоваться преимуществами гибкого ZC API и работать в zero-копии, может открывать каждый поток, присоединяющийся к идентификатору очереди, непосредственно через pfring_zc_ipc_attach_queue API. Пример с zcount_ipc:

zcount_ipc -c 10 -i 0
zcount_ipc -c 10 -i 0

Где:

  • -c <id> — идентификатор кластера, указанный в zbalance_ipc.

  • -i <id> — идентификатор очереди

Разделяй и властвуй

zbalance_DC_ipc (в PF_RING/userland/examples_zc) — пример приложения, способного захватывать трафик из нескольких интерфейсов или очередей RSS, фильтрация трафика с использованием нескольких потоков захвата, агрегированная фильтрация трафик со всех интерфейсов в одном потоке и пакеты балансировки нагрузки для нескольких потребительских процессов.

eth1 \
eth2 - (Filtering Thread 0) \                                    / (Consumer Process 0)
                              (FIFO Thread) - (Collector Thread) - (Consumer Process 1)
eth2 - (Filtering Thread 1) /                                    \ (Consumer Process 2)
eth3 /

Пример захвата трафика с 4 интерфейсов, использования 2 потоков захвата/фильтрации и пересылки с балансировкой нагрузки. трафик на 3 потребительских приложения:

sudo ./zbalance -i zc:eth1,zc:eth2 -i zc:eth2,zc:eth3 -c 10 -m 1 -g 0:1 -r 2 -n 3
Run your consumers as follows:
        pfcount -i zc:10@0
        pfcount -i zc:10@1
        pfcount -i zc:10@2
=========================
Absolute Stats: Recv 534 pkts (0 drops) - Forwarded 534 pkts (0 drops)
Actual Stats: Recv 211.00 pps (0.00 drops) - Forwarded 211.00 pps (0.00 drops)
=========================

L7 Классификация потока

ftflow (в PF_RING/userland/examples_ft) — это пример приложения на основе PF_RING FT API способен классифицировать трафик до layer 7. Это также можно расширить для фильтрации трафика на основе протокол приложения, использующий возможности фильтрации/шунтирования PF_RING FT API. Приложение печатает информацию о потоках, как только истекает срок действия потоков (или завершается работа приложения). в случае активных потоков). Пример:
