Возможности

Чтобы запустить необработанный захват с помощью PF_RING, вам необходимо запустить его с привилегированными правами. пользователя или установите соответствующие возможности для приложения.

PF_RING используется для проверки возможности CAP_SYS_ADMIN, однако начиная с ядра 3.8 требуется возможность CAP_SYS_RAW.

Пример последних ядер:

sudo setcap cap_net_raw+eip /usr/bin/pfcount

В ядре <3.8:

sudo setcap cap_net_admin+eip /usr/bin/pfcount

Если вы используете драйверы ZC, также необходимы CAP_IPC_LOCK и CAP_SYS_ADMIN:

sudo setcap cap_net_raw,cap_ipc_lock,cap_sys_admin+eip /usr/bin/pfcount

Примечание. Если ваше приложение не осуществляет захват напрямую из интерфейса ZC (например, он захватывает очередь ZC, созданную zbalance_ipc), CAP_SYS_ADMIN возможности не требуются.

Если вы запускаете приложение на основе PF_RING ZC API (например, zcount), огромные страницы разрешения также необходимы. Распространенная практика создания группы для огромных страниц. пользователей и установите GID при монтировании точки монтирования огромных tlb:

mount -t hugetlbfs -o gid=1002 nodev /dev/hugepages

Обратите внимание, что вы можете установить GID в файле конфигурации огромных страниц pf_ring. чтобы автоматически смонтировать файловую систему Hugetlb с нужными разрешениями:

echo "node=0 hugepagenumber=1024 gid=1002" > /etc/pf_ring/hugepages.conf

Также обратите внимание, что приложение ZC, использующее огромные страницы, необходимо перевести виртуальные адреса на физические адреса. По этой причине ему необходим доступ /proc/self/pagemap, однако в некоторых версиях ядра (например, 4.0 и 4.1) открывается этот файл непривилегированными процессами приводит к сбоям с -EPERM для безопасности причинам, тогда как в других ядрах возможности CAP_SYS_ADMIN обычно достаточно.
