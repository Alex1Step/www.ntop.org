2. Использование PF_RING с Docker

В этом руководстве показано, как запускать приложения обработки пакетов на основе PF_RING или PF_RING ZC внутри Docker контейнеров за несколько простых шагов.

Обзор поддержки и настройки сети Docker см. к документации Docker (https://docs.docker.com/v1.7/articles/networking/).

В качестве первого шага создайте образ Docker, используя Dockerfile ниже, в этом примере. на основе Ubuntu 20.

sudo docker build -t ubuntu20 -f Dockerfile.ubuntu20 .

Обратите внимание, что Dockerfile выполняет необходимые шаги для установки ntop. репозиторий, установив pfring и настроив скрипт точки входа run.sh, чтобы мы могли запускать команды, запустив изображение Docker из команды линия.

Dockerfile.ubuntu20

FROM ubuntu:20.04
MAINTAINER ntop.org

RUN apt-get update && \
  apt-get -y -q install wget lsb-release gnupg && \
  wget -q http://apt.ntop.org/20.04/all/apt-ntop.deb && \
  dpkg -i apt-ntop.deb && \
  apt-get clean all

RUN apt-get update && \
  apt-get -y install pfring

RUN echo '#!/bin/bash\nset -e\nexec "$@"' > /run.sh && \
  chmod +x /run.sh

ENTRYPOINT ["/run.sh"]

На этом этапе можно протестировать pf_ring, используя pfcount в качестве примера приложения.

Обратите внимание, что модуль ядра pf_ring.ko должен быть загружен на хост-компьютере. и что нам нужно установить правильные возможности, используя «-cap-add», чтобы работать с pf_ring.

Примечание

Версия модуля ядра pf_ring, загруженного на хост, и pf_ring Версия библиотеки/приложения, работающая в контейнере, должна быть одинаковой.

sudo docker run ubuntu20 pfcount -i eth0

Примечание: начиная с PF_RING 7.1 и ядра 3.8 «-cap-add net_admin» больше не требуется. Приложение, работающее внутри контейнера docker, может перехватывать трафик из интерфейсы видны только внутри контейнера. Если вы хотите захватывать трафик с интерфейса в пространстве имен хост-сети, вам следует запустить docker с «–network=host».

sudo docker run --network=host ubuntu20 pfcount -i eth0

При работе с PF_RING ZC используйте, например, zbalance_ipc для пересылки трафика. потребительским приложениям, работающим внутри контейнеров Docker, посредством очередей ZC, мы необходимо связать точку монтирования Hugetlb внутри контейнера с помощью «-v» и установить надлежащие возможности. Чтобы проверить это, запустите zbalance_ipc на хосте:

sudo zbalance_ipc -i eth0 -n 1 -m 1 -c 99

И прикрепите pfcount из контейнера в качестве потребителя к очереди кластера, созданной zbalance_ipc:

sudo docker run -v /dev/hugepages:/dev/hugepages --cap-add ipc_lock ubuntu20 pfcount -i zc:99@0

Вместо этого, если нам нужно создать кластер ZC в контейнере, например, в случае, если мы хотите запустить сам zbalance_ipc, приложению необходимо транслировать виртуальные адреса на физические адреса для предоставления адаптеру буферов DMA. По этой причине необходимо для доступа к /proc/self/pagemap, однако, в зависимости от версии ядра, открытие этого файл не разрешен непривилегированным процессам, что приводит к сбоям (-EPERM). Настройка Возможности SYS_ADMIN обычно достаточно в последних ядрах, чтобы она работала.
