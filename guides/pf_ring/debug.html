Аварийная отладка

Для диагностики зависания/сбоя ядра, вызванного загрузкой одного из модулей. предоставленный pf_ring, вы хотите, чтобы система создала дамп сбоя ядра (kdump).

В этом руководстве показано, как создать его на Ubuntu (kdump поддерживается, но по умолчанию не включено).

Требования

sudo apt update
sudo apt install linux-crashdump kdump-tools

Если /usr/lib/debug/boot/vmlinux-$(uname -r) не существует, установите отладку. символы ядра:

sudo apt install linux-image-unsigned-$(uname -r)-dbgsym
sudo apt install linux-modules-$(uname -r)-dbgsym

Ядру необходима предварительно зарезервированная память для загрузки аварийного ядра после паники.

cat /proc/cmdline | grep crashkernel

Если пусто, отредактируйте /etc/default/grub и добавьте в эту строку Crashkernel=512M:

GRUB_CMDLINE_LINUX_DEFAULT="quiet splash crashkernel=512M"

Затем обновите и перезагрузитесь:

sudo update-grub
sudo reboot

Включите службу kdump:

sudo systemctl enable --now kdump-tools

Настройте место хранения дампов в /etc/default/kdump-tools:

KDUMP_COREDIR="/var/crash"
KDUMP_KERNEL="/boot/vmlinuz-$(uname -r)"

Проанализируйте дамп

Воспроизведите сбой и проанализируйте дамп с помощью:

sudo crash /usr/lib/debug/boot/vmlinux-$(uname -r) /var/crash/vmcore
