Ванильный PF_RING

Ванильный PF_RING состоит из:

  1. Ускоренный модуль ядра, обеспечивающий низкоуровневое копирование пакетов в кольца PF_RING.

  2. Пользовательское пространство PF_RING SDK, которое обеспечивает прозрачную PF_RING-поддержку приложений пользовательского пространства.

PF_RING реализует тип сокета, через который приложения пользовательского пространства могут взаимодействовать с модулем ядра PF_RING. Приложения могут получать дескриптор PF_RING и выполнять вызовы API, которые описаны далее в этом руководстве. Дескриптор может быть привязан к:

  1. Физический сетевой интерфейс.

  2. Очередь RX, только на сетевых адаптерах с несколькими очередями.

  3. На «любой» виртуальный интерфейс, что означает, что принимаются/отправленные пакеты на всех интерфейсах системы.

Как указано выше, пакеты считываются из кольца памяти, выделенного во время создания. Входящие пакеты копируются модулем ядра в кольцо и считываются приложениями пользовательского пространства. Выделение/освобождение памяти для каждого пакета не выполняется. После того, как пакет был прочитан из кольца, пространство, используемое в кольце для хранения только что прочитанного пакета, будет использоваться для размещения будущих пакетов. Это означает, что приложения, желающие хранить архив пакетов, должны сохранять только что прочитанные пакеты. поскольку PF_RING не сохранит их.

Анализ пакетов

PF_RING поддерживает анализатор пакетов, способный извлекать метаданные из заголовков L2/L3/L4. Разбор пакетов может быть включен при использовании модуля ядра pf_ring (стандартные драйверы), устанавливающего флаг PF_RING_LONG_HEADER при звоню pfring_open()или явно вызывая pfring_parse_pkt() (это пользовательский файл при использовании обхода ядра технологии). Метаданные синтаксического анализа хранятся в заголовке пакета, в структура pfring_pkthdr.extended_hdr.

Туннелирование и инкапсуляция

Парсер PF_RING способен распознавать различные протоколы туннелирования и инкапсуляции, такие как:

  • VLAN/ЦинЦ

  • MPLS

  • GRE

  • GTP

Метаданные о внутренних заголовках также хранятся в файле структура pfring_pkthdr структуру, пожалуйста, обратитесь к документация API и файлы заголовков для обновленного списка извлеченных полей.

Фильтрация пакетов

PF_RING поддерживает оба устаревших фильтра BPF (т. е. те, которые поддерживаются приложениями на основе pcap, такими как tcpdump), а также два дополнительных типа фильтров (называемых подстановочными и точными фильтрами, в зависимости от того, что указаны некоторые или все фильтрующие элементы), что предоставляет разработчикам широкий выбор возможностей. Фильтры оцениваются внутри модуля PF_RING, то есть в ядре. Также доступны правила аппаратной фильтрации. на выбранных адаптерах при использовании драйверов ZC. PF_RING фильтры (кроме аппаратных фильтров) могут иметь действие указано, чтобы сообщить модулю ядра PF_RING, какое действие необходимо выполнить, когда данный пакет соответствует фильтру. Действия включают передачу/не передачу пакета приложению пользовательского пространства, остановку оценки цепочки фильтров или отражать пакет. В PF_RING отражение пакета — это возможность передать (немодифицированный) пакет, соответствующий фильтровать по сетевому интерфейсу (кроме интерфейса, на котором был получен пакет). Весь Функциональность отражения реализована внутри модуля ядра PF_RING, и единственное действие, запрошенное для приложение пользовательского пространства представляет собой спецификацию фильтра без какой-либо дальнейшей обработки пакетов.

Кластеризация пакетов

PF_RING также может повысить производительность приложений перехвата пакетов за счет реализации двух механизмов, называемых балансировка и кластеризация. Эти механизмы позволяют приложениям, желающим разделить набор пакетов на процесс, чтобы обрабатывать часть всего потока пакетов, одновременно отправляя все оставшиеся пакеты другому члены кластера. Это означает, что разные приложения, открывающие сокеты PF_RING, могут привязать их к конкретный идентификатор кластера (через pfring_set_cluster) для объединения сил и анализа каждой части пакетов.

Способ распределения пакетов по сокетам кластера указан в политике кластера, которая может быть либо для каждого потока (т. е. все пакеты, принадлежащие одному и тому же кортежу <proto, ip src/dst, port src/dst>), который является по умолчанию или циклический. Это означает, что если вы выберете балансировку по потокам, все пакеты, принадлежащие один и тот же поток (т. е. кортеж из пяти элементов, указанный выше) будет отправлен в одно и то же приложение, тогда как при циклическом переборе все приложения будут получать одинаковое количество пакетов, но нет гарантии, что пакеты принадлежат одному и тому же очередь будет получена одним приложением. Таким образом, балансировка по потокам, с одной стороны, позволяет сохранить логику приложения, так как в этом случае приложение получит подмножество всех пакетов, но этот трафик будет быть последовательным. С другой стороны, если у вас есть определенный поток, который занимает большую часть трафика, то приложение, которое будет обрабатывать такой поток, будет перегружено пакетами, и, следовательно, трафик не будет сильно загружен. сбалансированный.

Для получения дополнительной информации о кластеризации ядра прочтите PF_RING Раздел «Кластер ядра».
