3. Поддержка QEMU/KVM в PF_RING ZC

В этом руководстве показано, как запустить потребительское чтение из очереди ZC на виртуальной машине KVM.

3.1. Предварительные условия

  • Кему >= 1.5.1 и <= 2,5

  • Поддержка KVM в ядре Linux (модуль kvm_intel)

Чтобы запустить подчиненное приложение PF_RING ZC поверх виртуальной машины QEMU/KVM, выполните следующие простые шаги:

  1. Запустите виртуальную машину, указав сокет монитора для QEMU:

(H) qemu ... -chardev socket,path=/tmp/qmp0,server,nowait,id=qmp0 -mon chardev=qmp0,mode=control

(есть несколько готовых к использованию скриптов в папке PF_RING/userland/examples_zc/kvm/host/, дополнительную информацию см. в следующем разделе)

  1. Загрузите модуль uio в гостевую систему. Обратите внимание, что может потребоваться загрузка модуля горячего подключения (acpiphp) и модуля virtio_console (virtio_console) в соответствии с вашим дистрибутивом Linux.

(G) modprobe uio
(G) cd PF_RING/userland/examples_zc/kvm/guest/uio_kernel_module
(G) make && insmod uio_ivshmem.ko

  1. Запустите главное приложение PF_RING ZC на хосте, выведя список сокетов монитора всех работающих виртуальных машин:

(H) zbalance_ipc -i zc:eth1 -c 99 -n 2 -m 0 -Q /tmp/qmp0,/tmp/qmp1

Альтернативно запустите генератор трафика на хосте, указав сокет монитора работающей виртуальной машины. где потребительское приложение будет получать сгенерированный трафик:

(H) zsend -c 99 -Q /tmp/qmp0

  1. Запустите подчиненное приложение PF_RING ZC в гостевой системе (оба читают пакеты из указанных очередей):

(G1) zcount_ipc -i 0 -c 99 -u
(G2) zcount_ipc -i 1 -c 99 -u

3.2. Общие проблемы

Если у вас возникли проблемы с запуском zcount_ipc (или аналогичного) в гостевой системе с такой ошибкой:

zcount_ipc -i 0 -c 99 -u
 *** error mmap'ing uio memory region /dev/uio0: Invalid argument ***
dmesg  | tail -n 1
[ 1971.854205] zcount_ipc:3520 map pfn expected mapping type uncached-minus for [mem 0x28000000-0x28000fff], got write-back

Отредактируйте в /etc/default/grub строку, начинающуюся с GRUB_CMDLINE_LINUX_DEFAULT, и добавьте «nopat», например:

GRUB_CMDLINE_LINUX_DEFAULT="nopat"

Затем запустите:

update-grub

3.3. Как создать/загрузить виртуальную машину Qemu

Установите последнюю версию Qemu в соответствии с вашим дистрибутивом Linux или скомпилируйте Qemu из исходного кода:

wget http://wiki.qemu-project.org/download/qemu-*.tar.bz2
tar xvjf qemu-*.tar.bz2
cd qemu-*

В старых версиях Qemu (<=2.4) вам необходимо исправить компонент ivshmem, редактируя hw/misc/ivshmem.c. и закомментировав строку 303 (см. http://patchwork.ozlabs.org/patch/316785/):

//qemu_chr_fe_claim_no_fail(chr);

Настроить/скомпилировать/установить:

./configure
make
make install

Загрузите необходимые KVM и сетевые модули (это создаст мост с предоставленным интерфейсом):

cd PF_RING/userland/examples_zc/kvm/host/
./kvm-load.sh eth1

Загрузите ISO-образ компакт-диска Linux для установки ОС:

./vm-boot-cdrom.sh ubuntu-16.04.5-server-amd64.iso

Клиент VNC следует использовать для подключения к виртуальной машине и настройки сети для доступа ssh. Для работы в сети необходима поддержка Bridge и TUN/TAP (модуль моста, инструменты brctl и tunctl). После установки загрузите виртуальную машину с помощью:

./vm-boot.sh
