2. SR-IOV с PF_RING ZC

SR-IOV позволяет совместно использовать один физический адаптер PCI посредством различные виртуальные функции (VF). В основном используется в виртуальных средах. чтобы позволить различным виртуальным машинам использовать один физический интерфейс и улучшить производительность сети.

PF_RING включает ускоренные драйверы ZC для Intel адаптеров SR-IOV на базе на ixgbe (ixgbevf).

2.1. Захват из интерфейса VF

Чтобы включить SR-IOV на адаптере Intel ixgbe, вы можете использовать sysfs. В приведенном ниже примере мы активируем 2 виртуальные функции для интерфейса eth1:

echo '2' > /sys/bus/pci/devices/$(ethtool -i enp2s0f1 | grep bus-info | cut -d ' ' -f2)/sriov_numvfs

На данный момент 2 новых интерфейса, использующих ixgbevf драйвер должен появиться в есликонфигурация -а (например, enp3s16f1 и enp3s16f3). Пример:

ethtool -i enp3s16f1 | grep driver
driver: ixgbevf

Чтобы направить трафик на этот интерфейс, можно использовать IP-ссылка, применив фильтр к Мак и vlan (необязательный). Пример:

ip link set enp2s0f1 vf 0 mac 00:01:02:03:04:05 vlan 1
ip link set enp2s0f1 vf 1 mac 00:01:02:03:04:06 vlan 1

Обратите внимание, что адаптер настроен на обнаружение поддельных пакетов по по умолчанию, это не позволяет вам работать в беспорядочном режиме, когда генерация трафика. В этом случае вы получите журналы «Обнаружены поддельные пакеты». в dmesg на хосте, где выполняется физическая функция. Это возможно отключить проверку на спуфинг в адаптере, пример:

ip link set enp2s0f1 vf 0 spoofchk off
ip link set enp2s0f1 vf 1 spoofchk off

Чтобы включить драйвер ZC для этих интерфейсов, нам нужно загрузить тот ixgbevf драйвер распространяется с PF_RING. Пример из исходного кода:

cd PF_RING/drivers/intel
make
cd ixgbevf/ixgbevf-*-zc/src
./load_driver.sh

На этом этапе вы сможете перехватывать трафик с виртуального Функция в режиме ZC с добавлением «zc:» к имени интерфейса:

pfcount -i zc:enp3s16f1

2.2. Назначьте VF виртуальной машине на QEMU/KVM (virsh)

Чтобы назначить виртуальную функцию виртуальной машине, используя вирш, следуйте инструкциям следующие шаги.

Отредактируйте /etc/default/grub, как показано ниже:

GRUB_CMDLINE_LINUX_DEFAULT="iommu=1 msi=1 pci=assign-busses intel_iommu=on"

Обновить харч:

update-grub
reboot

Выключите виртуальную машину (в этом примере ubuntu16):

virsh shutdown ubuntu16

Определите сетевое устройство, которое нужно назначить, и проверьте идентификатор шины:

ethtool -i enp3s16f3 | grep bus-info | cut -d ' ' -f2
0000:03:10.3

Создайте XML-файл (например, vf.xml) с шиной/слотом/функцией устройства:

<interface type='hostdev' managed='yes'>
  <source>
    <address type='pci' domain='0' bus='03' slot='10' function='3'/>
  </source>
</interface>

Добавьте виртуальную функцию в конфигурацию виртуальной машины:

virsh attach-device ubuntu16 vf.xml --config

Выделите больше памяти виртуальной машине (необязательно):

virsh setmaxmem ubuntu16 2097152 --config
virsh setmem ubuntu16 2097152

Запустите виртуальную машину:

virsh start ubuntu16

На этом этапе вы можете войти в виртуальную машину, загрузить ixgbevf водитель (как объяснил в предыдущем разделе) и захватывать трафик от виртуальной функции.

2.3. Назначьте VF виртуальной машине в QEMU/KVM (вручную)

Чтобы назначить виртуальную функцию виртуальной машине без с использованием вирш, следуй следующие шаги.

Прочтите идентификатор шины для VF:

ethtool -i enp3s16f1 | grep bus-info | cut -d ' ' -f2
0000:03:10.1

Отвязать текущий драйвер:

echo 0000:03:10.1 > /sys/bus/pci/devices/0000\:03\:10.1/driver/unbind

Добавьте идентификатор VF в драйвер vfio:

modprobe vfio_pci
lspci -s 0000:03:10.1 -n
03:10.1 0200: 8086:10ed (rev 01)
echo "8086 10ed" > /sys/bus/pci/drivers/vfio-pci/new_id

Убедитесь, что для VF установлен драйвер vfio-pci:

lspci -s 03:10.1 -k

Добавьте VF в конфигурацию QEMU:

-device vfio-pci,host=03:10.1

На этом этапе вы можете войти в виртуальную машину, загрузить ixgbevf водитель (как объяснил в предыдущем разделе) и захватывать трафик от виртуальной функции.
