2. Примеры

2.1. Определение базовой конечной точки REST

Базовая конечная точка REST для связи при настройке исходящих очередей должна быть построена в соответствии со следующим форматом.

https://<host>:<port>/egress/{aggregated,balanced,bridge}/

Пользователь укажет агрегированный или сбалансированный или мост после части /egress/ URL-адреса, в зависимости от того, какой тип выхода настраивается.

2.2. Настройка правил на уровне очереди

После создания базовой конечной точки необходимо добавить ключевое слово default для настройки политики по умолчанию, а затем строку запроса, разделенную символом ?, с действие это может быть любое из: вперед, отказаться, шунт, срез-l4 и срез-l3.

Например, политика слайса-l4 по умолчанию может быть установлена ​​для политики уровня очереди агрегированных выходных очередей следующим образом:

https://<host>:<port>/egress/aggregated/default?action=slice-l4

Аналогично, политика шунтирования по умолчанию для сбалансированных выходных очередей может быть установлена ​​следующим образом:

https://<host>:<port>/egress/balanced/default?action=shunt

2.3. Настройка правил на уровне подсети

В правилах на уровне подсети должно быть указано ключевое слово ИП, за которым следует подсеть параметр (значение имеет формат CIDR <адрес/маска>), необходимый для указания контролируемой подсети. Ан действие Параметр необходим для указания фактической политики, которая должна применяться. Действие может быть любым из: вперед, отказаться, шунт, срез-l4 и срез-l3.

Например, следующий запрос может быть выдан для применения в сбалансированных выходных очередях политики отбрасывания для подсети 192.168.2.0/24.

https://<host>:<port>/egress/balanced/ip?subnet=192.168.2.0/24&action=discard

В качестве альтернативы можно установить вперед политика для подсети 192.168.3.0/24 в агрегированных выходных очередях как:

https://<host>:<port>/egress/aggregated/ip?subnet=192.168.3.0/24&action=forward

2.4. Настройка правил уровня протокола

В правилах уровня протокола должно быть указано ключевое слово протокол, за которым следует фактическая строка протокола, которая должна контролироваться. Ан действие требуется указать фактическую политику, которую необходимо принять. Действие может быть любым из: вперед, отказаться, шунт, срез-l4 и срез-l3.

Например, чтобы применить в сбалансированных выходных очередях политику отбрасывания для протокола SSH, можно выполнить следующий запрос

https://<host>:<port>/egress/balanced/protocol/SSH?action=discard

В качестве альтернативы можно установить вперед политика для протокола HTTP в агрегированной выходной очереди как

https://<host>:<port>/egress/aggregated/protocol/HTTP?action=forward
