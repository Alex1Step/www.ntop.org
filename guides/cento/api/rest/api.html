1. RESTful API Спецификация

1.1. Аутентификация

Учетных данных по умолчанию нет. Аутентификация отключена для каждого пользователя до тех пор, пока пароль явно настроен для этого пользователя в Redis, как описано ниже.

Обратите внимание, что для аутентификации следует использовать базовую аутентификацию доступа HTTP. например с завиток можно указать имя пользователя и пароль с помощью -u <user>:<password> как в команде ниже:

curl -u <user>:<password> "https://localhost:4443/egress/aggregated/default?action=forward"

Пожалуйста, проверьте Примеры раздел для получения дополнительных примеров.

1.1.1. Установка пароля REST API

Учетные данные хранятся в Redis (настраиваются через --redis). Пароли хранятся как соленые хеши SHA-256 под ключом cento.user.<username>.password, в формате sha256:<salt>:<hash>, где <salt> представляет собой случайную 16-байтовую шестнадцатеричную строку и <hash> это дайджест SHA-256 <salt> объединенный с открытым текстом пароль.

Чтобы установить или изменить пароль для пользователя, выполните команду ниже, заменив admin с фактическим именем пользователя и newpassword с желаемым паролем.

SALT=$(openssl rand -hex 16); redis-cli SET cento.user.admin.password "sha256:${SALT}:$(printf '%s%s' "$SALT" 'newpassword' | openssl dgst -sha256 -r | awk '{print $1}')"

Если экземпляр Redis прослушивает хост или порт, отличный от заданного по умолчанию, укажите сведения о соединении. с -h host и -p port.

1.2. API

1.2.1. Объединенная выходная очередь

GET /egress/aggregated/[<Индекс очереди>/]default

Установите политику по умолчанию для агрегированной выходной очереди.

  • Описание: Установите политику, которая будет применяться по умолчанию к трафику, направляемому в агрегированную выходную очередь или интерфейс.
