Запуск ntopng в качестве демона

Ntopng может запускаться в режиме демона в системах Unix и при необходимости запускаться автоматически при запуске системы. Выполнение и статус демона контролируются с помощью systemd с помощью команды systemctl сценарий. Сценарий systemd устанавливается автоматически в системах Unix, поскольку он является частью любой стандартной процедуры установки ntopng.

Файл конфигурации демона

Файл конфигурации Ntopng необходим при запуске его в качестве демона. Конфигурационный файл должен иметь имя ntopng.conf и должен быть помещен под /etc/ntopng/. Заинтересованный читатель может найти выше пример файла конфигурации. Файл конфигурации по умолчанию создается по умолчанию при установке ntopng из любого двоичного пакета.

Автоматический запуск демона при загрузке

Чтобы автоматически запускать демон ntopng при запуске системы, необходимо создать пустой файл ntopng.start в том же каталоге, что и файлы конфигурации. Таким образом, каталог будет содержать как файлы конфигурации, так и файлы запуска.

root@devel:/etc/ntopng$ ls -lha
total 28K
drwxr-xr-x   2 root root 4.0K Mar 17 15:44 .
drwxr-xr-x 117 root root  12K Mar 11 12:16 ..
-rw-r--r--   1 root root  211 Mar 15 17:54 ntopng.conf
-rw-r--r--   1 root root    0 Mar 17 15:44 ntopng.start

Существование ntopng.start файл больше не требуется в системах с systemd. В этих системах автоматический запуск демона ntopng контролируется включением/отключением службы ntopng как

systemctl enable ntopng
systemctl disable ntopng

Контроль демонов

В системах Unix демоном ntopng можно управлять с помощью systemd, используя команду systemctl инструмент. Принимаются все стандартные варианты. Опции и использование сценария управления демоном обсуждаются ниже.

начинать

Эта опция используется для запуска демона ntopng.

systemctl start ntopng

останавливаться

Эта опция используется для остановки экземпляра демона ntopng. Например

systemctl stop ntopng

перезапуск

Эта опция вызывает перезапуск экземпляра ntopng.

systemctl restart ntopng

статус

Эта опция отображает статус демона ntopng.

systemctl status ntopng

Запуск нескольких демонов

Несколько демонов ntopng могут быть запущены на одной машине, если systemd доступен. В общем-то, это не обязательно одиночный ntopng является многопользовательским и может обрабатывать несколько интерфейсы. Однако существуют обстоятельства, при которых желательно иметь несколько запущенных экземпляров ntopng.

Чтобы запустить несколько демонов ntopng, systemctl можно использовать. Каждый демон идентифицируется <name> так что systemctl может использоваться с этим идентификатором при управлении демоном. Например:

systemctl start ntopng@eno1
systemctl stop ntopng@eno1
systemctl start ntopng@lo
systemctl stop ntopng@lo

Каждый демон должен иметь свой собственный файл конфигурации в разделе /etc/ntopng и имя файла конфигурации должно быть названо как ntopng-<name>.conf. В приведенном выше примере предполагается два файла ntopng-eno1.conf и ntopng-lo.conf существовать под /etc/ntopng.

Чтобы запустить несколько демонов на одной машине, каждый демон должно гарантированно иметь собственную базу данных Redis (опция -r), это собственные порты HTTP/HTTPS (варианты -w и -W), и свой собственный каталог данных (опция -d). Эти параметры должны быть указаны в файл конфигурации каждого демона.

Чтобы запускать демоны при загрузке, необходимо включить их как

systemctl enable ntopng@eno1
systemctl enable ntopng@eno1

Демоны, которые были enable д, будет автоматически перезапускается после каждого обновления ntopng. Обратите внимание, что резервное копирование и восстановление Конфигурация ntopng не поддерживается при использовании нескольких демонов.

Доступ к ntopng через обратный прокси

Если у вас много экземпляров ntopng, которые вы хотите замаскировать за прокси-сервером, -З вариант — это то, что вы ищете. Дополнительную информацию смотрите на странице руководства.

Использование ntopng с прокси-сервером HTTP(S)

Если ntopng находится за прокси-сервером, который используется для доступа в Интернет, информация о прокси-сервере должны быть настроены в стандартные переменные среды, чтобы позволить ntopng обнаружить их. и подключитесь к Интернету (например, для загрузки черных списков). Оба HTTP и HTTPS поддерживаются.

export HTTP_PROXY=http://127.0.0.1:3128
ntopng -i eth0

Когда ntopng запускается как служба из systemd, необходимо настроить переменные среды. в /etc/systemd/system.conf, как показано ниже:

DefaultEnvironment="http_proxy=http://127.0.0.1:3128"
DefaultEnvironment="https_proxy=http://127.0.0.1:3128"

Затем запустите systemctl daemon-reexec, чтобы применить изменения:

sudo systemctl daemon-reexec

Альтернативно, информацию о прокси можно добавить только в службу ntopng. настроив /etc/systemd/system/ntopng.service, как показано ниже:

[Service]
Type=simple
Environment="http_proxy=http://127.0.0.1:3128"
Environment="https_proxy=http://127.0.0.1:3128"

Затем запустите systemctl daemon-reload, чтобы применить изменения.

sudo systemctl daemon-reload

Затем перезапустите ntopng

sudo systemctl restart ntopng
