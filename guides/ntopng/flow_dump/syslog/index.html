Syslog

Чтобы сбросить потоки в Syslog, укажите -F="syslog". Потоки сбрасываются в Syslog в формате JSON. Это позволяет внешним приложениям легко использовать дампированные потоки и упрощает доставку потоков. для последующих приложений, таких как Logstash.

Пример потока, сброшенного в Syslog, следующий:

{ "IPV4_SRC_ADDR": "192.168.2.222", "SRC_ADDR_LOCAL": true, "SRC_ADDR_BLACKLISTED": false, "SRC_ADDR_SERVICES": 0, "IPV4_DST_ADDR": "192.168.2.1", "DST_ADDR_LOCAL": true, "DST_ADDR_BLACKLISTED": false, "DST_ADDR_SERVICES": 0, "SRC_TOS": 0, "DST_TOS": 0, "L4_SRC_PORT": 38294, "L4_DST_PORT": 22, "PROTOCOL": 6, "L7_PROTO": 92, "L7_PROTO_NAME": "SSH", "TCP_FLAGS": 31, "IN_PKTS": 7, "IN_BYTES": 471, "OUT_PKTS": 5, "OUT_BYTES": 2028, "FIRST_SWITCHED": 1610381756, "LAST_SWITCHED": 1610381756, "CLIENT_NW_LATENCY_MS": 0.010000, "SERVER_NW_LATENCY_MS": 0.205000, "SRC_IP_COUNTRY": "", "SRC_IP_LOCATION": [ 0.000000, 0.000000 ], "DST_IP_COUNTRY": "", "DST_IP_LOCATION": [ 0.000000, 0.000000 ], "NTOPNG_INSTANCE_NAME": "devel", "INTERFACE": "eno1" }

Упакованные версии ntopng устанавливают правило в /etc/rsyslog.d/20-ntopng.conf для сброса потоков и всех других журналов, сгенерированных ntopng, Syslog в /var/log/ntopng.log. Это поведение можно изменить, отредактировав или удалив /etc/rsyslog.d/20-ntopng.conf.

Чтобы обработать или просмотреть все журналы, созданные ntopng, Syslog, файл /var/log/ntopng.log можно получить прямой доступ. В системах на базе systemd такие журналы можно получить доступ также с помощью journalctl средство. Например, чтобы получить все журналы ntopng, работающих как демон, можно запустить

$ sudo journalctl -u ntopng

Предупреждение

В случае /var/log/ntopng.log редактируется/удаляется вручную, сервис rsyslogd может потребоваться перезагрузка. Чтобы перезапустить rsyslogd наберите в консоли sudo service rsyslog restart

Примечание

Дамп потоков Syslog недоступен на Windows
