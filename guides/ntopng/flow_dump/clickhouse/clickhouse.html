Подключиться к ClickHouse

Чтобы соединить ntopng с ClickHouse, используйте опцию -F. Формат этой опции следующий

clickhouse;<host[@<tcp-port>,<mysql-port>]|unix-socket>;<dbname>;<user>;<pw>

или

clickhouse-cluster;<host[@<tcp-port>,<mysql-port>]|socket>;<dbname>;<user>;<pw>;<cluster name>

Где

  • <host[@mysqlport]|socket> Указывает базу данных host или socket файл. По умолчанию порт 9000 используется для подключения через родной API и 9004 для подключения через MySQL API. Чтобы использовать другой порт, укажите его с помощью @TCP_PORT,MYSQL_PORT. Хост может быть символическим именем или IP-адресом. По умолчанию ntopng подключается в виде открытого текста, если вы не хотите делать это через TLS, и в этом случае вам нужно добавить букву «s» после порта. Пример 192.168.2.1@9000,9004s. Дополнительную информацию о соединениях TLS см. далее в этой статье.

  • <dbname> Указывает имя базы данных, которая будет использоваться, по умолчанию: ntopng

  • <user> Указывает пользователя с разрешениями на чтение и запись на <dbname>

  • <pw> Указывает пароль, который аутентифицирует <user>

  • <cluster name> Указывает имя кластера ClickHouse. <user>

Если вы используете автономную базу данных ClickHouse, вам необходимо использовать -F clickhouse;.... тогда как с кластером вам нужно использовать -F clickhouse-cluster;....

Пример

Чтобы соединить ntopng и ClickHouse, оба работающие на одной машине, можно использовать следующую строку

ntopng -F "clickhouse;127.0.0.1;ntopng;default;default"

В приведенном выше примере 127.0.0.1 используется для подключения с помощью IPv4 (с использованием символьной строки localhost может разрешиться по адресу IPv6). Пользователь default, идентифицируется паролем defaultс разрешениями на чтение и запись в базе данных ntopng также указано. В качестве ярлыка вы можете использовать -F clickhouse для F="clickhouse;127.0.0.1;ntopng;default;default"

Приведенный выше пример с кластером ClickHouse будет таким:

ntopng -F "clickhouse-cluster;127.0.0.1;ntopng;default;default;ntop_cluster"

Что хранится в ClickHouse

ntopng хранит исторические потоки и оповещения в ClickHouse.

Потоки IPv4 и IPv6 хранятся в таблице flows. Столбец INTERFACE_ID используется для идентификации интерфейса, на котором был замечен поток, это полезно. ntopng контролирует несколько интерфейсов (см. -i).

Оповещения хранятся в нескольких таблицах, каждая из которых заканчивается суффиксом _alerts. Префикс таблицы указывает семейство предупреждений, например. host_alerts таблица содержит оповещения для хостов, flow_alerts таблица содержит оповещения для потоков и т. д.

Для получения дополнительной информации проверьте ntopng схема базы данных.

TLS Соединение

Чтобы соединить ntopng с ClickHouse с помощью безопасного соединения TCP, сначала создайте сертификат сервера с помощью следующей команды:

openssl req -subj "/CN=localhost" -new -newkey rsa:2048 -days 365 -nodes -x509 -keyout /etc/clickhouse-server/server.key -out /etc/clickhouse-server/server.crt

Эта команда генерирует сертификат сервера для безопасной связи между ntopng и ClickHouse, устанавливая безопасное соединение TCP.

Примечание

Чтобы позволить пользователю ClickHouse использовать сервер.crt и сервер.ключ файлы, необходимо сменить их владельца. Запустите следующую команду от имени суперпользователя, чтобы предоставить необходимые разрешения:

chown clickhouse:clickhouse /etc/clickhouse-server/server.key /etc/clickhouse-server/server.crt

Откройте файл ClickHouse config.xml и раскомментируйте следующие строки:

  • <!--<tcp_port_secure>9440</tcp_port_secure>-->

  • <!--<certificateFile>/etc/clickhouse-server/server.crt</certificateFile>-->

  • <!--<privateKeyFile>/etc/clickhouse-server/server.key</privateKeyFile>-->

Перезагрузите ClickHouse.

Начните ntopng, используя -Ф вариант, но в этом случае обязательно указать порт базы данных с с в конце этого.

clickhouse;<host[@<port>s]>;<dbname>;<user>;<pw>

Например:

ntopng -F "clickhouse;127.0.0.1@9000,9440s;ntopng;default;default`

Защита соединения в облаке ClickHouse

Вместо этого, чтобы защитить соединение в облаке ClickHouse, единственное, что нужно настроить, — это добавить с персонаж в -Ф опция после списка портов, при запуске ntopng (или в файле конфигурации), без необходимости настраивать что-либо еще. Например:

ntopng -F "clickhouse-cloud;127.0.0.1@9440,3306s;ntopng;default,default;default`

Примечание

Настоятельно рекомендуется обеспечить безопасность соединения при использовании ClickHouse Cloud, более того ClickHouse Облако по умолчанию принимает только защищенные соединения.

Проверка сертификата сервера

Когда хост раньше подключался (см. -F) не соответствует общему имени (CN) сертификата сервера ClickHouse, проверка TLS не удалась. Использовать --clickhouse-server-cn чтобы явно указать имя, которое следует ожидать в сертификате:

ntopng -F "clickhouse;clickhouse.host@9000,9440s;ntopng;default;default" --clickhouse-server-cn clickhouse.example.org

Взаимный TLS (mTLS)

ntopng также может аутентифицировать себя на сервере ClickHouse, используя сертификат клиента, в дополнение к обычной аутентификации по имени пользователя и паролю. Для этого необходимо установить оба --clickhouse-client-cert и --clickhouse-client-key к файлам в формате PEM:

ntopng -F "clickhouse;127.0.0.1@9000,9440s;ntopng;default;default" --clickhouse-client-cert /etc/ntopng/clickhouse-client.crt --clickhouse-client-key /etc/ntopng/clickhouse-client.key

Оба параметра должны быть установлены вместе.

Примечание

Файл закрытого ключа не должен быть зашифрован (без парольной фразы).

Обратите внимание, что сервер ClickHouse также должен быть настроен (в config.xml, под <openSSL><server> раздел), чтобы запросить или потребовать сертификат клиента и, при необходимости, сопоставить сертификат пользователю через <ssl_certificates>. В противном случае mTLS используется только для обеспечения транспортной безопасности, а аутентификация пользователя и пароля по-прежнему выполняется как обычно.

Строгий запуск

По умолчанию, если ntopng не удается подключиться к ClickHouse при запуске, он регистрирует ошибку и продолжает работу без поддержки ClickHouse. Чтобы изменить это поведение и заставить ntopng выйти, когда соединение ClickHouse не может быть установлено, используйте команду --strict-startup вариант. Пример:

ntopng -F "clickhouse" --strict-startup

Когда --strict-startup установлен, и ClickHouse не удается инициализировать (например, служба не работает), ntopng выводит ошибку и немедленно завершает работу. Это особенно полезно в производственных развертываниях, где работа без ClickHouse неприемлема, а серьезный сбой предпочтительнее тихой потери данных.

В любом случае, в случае сбоев во время выполнения соединения ClickHouse, ntopng продолжает работать, и соединение автоматически восстанавливается, когда соединение восстанавливается.
