10. ClickHouse Таймсерии

На этой странице подробно описан драйвер таймсерий ClickHouse. Для общего обзора все драйверы таймсерий см. Таймсерии.

Примечание

Для поддержки таймсерий ClickHouse требуется Предприятие М или лучшую лицензию и HAVE_CLICKHOUSE флаг времени компиляции. Он недоступен на Windows.

10.1. Обзор

Драйвер временных рядов ClickHouse хранит все показатели трафика, созданные ntopng (интерфейс трафик, статистика по хостам, сбои протоколов приложений и т. д.) в столбце ClickHouse база данных. Это обеспечивает высокую пропускную способность записи, гибкие запросы временного диапазона, автоматические данные. сохранение через TTL и дополнительное развертывание кластера/облака.

Все данные таймсерий помещаются в одну таблицу (timeseries), чьи строки содержат имя схемы, временная метка, карта тегов (пары ключ-значение, используемые для фильтрации) и карта метрик (фактическое числовые измерения). Драйвер является полной заменой драйверов RRD и InfluxDB. одни и те же графики ntopng и вызовы API работают независимо от того, какой драйвер активен.

10.2. Конфигурация

10.2.1. Режимы развертывания

Драйвер временных рядов ClickHouse выбирается с помощью -F опция, которая также настраивает параметры подключения. Пожалуйста, проверьте Дамп потоков раздел для настройки ClickHouse.

Примечание

Одинаковый -F флаг используется для ClickHouse сброс потока (исторические потоки) и ClickHouse временные ряды. Когда -F clickhouse (или вариант), оба набора функций имеют общий то же соединение с сервером ClickHouse и база данных.

10.2.2. Предпочтения драйвера таймсерии

Активный драйвер временной серии также можно изменить во время выполнения из пользовательского интерфейса настроек ntopng. под Таймсерии → Водитель. Установка его на clickhouse активирует этот драйвер для всех новых пишет временной ряд.

10.2.3. Хранение данных

Удержание контролируется Хранение данных временных рядов предпочтение (в днях, по умолчанию 365). Значение применяется как ClickHouse TTL положение о timeseries стол. Когда удержание изменения, DDL таблицы перевыпускается с новым TTL, а ClickHouse выполняет фоновую очистку. автоматически — ручная продувка не требуется.

10.3. Схема базы данных

10.3.1. Определение таблицы

При первом запуске (или при изменении срока хранения) ntopng создает следующую таблицу в настроенной базе данных ClickHouse (по умолчанию: ntopng):

CREATE TABLE IF NOT EXISTS `ntopng`.`timeseries`
(
    `schema_name`  LowCardinality(String),
    `tstamp`       DateTime CODEC(Delta, ZSTD),
    `tags`         Map(LowCardinality(String), String),
    `metrics`      Map(LowCardinality(String), Float64)
)
ENGINE = MergeTree()
PARTITION BY toYYYYMM(tstamp)
ORDER BY (schema_name, tstamp)
TTL tstamp + toIntervalDay(<retention_days>)

10.3.2. Сведения о столбце

schema_name (LowCardinality(String))

Определяет тип измерения, например. iface:traffic, host:traffic, interface:ndpi. С использованием LowCardinality позволяет избежать избыточного хранения строк для небольших набор различных идентификаторов схемы.

tstamp (DateTime CODEC(Delta, ZSTD))

Временная метка Unix точки данных. Кодек Дельта сохраняет различия между последовательными временные метки (уменьшая энтропию для обычных временных рядов), затем ZSTD сжимает результат.

tags (Map(LowCardinality(String), String))

Пары ключ-значение используются для фильтрации и группировки данных. Ключи — это идентификаторы с ограниченной мощностью, такие как как ifid, host, или protocol. Значения — это соответствующие идентификаторы объектов. Пример: {'ifid': '0', 'host': '192.168.1.1'}.

metrics (Map(LowCardinality(String), Float64))

Числовые измерения. Ключи — это имена метрик (bytes, packets, duration_ms, и т. д.); ценности Float64 измерения. Пример: {'bytes': 1048576.0, 'packets': 1024.0}.

10.3.3. Разделение и упорядочение

Данные распределяются ежемесячно (toYYYYMM(tstamp)), что позволяет ClickHouse обрезать весь разделы при запросе определенного диапазона времени. Внутри каждого раздела строки сортируются по (schema_name, tstamp), оптимизируя наиболее распространенный шаблон запроса: фильтрация по схеме, сканирование временной диапазон.

10.4. Поведение запроса

10.4.1. Метрики счетчика и индикатора

В каждой схеме таймсерий указывается, являются ли ее метрики счетчики (монотонно возрастающий итоги, например совокупные байты) или датчики (мгновенные значения, например, CPU процент нагрузки).

  • Прилавок метрики: драйвер извлекает один дополнительный интервал времени перед запрошенным диапазоном, вычисляет дельты для каждого сегмента, используя lag() оконная функция и делится на сегмент ширина для получения скорости (например, байт/секунда).

  • Измерять метрики: драйвер агрегирует (avg, max, или min) непосредственно внутри каждый раз ведро.
