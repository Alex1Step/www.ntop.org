Добавление новых показателей

Сценарии позволяют пользователям создавать свои собственные сценарии и пользовательские страницы до тех пор, пока пока определяют свои собственные схемы временных рядов. Часто этого бывает достаточно, чтобы добавить пользовательские метрики и визуализировать их. Однако некоторым пользователям необходимо экспортировать внутренние метрики ядра ntopng. Последующая информация должна дать хорошая отправная точка для этого.

Общий обзор

Элементы трафика (такие как локальные хосты и интерфейсы) периодически повторяются. а некоторые Lua-скрипты и их статистика сбрасываются в виде таймсерий. Элементы трафика обрабатываются стандартными способами:

  1. Большинство элементов трафика реализованы на C, и их статистика передается в Lua через ::lua метод. Например, AutonomousSystem::lua свалки статистику автономной системы в Lua. Важный если элемент имеет ::tsLua метод проверьте случай 2 ниже.

  2. Некоторые другие элементы трафика реализованы на языке C, но их статистика сохраняется. на TimeseriesPoint а не сам элемент. Например, данные локальных хостов хранятся в HostTimeseriesPoint сорт. В порядке чтобы добавить новые таймсерии для локального хоста, HostTimeseriesPoint это класс для изменения (и связанные с ним ::lua метод).

  3. Некоторые элементы трафика реализованы в Lua. Их состояние хранится в Redis. обычно в форме JSON. Сюда входят, например, устройства SNMP.

Чтобы добавить собственный таймсерий, необходимо определить правильный регистр. выше. Также важно отметить, что не все элементы трафика можно экспортировать. Например, временные ряды удаленных хостов и потоков невозможно экспортировать из-за дизайн ntopng.

Случай 1. Добавление метрик через ::луа метод

Новая метрика должна быть представлена ​​в ::lua метод. Тогда вы можете просто добавьте показатель в пользовательские сценарии таймсерий. Например, автономные системы num_hosts поле, выставленное на AutonomousSystem::lua таким образом можно записать как временную серию.

Обратите внимание: если метрика уже доступна в ::lua метод, вы можете сохранить совместимость со стандартом ntopng и обновить его в обычном режиме (форк ntopng не требуется).

Случай 2. Добавление метрик внутри ТаймсерияТочка

Чтобы добавить новую метрику в LocalHost или NetworkInterface, соответствующий TimeseriesPoint вместо этого следует изменить:

  • Для LocalHost измените HostTimeseriesPoint

  • Для сетевого интерфейса изменить NetworkInterfaceTsPoint

Что следует иметь в виду:

  • Новую метрику следует добавить в файл заголовка (например, HostTimeseriesPoint.h).

  • Метрику следует записать в TimeseriesPoint, (например, в LocalHostStats::makeTsPoint)

  • Метрика должна быть доступна Lua в TimeseriesPoint:lua метод (например, в HostTimeseriesPoint::lua)

После этого метрика должна быть доступна в Lua. Используйте пользовательские сценарии таймсерий чтобы экспортировать его как таймсерию. Поскольку это требует модификации исходного кода C, совместимость со стандартом ntopng сохранить невозможно.

Случай 3: Добавление метрик только для объектов Lua

Это действительно зависит от конкретного добавляемого элемента. Совместимость может быть гарантирована, а может и не быть гарантирована.

Пользовательские сценарии таймсерий

Как только новые метрики станут доступны в Lua одним из методов, описанных выше, такие метрики необходимо экспортировать как таймсерии. Для этого необходимо выполнить два действия. требуется:

  • Формат метрики должен быть объявлен в схеме таймсерий.

  • Метрика должна быть записана в драйвер таймсерий.

Оба действия могут быть реализованы внутри пользовательских сценариев таймсерий.

ntopng обрабатывает пользовательские временные ряды с обновлениями каждые:

  • 1 минута для интерфейсов

  • 5 минут для местных хостов

Это означает, что пользовательские временные ряды с точкой каждую минуту и точка каждые 5 минут может генерироваться для интерфейсов и локальных хостов соответственно.

ntopng ищет пользовательские временные ряды в следующих файлах Lua в разделе scripts/lua/modules/timeseries/custom/:

  • ts_minute_custom.lua для локальных хостов таймсерии с 5-минутными обновлениями

  • ts_5min_custom.lua для таймсерий интерфейса с обновлением по 1 минуте

Если файл ts_5min_custom.lua не существует, ntopng пропустит создание пользовательских таймсерий с 5-минутными обновлениями. Аналогично, если файл ts_minute_custom.lua не существует, ntopng пропустит создание пользовательских таймсерий с обновлениями по 1 минуте.

Примеры файлов ts_5min_custom.lua.sample и ts_minute_custom.lua.sample являются создается автоматически при установке ntopng с некоторым примером содержание. Эти файлы игнорируются ntopng. Однако безопасно скопируйте их в ts_5min_custom.lua и ts_minute_custom.lua и изменять копии, когда это необходимо. добавить собственные таймсерии.

Структура скриптов пользовательских таймсерий

Каждый пользовательский файл должен содержать метод setup который определяет тот или иной еще схемы. Каждая пользовательская таймсерия потребности схема для работы. А Схема определяет временные ряды с точки зрения тегов и показателей. документация подробно описывает, что такое схема. Позже в этом разделе будет показан пример схемы.

Файл ts_5min_custom.lua должен содержать обратный вызов ts_custom.host_update_stats который вызывается ntopng каждые 5 минут на каждый активный местный хост. Этот обратный вызов принимает следующие аргументы:

  • when Время (выраженное как эпоха Unix) вызова

  • hostname IP-адрес хоста, за которым, возможно, следует тег VLAN

  • host Метрики хоста в таблице Lua

  • ifstats Статистика интерфейса хост-интерфейса

  • verbose и дополнительный флаг передается, когда ntopng работает в подробный режим

Файл ts_minute_custom.lua должен содержать обратный вызов ts_custom.iface_update_stats который вызывается ntopng каждый минуту для каждого контролируемого интерфейса. Этот обратный вызов принимает следующие аргументы:

  • when Время (выраженное как эпоха Unix) вызова

  • _ifname Имя контролируемого интерфейса

  • ifstats Статистика интерфейса отслеживаемого интерфейса

  • verbose и дополнительный флаг передается, когда ntopng работает в подробный режим

Обратные вызовы можно использовать для добавления точек к временным рядам. Действительно, как только схема определена, необходимо append указывает на таймсерии. Функция, используемая для добавления точек к таймсерии это ts_utils.append описано позже в этом разделе документация.

Пример

Давайте посмотрим, как добавить интерфейсную таймсерию, которая подсчитывает количество проблемы, обнаруженные при анализе порядковых номеров. Всего проблем обнаруженное при анализе порядковых номеров, рассматривается как сумма TCP повторно переданные, неупорядоченные и потерянные пакеты.

Первое, что нужно сделать, это добавить схему в файл. setup функция из ts_minute_custom.lua. Схема создается следующим образом:

schema = ts_utils.newSchema("iface:tcp_seq_errors", {step = 60})
schema:addTag("ifid")
schema:addMetric("packets")

Первый аргумент newSchema указывает имя таймсерии "iface:tcp_seq_errors". Интерфейсы таймсерий должен начать с префиксом iface:. Второй аргумент — это таблица, которая должен содержать аргумент step который показывает, как часто таймсерии будут обновлены. Как мы в 1-минуте местные хосты сценарий Lua временной серии, значение 60 здесь необходимо указать.

Тогда функция addTag используется для указания идентификатора интерфейса ifid который будет использоваться для уникальной идентификации таймсерии когда контролируется несколько интерфейсов. Окончательно, addMetric есть позвонил с аргументом packets чтобы указать метрику имя. Обратите внимание, что оба ifid и packets просто здесь простые строки, их фактические значения будут установлены в ts_custom.iface_update_stats при обновлении таймсерии с помощью новые точки.

Количество проблем, обнаруженных при анализе порядковых номеров, прилавок, то есть является всегда возрастающей функцией время. По умолчанию схемы рассматривают метрики как счетчики, поэтому нет необходимо указать этот тип при добавлении схемы. Для датчики, у одного есть чтобы указать дополнительный metrics_type в таблице, содержащей step. Например, чтобы создать 1-минутный временной ряд для количества активные потоки данного хоста, можно использовать следующий синтаксис ts_utils.newSchema("host:flows", {step=60, metrics_type=ts_utils.metrics.gauge}).

Чтобы обновить таймсерию новыми точками, выполните обратный вызов ts_custom.iface_update_stats расширен с помощью ts_utils.append позвоните следующим образом.

ts_utils.append("iface:tcp_seq_errors",
{ifid = ifstats.id,
packets = ifstats.tcpPacketStats.retransmissions
             + ifstats.tcpPacketStats.out_of_order
             + ifstats.tcpPacketStats.lost},
when, verbose)

Первый аргумент ts_utils.append это название таймсерии и должен быть равным тому, который указан при определении схемы. второй аргумент — это таблица, которая должен содержать тег (ifid) и метрика (packets), которые должны быть установлены на их фактическое значение ценности. Как видно из примера выше, поле id стола ifstats используется для установки тега ifid, тогда как сумма ifstats.tcpPacketStats поля таблицы retransmissions, out_of_order и lost используются как значение метрики packets.

Наконец, третий аргумент when время звонка, и последний аргумент verbose указывает, является ли ntopng работает в подробном режиме.

С этого момента временные ряды будут постоянно обновляться ntopng.

Несколько схем и несколько ts_utils.append можно добавить в тот же файл.

Полный пример можно увидеть по адресу: https://github.com/ntop/ntopng/blob/dev/scripts/lua/modules/timeseries/custom/ts_MINUT_custom.lua.sample

Другой пример, который создает 5-минутные временные ряды общего количества локальных хостов. байты можно увидеть по адресу https://github.com/ntop/ntopng/blob/dev/scripts/lua/modules/timeseries/custom/ts_5min_custom.lua.sample

График новых показателей

После экспорта новых метрик в драйвер таймсерий (например, InfluxDB), сгенерированный временные ряды можно отображать на странице элементов трафика. Конкретный сценарий для модификация зависит от конкретного элемента трафика, вот несколько примеров:

  • Для локальных хостов измените хост_details.lua

  • Для сетевых интерфейсов измените if_stats.lua

Скрипт должен содержать вызов graph_utils.drawGraphs с timeseries поле. К нему следует добавить новые таймсерии. Вот, например, модифицированный файл host_stats.lua с новым хост: low_goodput_flows метрика:

graph_utils.drawGraphs(ifId, schema, tags, _GET["zoom"], url, selected_epoch, {
   top_protocols = "top:host:ndpi",
...
   timeseries = {
      {schema="host:traffic",                label=i18n("traffic")},
      {schema="host:flows",                  label=i18n("graphs.active_flows")},
      {schema="host:misbehaving_flows",        label=i18n("graphs.total_misbehaving_flows")},

      -- The new metric is added here in order to be shown into the charts
      {schema="host:low_goodput_flows",      label="Low Goodput Flows"},
...
   }
})

Метрика появится с надписью «Низкие потоки полезной продукции» в раскрывающемся списке временных рядов. после того, как будут доступны очки таймсерии.
