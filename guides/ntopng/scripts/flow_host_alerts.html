Оповещения о потоке/хосте

Чеки

Оповещения создаются внутри проверок. Проверки — это фрагменты кода, выполняемые ntopng. Проверки реализованы как классы C++ с предопределенным интерфейсом.

Интерфейсы проверки объявлены в классах:

  • include/FlowCheck.h для потоков

  • include/HostCheck.h для хозяев

Эти классы должны использоваться в качестве базовых при реализации проверок:

  • Каждая реализованная проверка хоста должна наследовать от HostCheck

  • Каждая реализованная проверка потока должна наследовать от FlowCheck

Классы реализованы с помощью двух файлов, а именно: .h файл с объявлением класса и файл .cpp файл с определением класса:

  • Объявления проверки хоста (.h файлы) находятся под include/host_checks. Определения проверки хоста (.cpp) файлы находятся под src/host_checks.

  • Объявления проверки потока (.h файлы) находятся под include/flow_checks. Определения проверки потока (.cpp) файлы находятся под src/host_checks.

Проверить выполнение

Выполнение проверок для хостов заключается в вызове ntopng:

  • HostCheck::periodicUpdate примерно каждые 60 секунд

Проверка каждого хоста при создании подкласса HostCheck, должен переопределить periodicUpdate для реализации желаемого поведения проверки.

Выполнение проверок для потоков заключается в вызове ntopng для каждого потока:

  • FlowCheck::protocolDetected как только будет обнаружен Layer-7

  • FlowCheck::periodicUpdate примерно каждые 300 секунд только для потоков с минимальной длительностью 300 секунд

  • FlowCheck::flowEnd как только поток заканчивается, т. е. когда сеанс TCP закрывается или когда истекает тайм-аут потока UDP

  • FlowCheck::flowBegin как только поток виден впервые

Каждая проверка потока при создании подкласса FlowCheck, должен переопределить один или несколько вышеперечисленных методов, чтобы реализовать желаемое поведение проверки.

Проверьте конфигурацию

Проверки настраиваются из веб-интерфейса ntopng. Конфигурация предполагает возможность:

  • Включить или отключить любую проверку

  • Устанавливайте параметры конфигурации выборочно для каждой проверки

Отключенная проверка не выполняется. Параметры конфигурации можно использовать для установки порогового значения, используемого проверкой для принятия решения о том, пора ли создавать оповещение. Аналогично, параметры конфигурации можно использовать для указания списка IP-адресов, которые следует исключить при выполнении проверок.

ntopng, чтобы заполнить пользовательский интерфейс конфигурации проверки и правильно сохранить настроенные параметры проверки, которые будут переданы экземплярам класса проверки C++, необходимо знать наряду с другой информацией:

  • Строки (необязательно локализованные) для имен и описаний проверок.

  • Тип и формат параметров конфигурации

  • Параметры по умолчанию, например, включена или выключена проверка по умолчанию.

ntopng читает эту информацию из небольших файлов Lua, расположенных в:

  • scripts/lua/modules/check_definitions/flow/ для проверки потока

  • scripts/lua/modules/check_definitions/host для проверки хоста

Эти файлы, описанные здесь (добавить ссылку), являются обязательными и должны присутствовать для правильного выполнения проверки.

ntopng использовать имена для связи конфигурации проверки с экземпляром класса C++. Общий <name> необходимо использовать как:

  • Имя файла Lua под scripts/lua/modules/check_definitions, например, <name>.lua

  • Строка, возвращаемая методом getName в файле класса C++, например, std::string getName() const { return(std::string("<name>")); }.

Оповещения

Проверки создают оповещения как часть их реализации. Проверка во время своего выполнения может обнаружить определенное состояние (например, аномалию), для которого она решает создать оповещение. Когда проверка решает создать оповещение, она сообщает ntopng, передавая ссылку на оповещение.

Оповещения реализуются с помощью классов C++. Интерфейсы оповещений объявляются в классах:

  • include/FlowAlert.h для потоков

  • include/HostAlert.h для хозяев

Эти классы необходимо использовать в качестве базовых при реализации оповещений:

  • Каждое реализуемое оповещение хоста должно наследовать от HostAlert

  • Каждое реализованное оповещение о потоке должно наследовать от FlowAlert

Определение оповещений

Оповещения однозначно идентифицируются ключом, присутствующим как в C++, так и в Lua. В C++ ключи оповещений перечисляются внутри файла. ntop_typedefs.h:

  • Перечисление FlowAlertTypeEnum определяет ключи для оповещений о потоке

  • Перечисление HostAlertTypeEnum определяет ключи для оповещений хоста

Каждый класс оповещений C++ должен реализовывать getClassType чтобы вернуть перечислимый ключ оповещения. Каждое перечисляемое значение должно использоваться одним и только одним классом оповещений.

В Lua ключи оповещений перечисляются внутри файлов:

  • scripts/lua/modules/alert_keys/flow_alert_keys.lua для оповещений о потоке

  • scripts/lua/modules/alert_keys/host_alert_keys.lua для оповещений хоста

Файлы C++ и Lua должны быть синхронизированы, то есть иметь одинаковые пронумерованные ключи оповещений. Это означает использование одних и тех же имен и номеров перечислений в C++:

typedef enum {
flow_alert_normal                           = 0,
flow_alert_blacklisted                      = 1,
flow_alert_blacklisted_country              = 2,
[...]
} FlowAlertTypeEnum;

и в Луа:

local flow_alert_keys = {
  flow_alert_normal                          = 0,
  flow_alert_blacklisted                     = 1,
  flow_alert_blacklisted_country             = 2,
  [...]
 }

Чтобы реализовать оповещение, в бот C++ и Lua необходимо добавить дополнительный ключ оповещения.

Форматирование оповещений

Оповещения отображаются графически внутри веб-интерфейса ntopng, а также экспортируются внешним получателям. ntopng, чтобы форматировать оповещения, помимо другой информации необходимо знать:

  • Уникальные ключи оповещений

  • Строки (необязательно локализованные) для названий и описаний предупреждений.

  • Как обрабатывать параметры, вставленные в оповещение из классов C++

ntopng читает эту информацию из небольших файлов Lua, расположенных в:

  • scripts/lua/modules/alert_definitions/flow/ для оповещений о потоке

  • scripts/lua/modules/alert_definitions/host/ для оповещений хоста

Эти файлы являются обязательными и должны присутствовать для правильного создания и визуализации оповещения. Каждый файл должен возвращать таблицу, содержащую некоторые метаданные, включая уникальный ключ оповещения, считанный из одного из файлов перечисления ключей оповещений Lua. Каждый ключ оповещения должен быть возвращен одним и только одним файлом Lua.

Создание оповещений о потоке

Классы оповещений создаются внутри buildAlert, метод, который должен быть реализован при каждой проверке потока. Этот метод вызывается ntopng для создания оповещения, когда ему было приказано сделать это при проверке потока.

Использование чеков triggerAlert чтобы передать ntopng оповещение. Первый метод — асинхронный вызов, он быстрее, но может привести к созданию оповещения JSON после вызова. FlowCheck должен реализовать метод buildAlert(), который вызывается при основной проверке для фактического создания объекта FlowAlert. Второй метод — синхронный вызов, более дорогой, но приводит к немедленной постановке оповещения (FlowAlert) в очередь всем получателям.

Создание оповещений хоста

Классы оповещений создаются внутри проверок хоста.

Использование чеков triggerAlert чтобы сообщить ntopng о создании оповещения со статусом «занято», и его необходимо отпустить. Действительно, фактическое создание оповещения инициируется при проверке хоста с помощью вызова h->triggerAlert которому нужен указатель на экземпляр оповещения хоста в качестве параметра. Этот вызов сообщает ntopng создать предупреждение на экземпляре хоста, на который указывает h. Можно ли вообще использовать другой метод, storeAlert, который после срабатывания немедленно испускается.
