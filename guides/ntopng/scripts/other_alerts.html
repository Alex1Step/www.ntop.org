Другие оповещения (Интерфейс, MAC, Локальные сети, SNMP, Система, Пользователь)

Все эти семейства оповещений могут быть созданы одинаковым образом, без каких-либо различий, за исключением пар, которые будут подробно показаны позже.

ntopng поддерживает пользовательские скрипты (Lua) для следующих элементов трафика:

  • interface: сетевой интерфейс ntopng. Проверьте Проверки интерфейса API.

  • network: локальная сеть ntopng. Проверьте Сетевые проверки API.

  • system: система, поверх которой работает ntopng.

  • SNMP interfaces: интерфейсы контролируемых SNMP устройств.

  • mac: MAC-адрес ntopng.

Обратитесь к Проверьте крючки для имеющихся крючков.

Создать чек

Первым делом создайте чек.

Для этого создайте новый файл в папке scripts/lua/modules/check_definitions папка; обратите внимание, что в этой папке присутствуют различные папки, по одной на каждый тип семейства оповещений.

Например, если необходимо создать оповещение локальной сети, просто добавьте новый файл в scripts/lua/modules/check_definitions/network папка.

Обрабатывает конфигурацию по умолчанию и часть GUI.

В только что созданный файл example_check.lua добавьте следующий раздел:

local checks = require("checks")
local other_alert_keys = require "other_alert_keys"
local alert_consts = require("alert_consts")

local check_example = {
        -- Describe the script category
        category = checks.check_categories.network,
        -- Describe the script severity
        severity = alert_consts.get_printable_severities().warning,

        -- Is the alert enabled or not by default?
        default_enabled = false,
        -- The alert ID
        alert_id = other_alert_keys.other_alert_example,

        -- Is some kind of threshold / user input needed?
        default_value = {
                operator = "gt",
                threashold = 128,
        },

        -- Handles the GUI (visualization) part
        gui = {
                i18n_title = "alerts_dashboard.check_example_title",
                i18n_description = "alerts_dashboard.check_example_description",
                i18n_field_unit = checks.field_units.http_flow,
                input_builder = "threshold_cross",
                field_max = 65535,
                field_min = 1,
                field_operator = "gt";
        }
}

return check_example

  • category: здесь добавьте, например, категорию оповещения. network (список доступных категорий можно найти в scripts/lua/modules/alert_categories.lua);

  • severity: Опишите серьезность предупреждения (список доступных уровней серьезности в scripts/lua/modules/alert_severities.lua);

  • default_enabled: логическое значение, указывающее, должна ли проверка быть включена по умолчанию (без включения пользователем ее) или нет;

  • alert_id: представляет идентификатор оповещения, соответствующий этой проверке (см. следующий раздел);

  • default_value: Нужно ли пользователю что-то настраивать (например, порог, список наций)? если нет, то просто поставь default_value = {};

  • hooks: таблица Lua с именами хуков в качестве ключей и проверками в качестве значений. Проверьте крючки являются событиями или моментами времени. ntopng использует перехватчики, чтобы знать, когда вызывать проверку. Проверка, определяющая перехватчик, получит обратный вызов перехватчика, вызванный ntopng. Чеки должны регистрироваться хотя бы на одном хуке. Видеть Проверьте крючки.

  • gui: этот раздел обрабатывает часть GUI, поэтому описание проверки, имя и т. д.:

    • i18n_title: Название (Наименование) чека;

    • i18n_description: Описание (почему/когда выдается предупреждение) проверки;

    • i18n_field_unit: ТОЛЬКО ЕСЛИ default_value НЕ ПУСТОЙ, тип порога, бит/с или балл/с? (см.: scripts/lua/modules/field_units.lua);

    • input_builder: ТОЛЬКО ЕСЛИ default_value НЕ ПУСТОЙ, какой ввод нужен пользователю? threashold_cross или items_list?;

    • field_max: максимальное значение поля порога

    • field_min: минимальное значение поля порога

    • field_step: значение шага для поля порога

    • field_operator: можно использовать для фиксации определенного порогового оператора: gt

    для оператора «>», lt для оператора «<» - i18n_field_unit: строка локализации, которая будет отображаться после порога поле (например, «Байты» в приведенном выше примере). checks.field_units предоставляет некоторые часто используемые значения.

Другие необязательные опции:

  • packet_interface_only (необязательно): выполнять скрипт только на пакетных интерфейсах, исключая интерфейсы ZMQ.

  • nedge_only (необязательно): если true, скрипт выполняется только в nEdge.

  • nedge_exclude (необязательно): если true, скрипт не выполняется в nEdge.

Запустить оповещение

Чтобы иметь возможность активировать оповещение example_check, необходима функция обратного вызова, которая определяет, когда активировать оповещение; Проверка может выполняться с 3 различными периодичностью:

  • min: Звонят каждую минуту.

  • 5mins: Звонят каждые 5 минут.

  • hour: Звонят каждый час.

  • day: Звонят каждый день (в полночь по местному времени).

  • all: специальное имя перехватчика, которое приведет к вызову соответствующей проверки для всех доступных перехватчиков.

Добавьте в lua функцию обратного вызова, которая будет проверять срабатывание оповещения или нет, а затем добавьте обратный вызов в таблица check_example

local function check_to_trigger_allert(params)
        -- Get the configured threhsold by the user in the GUI
        local user_configured_threshold = params.check_config.threshold
        -- Example of value to check
        local my_value_to_check = 10

        -- Create the alert instance, this needs alwais to be done
        local alert = alert_consts.alert_types.alert_my_example_alert.new(
                my_value_to_check,
                threshold
        )

        -- These two functions call automatically add various info to the alert
        -- MUST BE CALLED
        alert:set_info(params)
        alert:set_subtype(script.key)

        -- Trigger the alert, if the threhsold was exceeded
        if my_value_to_check > user_configured_threshold then
                alert:trigger(params.alert_entity, nil, params.cur_alerts)
        else
        -- Do not trigger the alert, the threshold was not exceeded
                alert:release(params.alert_entity, nil, params.cur_alerts)
        end
end
-- Remember to add the right periodicity to the callback
script.hooks["min"] = check_to_trigger_allert

Обработка пользовательских изменений в различных ситуациях

Есть несколько полезных обратных вызовов, выполняемых в определенное время, которые можно использовать для различные проверки/контроли

-- #################################################################

function script.onEnable(hook, hook_config)
        ntop.setPref("ntopng.prefs.is_broadcast_domain_too_large_enabled", 1)
end

-- #################################################################

function script.onDisable(hook, hook_config)
        ntop.setPref("ntopng.prefs.is_broadcast_domain_too_large_enabled", 0)
end

-- #################################################################

function script.onLoad(hook, hook_config)
        ntop.setPref("ntopng.prefs.is_broadcast_domain_too_large_enabled", 1)
end

-- #################################################################

function script.onUnload(hook, hook_config)
        ntop.setPref("ntopng.prefs.is_broadcast_domain_too_large_enabled", 0)
end

-- #################################################################

function script.setup()
        return ntop.getPref("ntopng.prefs.is_broadcast_domain_too_large_enabled") == "1"
end

-- #################################################################

function script.teardown()
        ntop.setPref("ntopng.prefs.is_broadcast_domain_too_large_enabled", 0)
end

-- #################################################################

  • onEnable(): функция, вызываемая, когда проверка включена;

  • onDisable(): функция, вызываемая, когда проверка отключена;

  • onLoad(): функция, вызываемая при загрузке проверки (например, при запуске);

  • onUnload(): функция, вызываемая при выгрузке чека (например, при выключении);

  • setup(): функция, вызываемая при запуске, если возвращается ложь, проверка не будет отображаться в GUI;

  • teardown(): вызывается после завершения операции сценария (например, после того, как все хосты были пройдены и вызваны перехватчики).

Идентификатор оповещения

Идентификатор оповещения — это уникальный идентификатор, который идентифицирует оповещения между собой.

Просто добавьте новую запись в scripts/lua/modules/alert_keys/other_alert_keys.lua файл.

Добавлять other_alert_example к столу:

alert_exporters_limit_exceeded       = OTHER_BASE_KEY + 96,
alert_acl_violation_arp              = OTHER_BASE_KEY + 97,
other_alert_example                  = OTHER_BASE_KEY + 98,

MAX_OTHER_ALERT_TYPE = OTHER_BASE_KEY + 127 -- see ntop_typedefs.h

}

Примечание

Ключи оповещений гарантированно будут постоянными и никогда не изменятся, даже в версиях ntopng.

Предупреждение

До 15 апреля 2020 г. не существовало концепции alert_key. Обратная совместимость с оповещениями, созданными до этой даты, не гарантируется.

Создайте сценарий оповещения

Наконец, необходим сценарий, описывающий оповещение (конкретное срабатывающее оповещение).

Создать другой скрипт alert_my_example_alert в scripts/lua/modules/alert_definitions/other папка

Примечание

Имя файла оповещения и тип оповещения при создании оповещения (alert_consts.alert_types.alert_my_example_alert.new) ДОЛЖНЫ быть одинаковыми.

local other_alert_keys = require "other_alert_keys"
local alert_creators = require "alert_creators"
local classes = require "classes"
local alert = require "alert"
local alert_entities = require "alert_entities"

-- ##############################################

local alert_my_example_alert = classes.class(alert)

-- ##############################################

alert_my_example_alert.meta = {
        alert_key = other_alert_keys.other_alert_example, -- Alert ID previously added
        i18n_title = "alerts_dashboard.check_example_title",
        icon = "fas fa-fw fa-sign-in", -- Icon
        entities = {
                alert_entities.network -- Which is the Entity of the alert? In our case network
        },
}

-- ##############################################

-- This function is called when creating the alert
function alert_my_example_alert:init(my_value_to_check, threshold)
        -- Call the parent constructor
        self.super:init()

        -- Add this only if custom fields are used, e.g. my_value_to_check and threshold
        self.alert_type_params = {
                my_value_to_check = my_value_to_check,
                threshold = threshold
        }
end

-- #######################################################

-- This function is used to display the results in the Alerts Page (when displaying the alert)
function alert_my_example_alert.format(ifid, alert, alert_type_params)
        return i18n('alerts_dashboard.alert_my_example_alert_descr', { num = alert_type_params.my_value_to_check, threshold = threshold })
end

-- #######################################################

return alert_my_example_alert

  • alert_my_example_alert.meta: здесь необходимо добавить информацию об оповещениях:

    • alert_key: ранее добавленный идентификатор оповещения;

    • i18n_title: заголовок, отображаемый при показе оповещения (предложение: используйте тот же i18n_title, что и в разделе GUI при создании чека);

    • icon: значок Font Awesome 5, отображаемый рядом со i18n_title.

    • entities: Здесь необходим объект, в основном оповещение создается для сетевых оповещений, поэтому используйте сетевой объект; список сущностей здесь: scripts/lua/modules/alert_entities.lua;

  • alert_my_example_alert:init: эта функция вызывается при создании оповещения (при вызове нового в проверке), если необходимы пользовательские параметры, передайте их сюда и назначьте эти параметры в self.alert_type_params

  • alert_my_example_alert.format: эта функция вызывается для отображения предупреждающего сообщения, поэтому при отображении сработавшего оповещения; параметры, переданные в новом, можно получить из alert_type_params
