Syslog Чеки

Скрипты Syslog используются для обработки событий syslog и приема данных, включая потоки и оповещения из внешних источников (например, оповещения от Системы обнаружения вторжений).

Расположение скриптов

Syslog скрипты находятся под /usr/share/ntopng/scripts/callbacks/system/syslog и следует использовать имя источника (например, имя приложения) с .lua расширение как имя файла. Фактически демультиплексирование сообщений реализуется с помощью имя источника для соответствия имени сценария. Например, журнал сообщений исходя из suricata будет доставлен в /usr/share/ntopng/scripts/checks/syslog/suricata.lua сценарий.

Скрипт API

Модуль syslog должен реализовывать следующие функции:

  • setup (необязательно), который вызывается один раз для инициализации модуля.

  • teardown (необязательно), который вызывается один раз для завершения модуля.

  • hooks.handleEvent который вызывается для каждого сообщения журнала, соответствующего модулю.

Пример сценария

Вот пример сценария suricata.lua обработка сообщений журнала от Suricata, экспортировано в syslog в формате Eve JSON.

local dirs = ntop.getDirs()
package.path = dirs.installdir .. "/scripts/lua/modules/?.lua;" .. package.path
require "lua_utils"
local json = require ("dkjson")

local syslog_module = {
   hooks = {},
}

-- The function below is called once to initialize the script
function syslog_module.setup()
   return true
end

-- The function below is called for each log message received from Suricata
function syslog_module.hooks.handleEvent(message)
   local alert = json.decode(message)
   tprint(alert)
end

-- The function below is called once to terminate the script
function syslog_module.teardown()
   return true
end

return syslog_module
