Схемы таймсерий

Проверки, вызываемые через перехватчики проверок, могут использовать Таймсерии API писать свои собственные данные временных рядов, а затем визуализировать их в Пользовательский Страницы. Полный пример скрипта, специализирующегося на сборе Redis метрик. это Redis сценарий монитора .

Чтобы написать таймсерии, сначала необходимо определить таймсерии. схемы.

Определение схемы

Пользовательские схемы определяются в ./ts_schemas подкаталог скрипта. Каталог может содержать один или несколько следующих файлов:

  • min.lua: Определите схемы, точки которых имеют разрешение 1 минуту.

  • 5mins.lua: Определите схемы, точки которых имеют разрешение 5 минут.

  • hour.lua: Определите схемы, точки которых имеют разрешение 1 час.

  • day.lua: Определите схемы, точки которых имеют разрешение 1 день.

Например, схемы, определенные в мин.луа подходят для использования пользователем сценарии мин крюк. Каждый файл должен использовать таймсерию API, чтобы определить его схемы. Вот пример мин.луа:

local ts_utils = require "ts_utils_core"
local schema

schema = ts_utils.newSchema("example:active_hosts", {
  step = 60,
  metrics_type = ts_utils.metrics.gauge,
})

schema:addTag("ifid")
schema:addMetric("num_hosts")

Приведенный выше сценарий определяет схему с именем пример: active_hosts чьи баллы иметь разрешение 60 секунд. По внутренним причинам всегда необходимо указать шаг даже если файл называется мин.луа. Схема определены еслиид тег и содержит одну метрику с именем num_hosts.

Использование схем

Затем проверка может использовать приведенную выше схему следующим образом:

local script = {
  hooks = {},

  ...
}

script.hooks.min = function(params)
  ...

  if params.ts_enabled then
    local ifid = getSystemInterfaceId()
    local num = ... get the current metric value here ...

    ts_utils.append("example:active_hosts", {ifid = ifid, num_hosts = num})
  end
end

return(script)

Важно это проверить params.ts_enabled флаг, чтобы позвонить ts_utils.append только если временные ряды включены для данного объекта, обрабатываемого в данный момент.
