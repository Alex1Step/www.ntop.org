DNS Контакты сервера

Проверяет наличие DNS контактов сервера.

Серверы DNS чувствительны ко всем сетевым атакам. Существует много способов, с помощью которых злоумышленники могут передать большой объем сетевого трафика на серверы DNS, например, наводнения TCP/UDP/ICMP, в результате чего услуга становится недоступной для других пользователей сети за счет насыщения сетевого соединения с серверами DNS.

Предупреждение отправляется, когда количество различных серверов DNS, с которыми осуществляется соединение, превышает пороговое значение.

ICMP Наводнение

Проверяет наличие ICMP Флуда.

Флуд ICMP — это распространенная атака типа «отказ в обслуживании» (DoS), при которой злоумышленник выводит из строя компьютер жертвы, перегружая его эхо-запросами ICMP, также известными как пинги. Атака включает в себя наводнение сети жертвы пакетами запросов, зная, что сеть ответит равным количеством ответных пакетов.

Оповещение отправляется, когда количество отправленных/полученных ICMP потоков/сек превышает пороговое значение.

Сканировать

Обнаруживает действия по сканированию портов, сетей и служб. Для этого предупреждения требуется Clickhouse.

Проверка выполняется каждые 5 минут для исторических потоков, учитывая только те потоки, которые не получили ответа. Каждое обнаружение имеет свой собственный порог, который можно настроить (или отключить индивидуально) в настройках проверки; оповещение срабатывает при достижении или превышении порогового значения.

  • Сканирование портов: хост связался со слишком большим количеством портов другого хоста. Порог — это количество различных портов, к которым осуществляется соединение на одном хосте (по умолчанию: 20 портов).

  • Сканирование служб: атака, нацеленная на несколько хостов определенной службы. Порог — это количество различных хостов, подключенных к одному и тому же порту (по умолчанию: 50 хостов).

  • Сетевое сканирование: связь с необычно большим количеством хостов. Порог — это количество различных хостов, с которыми осуществляется контакт в одной сети (по умолчанию: 100 хостов). Об этом не сообщается для хостов, уже зарегистрированных для сканирования служб.

  • Служба не работает: хост предпринял слишком много попыток связаться с другим хостом через определенный порт, но целевой объект не ответил. Такое поведение может указывать на то, что служба назначения не работает или недоступна. Порог — это количество попыток подключения к одному и тому же хосту и порту (по умолчанию: 50 потоков).

Интерфейс: Пакет & ZMQ

Категория: Кибербезопасность

Сканирование в реальном времени

Набор проверок для идентификации хостов, выполняющих действия по сканированию.

  • Сканирование хостов только для приема: обнаруживает сканирование, нацеленное на хосты только для приема. Предупреждение срабатывает каждый раз, когда хост, предназначенный только для приема, подвергается попытке сканирования.

  • Сканирование неполных потоков: обнаруживает хосты, генерирующие необычно большое количество неполных потоков TCP/UDP. Эти шаблоны часто указывают на сканирование хоста или сети, которое может быть предшественником эксплойтов или атак.

  • SYN Scan: обнаруживает активность сканирования SYN. При сканировании SYN, аналогично сканировании портов, злоумышленник пытается инициировать соединение TCP с каждым портом на целевом сервере, отправляя пакет SYN (синхронизации). Если порт отвечает SYN/ACK, это указывает на то, что порт открыт. Затем злоумышленник отправляет RST, чтобы избежать завершения рукопожатия.

  • Сканирование FIN: обнаруживает активность сканирования FIN. Этот метод используется злоумышленниками или аналитиками безопасности для идентификации открытых портов путем отправки пакетов только с установленным флагом FIN (завершение). Открытые порты обычно не отвечают, а закрытые порты отправляют RST.

  • Сканирование RST: обнаруживает необычно большое количество пакетов с флагом RST (сброс). Всплеск флагов RESET может указывать на поведение сканирования или потенциальные проблемы в сети.

Флуд-атака SNMP использует протокол SNMP, отправляя большой объем запросов SNMP на целевое устройство за короткий период. Эти запросы часто перегружают ресурсы CPU или памяти целевого устройства, что приводит к снижению производительности или даже полному сбою сетевых служб устройства.

СИН Флуд

Проверяет наличие SYN-флуда.

Оповещение о наводнении SYN

DDoS-атака SYN-флуд использует слабость соединения TCP («трехстороннее рукопожатие»), на запрос SYN для инициирования соединения TCP с хостом должен быть получен ответ SYN-ACK от этого хоста, а затем подтвержден ответом ACK от запрашивающей стороны. В сценарии SYN-флуда запрашивающая сторона отправляет несколько запросов SYN, но не отвечает на ответ SYN-ACK хоста или отправляет запросы SYN с поддельного IP-адреса. Хост-система продолжает ожидать подтверждения каждого запроса, что приводит к отказу в обслуживании.

Оповещение отправляется, когда количество отправленных/полученных SYN/сек превышает пороговое значение.
