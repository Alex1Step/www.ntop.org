Suricata Интеграция

ntopng интегрируется с Suricata для импорта оба поток метаданные (Suricata действует как датчик) и оповещения. Прием оповещений позволяет ntopng дополнять встроенный анализ трафика. движок с гибкими возможностями обнаружения угроз на основе сигнатур предоставлено Suricata.

ntopng реализует прием потоков и оповещений из Suricata с помощью Ева JSON формат через syslog.

Предупреждение

Это новая функция, доступная в ntopng начиная с версии 3.9.

Чтобы настроить Suricata для экспорта метаданных потока в ntopng, установите Suricata согласно Suricata Документация и настройте его для использования syslog как тип файла EVE в suricata.yaml файл конфигурации (обычно он находится в папке /etc/suricata/suricata.yaml или /usr/local/etc/suricata/suricata.yaml):

- eve-log:
    enabled: yes
    filetype: syslog

Экспорт потоков

Если вы уже обрабатываете трафик с помощью ntopng (отражая тот же трафик до Suricata и ntopng), экспорт потоков из Suricata не требуется, так как ntopng уже занимается расчетом потоков в дополнение к другим видам деятельности по анализу трафика что не всегда возможно при сборе потоков от Suricata, а не глядя на сырой трафик.

Вместо этого, если вы хотите использовать Suricata в качестве датчика для экспорта метаданных потока в ntopng, вам также необходимо включить netflow в suricata.yaml файл конфигурации:

- netflow

Syslog Конфигурация

Пожалуйста, проверьте Syslog Конфигурация абзац в Syslog Прием журналов раздел инструкции по настройке rsyslog.

Беги Suricata

На этом этапе вы сможете запустить Suricata, чтобы начать экспорт оповещений. (и течет) через syslog:

suricata -c /etc/suricata/suricata.yaml -i eth1

ntopng Конфигурация

В качестве последнего шага вам следует настроить ntopng для приема сообщений syslog, добавив интерфейс Syslog syslog://<ip>:<port> в файл конфигурации для прослушивания подключений к указанным <ip> и <port>.

Если вы используете Suricata для экспорта метаданных потока и включили netflow в в suricata.yaml файл конфигурации, вы не нужно настраивать дополнительные интерфейсы в ntopng. В противном случае вы необходимо также настроить интерфейс (например, eth1) для живого трафика.

Пример:

-i=syslog://127.0.0.1:5140
-i=eth1

Пожалуйста, не забудьте перезапуск тот ntopng сервис для применения изменений.

Если вы настроили два интерфейса в ntopng, интерфейс syslog для приема оповещений и сетевой интерфейс для обработки трафика, вы необходимо дать команду ntopng привязать оповещения к трафику. Этого можно достичь настроив интерфейс syslog в качестве сопутствующего интерфейса для сети. интерфейс через страницу конфигурации интерфейса в веб-интерфейсе ntopng GUI.

  1. Перейти к Интерфейсы -> (интерфейс) -> Настройки и выберите Зеркальный трафик.

  2. Перейти к Интерфейсы -> (интерфейс) -> Настройки и выберите интерфейс syslog в Сопутствующий интерфейс падать.

  3. Сохранять

На этом этапе пакетный интерфейс должен иметь возможность обрабатывать и отображать оповещения, генерируемые Suricata и позволяющие детализировать трафик и пакеты.
