Архитектура

nAnalyst структурирован как агентный цикл, который находится между вводом естественного языка пользователя и уровнем данных ntopng. На диаграмме ниже показан поток высокого уровня.

User question (chat or MCP client)
         │
         ▼
┌─────────────────────┐
│   nAnalyst Agent    │
│  (reasoning loop)   │
└────────┬────────────┘
         │ selects tools
         ▼
┌──────────────────────────────────────────────────┐
│              Domain-Specific Tools               │
│  SQL queries · flow lookup · host/asset info     │
│  SNMP · alert management · policy engine         │
│  active monitoring · chart generation            │
└──────────────────┬───────────────────────────────┘
                   │ results
                   ▼
┌──────────────────────────────────────────────────┐
│         ntopng Data Layer                        │
│  ClickHouse (flows) · Redis (live state)         │
│  nDPI signatures · SNMP · alert subsystem        │
└──────────────────────────────────────────────────┘

Как обрабатывается запрос

  1. Пользователь задает вопрос — через встроенный чат или любой MCP-совместимый клиент.

  2. Агент запускается — nAnalyst инициализирует сеанс рассуждения, привязанный к аутентифицированному пользователю ntopng.

  3. Выбор инструмента — агент определяет, какие из более чем 25 сетевых инструментов актуальны. Инструменты не вызываются вслепую; агент рассуждает о том, какие доказательства необходимы.

  4. Сбор данных — инструменты запрашивают ClickHouse для исторических потоков, инвентаризацию активов для метаданных хоста, SNMP для информации об устройстве и подсистему оповещения об активных инцидентах.

  5. Сбор доказательств — собранные данные структурируются в журнал доказательств. Диаграммы генерируются и встраиваются в ответ чата. Сохраняется полная трассировка SQL и вызовов инструментов.

  6. Ответ и дальнейшие действия — агент синтезирует доказательства в простой ответ с цитатами и, при необходимости, предлагает или выполняет последующие действия (создание политик, добавление мониторов, подавление шума).

  7. Упорство — доказательства и рассуждения сохраняются между сеансами, поэтому контекст не теряется между разговорами.

LLM интеграция

nAnalyst общается с LLM только для рассуждений и генерации естественного языка. Весь поиск данных выполняется вызовами инструментов вашего экземпляра ntopng.

Поддерживаемые LLM бэкэнды:

  • антропный (Клод) — родной формат API

  • ОпенАИ — собственный формат API

  • AWS Коренная порода — OpenAI-совместимая конечная точка

  • Квен (Облако Алибаба) — OpenAI-совместимый; протестировано с Qwen3 235B-A22B

  • Локальные серверы вывода — лама-cpp, вллм, сленгили любой OpenAI-совместимый сервер

Видеть LLM Настройка для получения подробной информации о конфигурации.
