Установка и настройка LM

Пакет LM распространяется через выделенный, защищенный паролем репозиторий, который по умолчанию не включен. Пожалуйста, прочитайте раздел ниже, чтобы включить его.

Ubuntu/Debian Установка ЛМ

На хосте, на котором будет работать сервер LM, установите репозиторий ntop, как описано на странице packages.ntop.org.

Файл /etc/apt/sources.list.d/ntop-lm.list устанавливается с закомментированным репозиторием LM. Ниже вы можете увидеть примеры для Ubuntu 24.04 LTS:

$ cat /etc/apt/sources.list.d/ntop-lm.list
# If you want to use the license manager uncomment the line below
# and read https://www.ntop.org/guides/license/installation.html
#deb [signed-by=/usr/share/keyrings/ntop-archive-keyring.gpg] https://packages.ntop.org/apt-lm/24.04/ x64/

Чтобы включить его (от имени пользователя root), выполните:

  1. Раскомментируйте `deb` линия.

  2. Редактировать /etc/apt/auth.conf (или создайте, если не существует) и добавьте строку machine packages.ntop.org/apt-lm/24.04/ login YOUR_USERNAME password YOUR_PASSWORD где вы заменяете YOUR_USERNAME и YOUR_PASSWORD учетными данными, которые вы получили от ntop.

  3. chmod 600 /etc/apt/auth.conf и chown root:root /etc/apt/auth.conf

apt-get update
apt-get install ntop-license-manager

Пакет устанавливает LM как услугу.

Дистрибутивы на базе Rocky/RedHat Установка LM

На хосте, на котором будет работать сервер LM, установите репозиторий ntop следующим образом:

curl https://packages.ntop.org/centos-lm/ntop-lm.repo > /etc/yum.repos.d/ntop-lm.repo (Ночью)

или

curl https://packages.ntop.org/centos-stable-lm/ntop-stable-lm.repo > /etc/yum.repos.d/ntops-stable-lm.repo (Стабильный)

Затем отредактируйте установленные файлы, заменив ВАШЕ_ИМЯ_ПОЛЬЗОВАТЕЛЯ и ВАШ_ПАРОЛЬ учетными данными, полученными от ntop.

Файл клиента LM

Примечание

Licensemgr.bin предназначен для каждой организации, а не для каждого хоста, поэтому все хосты, принадлежащие одной компании, использующей LM, будут использовать один и тот же файл Licensemgr.bin.

В дополнение к лицензиям LM каждый клиент получает от ntop клиентский файл с именем `licensemgr.bin` это специфично для компании/клиента, использующего LM. Этот файл должен быть установлен как /etc/licensemgr.bin на каждом хосте, на котором работает приложение ntop, которое проверяет свою лицензию с помощью LM (т. е. запускается с `--license-mgr`).

Если файл отсутствует или недействителен, приложение не сможет использовать LM. Если файл установлен правильно, приложение при запуске регистрирует клиента, которому лицензирован файл:

This LM client is licensed to: My Company

Windows

Приложения ntop, работающие на Windows, могут использовать LM в качестве клиентов и проверять свои лицензии. Вместо этого сервер LM не может работать на Windows: его необходимо установить на хосте Linux.

На Windows, `licensemgr.bin` клиентский файл должен быть помещен в рабочий каталог приложения.

Конфигурация

Файлы конфигурации LM хранятся в /usr/share/ntop/etc/. А именно

  • License-manager.conf — файл конфигурации LM.

  • cert.pem и key.pem — файлы, используемые LM для настройки связи TLS, используемой приложениями для общения с LM.

Файлы лицензий, управляемые LM, вместо этого устанавливаются в /etc/ntop/license_manager/ как отдельные файлы. Пример: /etc/ntop/license_manager/nprobe.license.enterprise_m

Файл конфигурации LM

Файл конфигурации LM (/usr/share/ntop/etc/license-manager.conf) имеет следующий формат:

#
# Listening IP:port (default: 0.0.0.0:7153)
#
--listen=0.0.0.0:7153

#
# Web listening IP:port (Default: 127.0.0.1:4444)
#
--web=0.0.0.0:4444

#
# User authentication tokens file (optional, no authentication by default)
#
#--auth-tokens=/usr/share/ntop/etc/auth_tokens.conf

#
# License leases log file (log all licenses allocated/released)
#
--lease-log=/var/log/ntop-license-manager-leases.log

#
# Verbose logs (debug)
#
--verbose

Где:

  • Файл токенов аутентификации пользователя — это файл, содержащий токены аутентификации, по одному на строку, используемые для аутентификации приложений (см. AUTH_TOKEN в файле конфигурации приложения ниже).

  • Файл журнала аренды лицензий используется для хранения истории лицензий, выделенных для приложений, и случаев их освобождения.

Пример файла токенов аутентификации пользователя (например, путь которого может быть /usr/share/ntop/etc/auth_tokens.conf), содержащего 3 токена:

OKR8OTKWZX1K1RPWKW9B3CLYYJGPA1Q9EECDDE011E4GUX4UEWKJY5YEEK1Y55TB
Z6L0F0LS1O3ZK5PZBMEW0AFTDUK4V8AFZ7JW61G70XU39OOVIGLRPDZW8K9DUBE1
3FDEP7U38LCPGBSRY3KVMDRMLM2LFWKO9T7EY4VYSSV75JP1B25V2QYZVT7IH1JF

TLS Конфигурация

Приложения общаются с LM через TLS. Пакет LM поставляется с самозаверяющим сертификатом. Вы можете использовать свой собственный центр сертификации для создания лицензий или создать их с помощью OpenSSL следующим образом.

  • openssl req -x509 -newkey rsa:4096 -keyout key.pem -out cert.pem -sha256 -days 365

Запуск/остановка службы

LM управляется как стандартная служба Linux следующим образом:

  • сервис ntop-запуск менеджера лицензий

  • остановка службы ntop-менеджер лицензий

  • сервис ntop-перезапуск менеджера лицензий

Все команды необходимо выполнять от имени суперпользователя (root).

nProbe и ntopng Конфигурация для использования LM

nProbe и ntopng в настоящее время являются единственными приложениями, которые могут использовать LM. Такие приложения проверяют свои лицензии с помощью LM, указав `--license-mgr <conf file>`.

Этот файл конфигурации (пример в /usr/share/ntop/etc/license-manager-client.conf) имеет следующий формат:

#
# IP and port of the license manager
#
LICENSE_MANAGER=127.0.0.1:7153

#
# Unique instance name
#
INSTANCE_NAME=example

#
# User authentication token (optional)
#
AUTH_TOKEN=OKR8OTKWZX1K1RPWKW9B3CLYYJGPA1Q9EECDDE011E4GUX4UEWKJY5YEEK1Y55TB

#
# nprobe ntopng
#
PRODUCT_FAMILY=nprobe

#
# pro enterprise_s enterprise_m enterprise_l enterprise_xl
#
PRODUCT_EDITION=enterprise_m

Где:

  • LICENSE_MANAGER — это IP-адрес и порт хоста, на котором работает LM. Если вы хотите, вы можете определить дополнительный менеджер лицензий, добавив дополнительный адрес и порт. Пример: LICENSE_MANAGER=127.0.0.1:7153,192.168.1.23:7728. Обратите внимание: если вы используете два экземпляра менеджера лицензий, установленные на двух разных хостах, вам понадобятся два разных набора лицензий.

  • INSTANCE_NAME — это строка, используемая для определения данного конкретного экземпляра.

  • AUTH_TOKEN — это токен, который LM может использовать для предотвращения выдачи действительных лицензий для неизвестного AUTH_TOKEN. Его значение необходимо настроить в LM.

  • PRODUCT_FAMILY и PRODUCT_EDITION определяют, какую лицензию будет использовать приложение ntop в качестве LM при обращении к нему.

Принятые значения PRODUCT_FAMILY: `nprobe`, `ntopng`, `n2disk`, `cento`.

Допустимые значения PRODUCT_EDITION для каждого продукта:

  • nprobe: `pro`, `enterprise_s`, `enterprise_m`, `enterprise_l`, `enterprise_xl`

  • ntopng: `pro`, `enterprise_m`, `enterprise_l`, `enterprise_xl`, `enterprise_xxl`

  • n2disk: `1g`, `5g`, `19g`

  • центо: `s`, `m`, `l`, `xl`, `xxl`
