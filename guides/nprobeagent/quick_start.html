nProbe Агент и ntopng

Лучший способ начать работу с системой видимости сети — использовать ntopng в качестве сборщика данных, экспортируемых агентом nProbe. Для этого вам понадобятся две детали:

  • nProbe Агент (nprobe-агент), небольшое приложение, которое интегрирует libebpfflow и отвечает за самоанализ системы, экспортируя данные в сборщик.

  • ntopng, инструмент анализа и визуализации, который получает аналитические данные от агента nProbe и визуализирует их в удобном формате GUI.

Конфигурация проста. Вы можете стрелять nprobe-агент только один вариант(–zmq), который в основном сообщает ему адрес, по которому ntopng прислушивается к интроспектируемым данным.

nprobe-agent -v --zmq tcp://127.0.0.1:1234c

В этом примере мы собираемся использовать nprobe-агент и ntopng на одном хосте, поэтому мы безопасно используем адрес обратной связи 127.0.0.1 для их взаимодействия. Однако в этом нет необходимости, поскольку nprobe-агент и ntopng может работать на отдельных хостах. Вы даже можете запустить несколько nprobe-агент и позвольте им экспортировать в один и тот же экземпляр ntopng.

Чтобы собрать данные из nprobe-агент, ntopng можно запустить следующим образом:

ntopng -i tcp://*:1234c -m "192.168.2.0/24"

Где:

  • -я указывает на каком порту ntopng должен прослушивать входящие данные (см. порт 1234, тот же, что используется для nprobe-агент)

  • -м указывает интересующую локальную сеть

После запуска обоих приложений укажите в браузере адрес ntopng и вы начнете видеть сетевые коммуникации вместе с информацией о пользователях, процессах и контейнерах.

Для получения дополнительной информации о ntopng и интеграция с nProbe Агент пожалуйста, проверьте ntopng документация

Docker Контейнер

Файл Dockerfile для запуска агента nProbe в качестве контейнера доступен на github. Создать и запустить контейнер с помощью Dockerfile несложно, вам просто нужно выполнить приведенные ниже команды:

wget https://raw.githubusercontent.com/ntop/docker-ntop/master/Dockerfile.agent
docker build -t agent -f Dockerfile.agent .
docker run -it --network=host -v /etc/nprobe-agent.license:/etc/nprobe-agent.license:ro \
  -v /lib/modules:/lib/modules:ro -v /usr/src:/usr/src:ro -v /etc/localtime:/etc/localtime:ro \
  -v /sys/kernel/debug:/sys/kernel/debug -v /var/run/docker.sock:/var/run/docker.sock \
  -v /snap/bin/microk8s.ctr:/snap/bin/microk8s.ctr --privileged agent

Обратите внимание:

  • Файл лицензии следует поместить в папку /etc/nprobe-agent.license на хосте, если только вы не хотите лицензировать только определенный контейнер. –network=host -v /etc/nprobe-agent.license:/etc/nprobe-agent.license:ro требуется для совместного использования лицензии из хост-системы с контейнером, как описано в разделе Часто задаваемые вопросы.

  • – привилегированный и все остальные -v опции (подключенные тома) требуются по eBPF.
