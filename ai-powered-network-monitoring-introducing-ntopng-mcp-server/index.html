Что такое MCP?

Протокол контекста модели (MCP) предоставляет сетевые инструменты и инструменты данных ntopng помощникам AI, такие как расширения Claude Code, Cursor и VS Code. Вместо того, чтобы вручную запрашивать данные таблицы или писать SQL, вы описываете то, что вам нужно, простым языком.

MCP Позволяет:

  • Выполните ClickHouse SQL-запросы к потоку данных за 24 месяца.
  • Получите статистику об активных хостах и ​​потоках в кратчайшие сроки.
  • Запросите список устройств SNMP и информацию об интерфейсе.
  • Поиск документации ntopng в режиме онлайн.
  • Настроить активный мониторинг с использованием естественного языка.
  • Создавайте политику безопасности для оружия.

В отличие от большинства инструментов, которые являются монолитными и поэтому запускают сервер MCP как внешний процесс, сервер ntopng MCP реализован внутри ntopng, что не позволяет вам установить и запустить дополнительный компонент.

Выше вы можете увидеть, например, как работает сервер ntopng MCP. единственное требование с вашей стороны — обновление ntopng до последней версии для разработчиков (скоро она будет включена в табличную версию),

Почему безопасность безголовой сети?

Безголовая безопасность обеспечивает мониторинг с помощью API и автоматизации — доступ к панели управления не требуется. Команды SOC и сетевые менеджеры получают выгоду от:

  • Скорость
    Задайте вопрос, приведите контекст и рекомендации для считанных секунд вместо минут ручного расследования.
  • Полнота
    Один разговор извлекает данные из нескольких источников: потоки в мгновение ока, исторические запросы, инвентаризация устройств, оповещения.
  • Автоматизация
    Устанавливайте пороговые значения, создавайте политику и включите проверки без команды CLI или вручную.

создай свой токен API

Шаг 1. Доступ к настройкам

В пользовательском интерфейсе ntopng проверьте в «Настройки» -> «Пользователи» -> «Токен аутентификации пользователя» -> «Создать токен».

Шаг 2. Скопируйте токен

Добавьте ntopng в код Клода

claude mcp add-json ntopng \
  '{"type":"http","url":"http://NTOPNG_URL:NTOPNG_PORT/lua/rest/v2/exec/llm/mcp.lua","headers":{"Authorization":"Token YOUR_TOKEN"}}' \
  --scope user

Заменить:

  • NTOPNG_URL: имя хоста или IP (localhost, Monitor.company.com)
  • NTOPNG_PORT: порт ntopng (по умолчанию 3000)
  • YOUR_TOKEN: вставьте свой токен из шага 3.

Пример:

claude mcp add-json ntopng \
  '{"type":"http","url":"http://localhost:3000/lua/rest/v2/exec/llm/mcp.lua","headers":{"Authorization":"Token ntop_abc123def456"}}' \
  --scope user

Проверка

  1. Запустите claude mcp add-json
  2. Перезапустить Клод Код
  3. Введите /mcp, и вы должны увидеть ntopng MCP, как показано на рисунке ниже.
  4. Проверьте доступные инструменты, правильно ли проанализировали элементарные инструменты и соединения.
  • Доступные инструменты

Список инструментов, доступных для LLM через встроенный сервер ntopng MCP, зависит от версии ntopng, которую вы используете. На сегодняшний день список доступных инструментов приведен ниже, но мы предполагаем, что пользователи будут носить свой вклад и создавать новые:

  • Инструменты написаны на Lua с использованием API ntopng.
  • Установка проста: вам просто нужно поместить их в фиксатор LLM. См. эта страница в качестве справочника по доступным инструментам.

Варианты использования: аналитика SOC

Случай 1. Расследование подозрительных запросов DNS

Сценарий: Ваш SIEM пометил необычные запросы DNS к известным конкурентным доменам C2.

Аналитик: «Какие хосты запрашивали конкурентный-домен.com за последние 24 часа?»

Клод:

  1. Звонки query → ClickHouse: SELECT src_ip, count() FROM flows WHERE L7_PROTO='dns' AND DOMAIN_NAME LIKE '%malicious%' AND FIRST_SEEN >= now() - INTERVAL 1 day GROUP BY src_ip
  2. Возвращает: «192.168.1.42 запрошено 23 раза, 10.0.0.5 запрошено 3 раза»
  3. Аналитик на днях: «Получите оперативную статистику по 192.168.1.42»
  4. Клод: get_host_info -> Показывает активные порты сервера, последние потоки, историю предупреждений
  5. Результат: у аналитика есть контекст для принятия решения: заблокировать хост, изолировать или провести полный мониторинг.

Время принятия решения: менее 1 минуты (против 10–15 минут ручного исследования)

Случай 2. Обнаружение утечки данных

Сценарий: Передача больших объемов данных на внешний IP в нерабочее время.

Аналитик: «Покажите мне 5 основных исходящих потоков на нелокальные IP-адреса за последний час по количеству переданных байтов»

Клод:

  1. Звонки query -> SELECT src_ip, dst_ip, dst_port, SUM(bytes) FROM flows WHERE dst_ip NOT IN (192.168.0.0/16, ...) AND FIRST_SEEN >= now() - INTERVAL 1 hour GROUP BY src_ip, dst_ip ORDER BY SUM(bytes) DESC LIMIT 5
  2. Возвращает: 10.0.0.8 → 203.0.113.50:443 = 500 MB (подозрительно)
  3. Аналитик: «Какой протокол и домен для этого потока?»
  4. Клод: «HTTPS к известному CDN (Akamai). Вероятно, законно, если только этот хост не должен иметь доступа к внешнему серверу».
  5. Аналитик: «Добавьте объявления для этой пары хост-доменов».
  6. Клод: Звонки add_domain_alert_exclusion → Подавляет будущие оповещения для этого потока.

Исход: Отличите утечку данных от законного доступа к облаку за 3 минуты

Случай 3: Отслеживание управления и контроля ботнета

Сценарий: Несколько хостов обращаются к одному и тому же внешнему IP-адресу через нестандартный порт.

Аналитик: «Найти все хосты, обращавшиеся к 45.142.222.50:8443 за последние 7 дней»

Клод:

  1. Звонки query → SELECT DISTINCT src_ip, dst_ip, dst_port, COUNT() as flow_count, SUM(bytes) FROM flows WHERE dst_ip='45.142.222.50' AND dst_port=8443 AND FIRST_SEEN >= now() - INTERVAL 7 day GROUP BY src_ip
  2. Возврат: найдено 12 хостов (диапазоны 192.168.1.x, 10.0.0.x).
  3. Аналитик: «Получить информацию об активах на каждом хосте»
  4. Клод: Для каждого IP → ОС, модель устройства, первое/последнее посещение, сегмент сети.
  5. Аналитик: Соответствует системе оповещения → Подтверждает сигнал маяка C2.
  6. Решает: поместить в карантин все 12 хостов, захватить PCAP для криминалистики.

Исход: Обнаружение и ограждение бокового движения за 5 минут

Варианты использования: сетевые менеджеры

Случай 1. Выявление у «седателей» пропускной способности

Сценарий: Загрузка интерфейса на уровне 80%. Нужно найти виновных.

Менеджер: «Назовите мне 10 разговоров, которые больше всего потребляли пропускную способность на eth0 за последние 6 часов»

Клод:

  1. Звонки query → SELECT src_ip, dst_ip, L7_PROTO, SUM(bytes) FROM flows WHERE src_port != 0 AND FIRST_SEEN >= now() - INTERVAL 6 hour GROUP BY src_ip, dst_ip, L7_PROTO ORDER BY SUM(bytes) DESC LIMIT 10
  2. Результаты таблицы: межсерверное соединение (HTTP/с), трафик резервного копирования (SMB), потоковое видео (QUIC).
  3. Менеджер: «Какие из них запланированные, а какие — аномальные?»
  4. Клод: Предлагает обычные схемы (резервное копирование в 2–4 утра, движение во время игры).
  5. Менеджер: решает обновить расписание резервного копирования, следить за видеотрафиком.

Исход: Решение по планированию производства на основе данных за 10 минут

Случай 2. Мониторинг работоспособности концентратора VPN

Сценарий: Удаленные работники сообщают о слабых VPN-соединениях.

Менеджер: «Получить статистику SNMP на VPN-шлюзе-01 (192.168.255.1)»

Клод:

  1. Звонки get_snmp_device_info → Показывает все интерфейсы, CPU 45%, Память 78%, Статус канала.
  2. Менеджер: «На каком интерфейсе самый высокий трафик?»
  3. Клод: eth1 (WAN): 500 Mbps входящий, 200 Mbps исходящий
  4. Менеджер: «Сколько сейчас подключено активных VPN-сессий?»
  5. Клод: Звонки query → SELECT COUNT(DISTINCT src_ip) FROM flows WHERE L4_PROTO='UDP' AND dst_port=1194
  6. Результат: 250 активных сеансов (ожидается максимум 200).
  7. Диспетчер: активирует оповещения о емкости, планирует обновление шлюза.

Исход: Выявление узких мест и обоснование расширения мощностей за 5 минут

Случай 3: Проверка охвата мониторинга

Сценарий: Необходимо обеспечить, чтобы все важные устройства контролировались.

Менеджер: «Перечислите все SNMP устройства, которые мы отслеживаем»

Клод:

  1. Звонки list_snmp_devices → Возвращает 47 устройств
  2. Менеджер: «Какие из них не отправили в последний час?»
  3. Клод: Идентифицирует 3 отключенных устройства.
  4. Менеджер: «Получите информацию об активах по этим IP-адресам».
  5. Клод: возвращает ОС, модель, самую известную конфигурацию.
  6. Менеджер: далее правила брандмауэра, перезапускает эти устройства, подтверждает доступность.

Исход: Обнаружение пробелов в превентивном мониторинге, исправление за 3 минуты

Инструменты чтения и записи

Только чтение (безопасно звонить): query, chart, describe_table, get_host_info, get_asset_info, list_snmp_devices, get_live_flows_for_host, get_live_flows_summary, search_docs

Писать (требуется подтверждение): add_host_alert_exclusion, add_domain_alert_exclusion, add_certificate_alert_exclusion, add_active_monitoring_script, create_ai_policy. Клод всегда заботится перед выполнением.

Поиск неисправностей

Нет доступных инструментов (инструменты ntopng pro LLM недоступны)

Причина: Работает версия ntopng Сообщество (модуль Pro отсутствует).

Исправить: Используйте бесплатные инструменты сообщества (9 инструментов, признанных выше). Или обновите версию Enterprise, чтобы получить полный набор инструментов.

ClickHouse запросы не выполняются (таблица не найдена)

Причина: ClickHouse экспорт не включен.

Пустой ответ от get_host_info

Причина: Хост устарел из-за кэша в памяти.

Исправить: Использовать query инструмент для научных данных. Использовать get_asset_info для постоянной инвентаризации устройства.

Часто задаваемые вопросы

MCP бесплатно?

Да. Инструменты сообщества и протокол MCP бесплатны. Клиенты Pro/Enterprise получают доступ ко всем 20 инструментам.

Могу ли я использовать это с пультом ntopng?

Да. Укажите полный URL-адрес и убедитесь в подключении к сети. Используйте HTTPS в целях безопасности.

Что, если я потеряю свой токен?

создать новый в Настройки → Создать токен.

Можно ли нескольким пользователям использовать один токен?

Да, но воспользуйтесь протоколами для каждого пользователя для подотчётности в журнале аудита.

Работает ли MCP с Курсором или другими клиентами?

Да. MCP — стандартный протокол. Настройте и ту же конечную точку HTTP в курсоре, VS Code или клиентских агентах Python.

Какие данные видит Клод?

Только то, что возвращают инструменты: результаты запроса потока (IP-адреса, порты, байты, протоколы), статистика хоста (CPU, память, скорость интерфейса), инвентаризация устройств, конфигурации оповещений. Нет необработанных пакетных данных.

Наслаждайтесь и вносите свой вклад в список инструментов MCP!
